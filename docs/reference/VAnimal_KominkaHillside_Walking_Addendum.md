# 古民家の裏山 — 散歩企画のユーザー追補

2026-09-19 にユーザーが提示した 11 項目のまとめを整理した受領記録。逐語録ではない。**「後から渡した資料の方を正にする」というユーザー指定により、以前の企画原本・会話・試作と食い違う場合は本資料を優先する。** 以前の原本は履歴として保存する。現行仕様は [game-design.md](../game-design.md)、判断基準は [core-concept.md](../core-concept.md)。後の実装判断でこの記録を書き換えず、現行仕様に変更履歴を残す。

## 1. 目的と位置づけ

ワールド名は「古民家の裏山」。古民家ドッグランの犬たちと秋の山へ散歩に出かけ、犬への愛着を別の場所・過ごし方へ広げる。訪問数やバズを主目的にせず、古民家の体験に奥行きを加える拡張エリアワールドとする。古民家だけでも遊びが完結し、もっと楽しみたい人には散歩先がある関係を守る。

## 2. 別ワールドとして制作

同一ワールド内の増設も検討したが、今回は別ワールド。Quest 単体・iOS の快適さを守り、容量・負荷を配分する制作方針であり、同一ワールドでは技術的に不可能と確認した結果ではない。古民家は遊ぶ・くつろぐ・一緒に寝る、裏山は連れ出す・歩く・景色を楽しむ。移動しない人の満足も維持する。

## 3. 対象プラットフォーム

PC に加え Quest 単体・iOS 対応を目指す。「単体機で動物と触れ合える場所が少ない」「対応ワールドでこれだけ遊べるのがうれしい」という利用者の声を踏まえる。軽量な景観、必要な自作ギミック、既存の仕組み・素材の再利用で容量と負荷を管理する。自作だから自動で軽いとは考えず、実機で確認する。

## 4. 散歩体験の中心

気に入った犬と少し歩き、遊び、休む。リード操作の難しさや犬の制御を遊びの中心にしない。周囲で自然に動く犬と一緒に出かけた感覚を重視する。

想定する流れは、犬を選ぶ → 左右どちらかの手にリードをつなぐ → 山道を歩く → 止まって撫でる・おもちゃで遊ぶ → 再び歩く・休む・古民家へ戻る。操作手順や UI の確定ではない。

## 5. 犬とリード

| 項目 | 決まっている内容 |
|---|---|
| 犬 | 古民家と同じ 6 匹をベースにする |
| 接続中 | つないだ手を基準とする一定範囲内で行動する |
| 未接続 | 自由に行動する |
| 上限 | 片手 3 匹、左右合わせて 1 人 6 匹 |
| 接続先 | 左右を選べる |
| 物理 | 絡まり・引っ張り合いはシミュレーションしない |
| リードの役割 | 一緒に歩く犬の選択と行動範囲の指定 |
| 見た目 | 首輪・リードでおしゃれを楽しめるようにする |

手元の一点に固定する意味ではない。範囲の広さ、範囲内の動き、歩行中の立ち位置は今後調整する。未接続の自由行動も山全域への無制限な移動とは別で、範囲と帰還方法を地形に合わせて決める。

## 6. おもちゃ・飾り・休憩

既存の遊びに首輪とリードが増える方向。おもちゃは残したく、リードとの置き換えにはしない。撫でるなどは古民家の仕組みをベースにする。専用の睡眠部屋は不要。既存の飾りを持ってくるか絞るか、屋外で伏せる・一緒に休む動作の範囲、集合などトレーナー機能の対象は未確定。リード中におもちゃで遊べるか、外す必要があるかも未確定で、Fetch と散歩の行動が競合しないよう設計する。

## 7. 景観と空間

秋の裏山を Unity Terrain で作る方向。木・草・岩は見た目と負荷を見て配置する。軽量化した古民家の外観を遠くに置き、あそこから来た感覚を作る。不要な室内設備・ギミックは持ち込まない。散歩道、遊び場、休憩場所を必要な範囲で構成する。購入済みの秋の山アセットと依存アセットは所有しているが、完成シーンの丸ごと使用を前提にしない。

受領したまとめではコース長、周回か往復か、休憩場所の数、端の処理は未確定。直前の会話では「円にしなくてよい。門から伸びて上で犬が遊べる」Terrain v4 が了承されている。ただし後から渡した本資料を正とする指定に従い、周回か往復かも未確定とする。v4 は現在の試作として残し、最終仕様を固定しない。

## 8. 古民家とのつながり・状態

世界観は緩くつなぎ、厳密な地理設定より同じ犬たちとの過ごし方が増えることを優先する。出発・帰還の導線を検討する。元の古民家インスタンスへ戻る方法、名前や飾りの持ち越し、リード接続や遊びの途中経過を引き継ぐ必要性、帰還時のリセット許容範囲は未解決。「世界観として同じ犬」と「実行中の状態がそのまま移動する」を分け、状態引き継ぎを実装済み・実現確定と扱わない。

## 9. 犬ギミックの移植

最初は古民家の確認済み実装をコピーし、裏山に必要な動き・遊びに合わせて育てる。初めから汎用ライブラリ化を進めすぎない。コピー元のコミットと固定タグ、日付、スクリプト・Prefab・設定などの範囲、既知の不具合・注意事項、裏山側の変更を残す。古民家側にも切り出し元のタグを付ける。

同じ修正が両ワールドで繰り返される部分が見えたら共通化を検討する。ワールドをモジュール的に展開することとコードの共通ライブラリ化は別々に判断する。

## 10. 実装前に詰める事項

| 項目 | 未決定の内容 |
|---|---|
| 接続操作 | 犬の選択・左右の選択・解除方法 |
| 端末別操作 | VR・デスクトップ・スマホの操作方法 |
| 行動範囲 | リードの長さ・立ち位置・自由行動の範囲 |
| 追従 | 高速移動・段差・障害物への対応 |
| 複数人 | 同じ犬を複数人が選んだ場合の扱い |
| 他の遊び | リード中の Fetch・呼び出し・集合の優先順位 |
| 離脱 | 接続した人の退出時の解除・帰還 |
| 同期 | 接続先や犬の状態を誰が管理するか |
| おしゃれ | 首輪・リードの種類・選択・保存・公開範囲・解放条件 |
| 性能 | 6 匹の散歩と複数人利用で対象端末の快適さを保てるか |

具体値・挙動は現状の犬システムを確認して決める。今回の会話で固定していない。

## 11. シリーズ全体

古民家を土台に各ワールドが一つの体験を担当し、裏山を最初の拡張先とする。Animal Wash も将来つながる可能性はあるがアイディア段階で、古民家の付属作品とは確定していない。今回の優先は Quest 単体・iOS でも快適にあの犬たちと散歩できる一作。大きなワールド間連携は必要性が見えてから育てる。
