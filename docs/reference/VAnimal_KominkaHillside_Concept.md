# 古民家の裏山 — 企画・AI引き継ぎ資料

作成日：2026-09-19  
状態：コンセプト合意済み。配置・仕様の詳細は制作時に検討する。

## 1. 名称

| 用途 | 名称 | 状態 |
|---|---|---|
| VRChatワールド名 | 古民家の裏山 | 決定 |
| Unityプロジェクト名 | VAnimal_KominkaHillside | 提案 |

Hillsideは山の斜面・山腹の意味。身近な山道で過ごす企画に合わせた開発用名称であり、英語の公開ワールド名は未決定。季節をプロジェクト名に含めず、将来の展開にも使える名称にする。

## 2. コンセプト

**古民家ドッグランで仲良くなった6匹と、秋の山へお散歩に。犬と遊び、休憩し、遠くに見える古民家を眺めながら、いつもの場所の続きを楽しむ。**

古民家ドッグランの世界に奥行きを加える続編。古民家から見えていた山へ行き、山から古民家を見返すことで、「あそこから犬たちと来た」という場所のつながりを感じてもらう。

主目的は新たなバズの獲得ではなく、古民家に来てくれた人が、同じ犬たちとの思い出を増やせること。スマホでVRChatを遊ぶ人にも、複数のワールドを通して深まる体験を届けたい。

## 3. 体験の核

- 古民家ドッグランと同じ6匹に会い、秋の山で一緒に過ごす。
- 山道を散策し、犬と遊び、景色のよい場所で休む。
- 遠くの古民家を眺め、既存ワールドとのつながりを感じる。
- 撫でる・ボール・添い寝など、既存機能を活用する。環境に合わない機能のみ調整する。
- 専用の散歩AIや新しい大規模ギミックは、初期制作の必須条件にしない。

「同じ6匹」は体験上の継続性を指す。ワールドを越えた状態・名前・ポイント等のデータ共有は、この企画では未決定。

## 4. 環境制作の方針

地形はUnity Terrainで制作する方向。完成済みの山シーンに合わせるより、古民家が見える位置、散歩道、休憩場所を目的に合わせて設計する。

- 秋の紅葉を基調とする、身近で落ち着いた山。
- 地形・樹木・岩・草を詰め込みすぎず、見通しと遊びやすさを重視する。
- 古民家は遠景用として外観を残し、室内・家具・ギミック等を省いて軽量化する。
- 古民家の屋根や建物の形など、「あの場所だ」と分かる特徴を残す。
- 購入済みのAutumn Valley - Levelおよび依存アセットは、必要な木・岩・素材等を選んで活用を検討する。完成シーンの丸ごと使用は必須ではない。
- ユーザーは依存アセットをすべて所有済み。

参考アセット：https://assetstore.unity.com/packages/3d/environments/landscapes/autumn-valley-level-231538

## 5. 空間構成のたたき台（未確定）

生成したイメージ図は雰囲気・構成の参考であり、正確な地形図や確定レイアウトではない。画像間には配置差があり、犬の頭数・犬種の描写も仕様の根拠にしない。実際の犬は既存の6匹を基準とする。

| 場所 | 役割 |
|---|---|
| 山道の入口 | 古民家から散歩に来たと感じる起点 |
| 緩やかな散歩道 | 犬と過ごしながら移動できる道。短い周回路を候補とする |
| 展望・休憩場所 | 古民家が見える眺めと、ベンチやくつろげる平地 |
| 小さな広場 | 犬と遊ぶための、段差の少ない場所 |
| 遠景の古民家 | 世界のつながりを伝える背景。内部探索は初期範囲に含めない |

地形の端は、山側では土手・岩・木立、谷側では柵と下り斜面で自然に区切る案。歩ける範囲の外に景観用の余白を設け、その先を簡略化した遠景につなぐ。散歩道からTerrainの切断面や空白が見えない構成を目指す。

古民家方向への道を門で区切る案もあるが、門・柵の位置や実際の移動制限方法は未確定。視覚上の境界と、プレイヤー・犬が範囲外へ出ないための実装は別途確認する。

## 6. 対応プラットフォーム

当初のPC専用案から、**PCに加えてスマホ対応も目指す方針**に更新した。対応の確約ではなく、初期段階の実機確認で成立性を判断する。Android・iOS・Quest単体それぞれの公開対応範囲は別途決める。

豪華さは草木の密度だけに頼らず、眺め・道・犬とのふれあい・古民家とのつながりで作る。まず少ない構成で、描画負荷と犬の移動・遊びが成立するかを確認する。Terrainを使うだけで軽量になるとは判断しない。

## 7. 犬ギミックの移植・管理

古民家ドッグランの動作確認済み実装を一式コピーし、以後は本ワールドで個別に改修する。共通ライブラリ化や大規模な部品化は先行しない。

移植時にはコピー元に固定タグを付け、移植先に以下を記録する。

- コピー元リポジトリ、タグ名、コミットSHA
- 移植日と移植した機能・ファイルの範囲
- 移植時の変更点、省略した機能、既知の不具合
- 移植後は個別管理する方針

タグ例：`export/kominka-hillside-v1`。これは命名例であり、タグは未作成。作成したタグは後から動かさない。

既存の同期処理や不具合対策を引き継ぎ、山に合わせた差分を加える。各ワールドで不具合修正が発生した場合は、他ワールドにも同じ原因がないか確認し、必要な修正のみ取り込む。変更の自動同期は行わない。

## 8. 初期範囲と未決定事項

初期範囲は、コンパクトな山の環境、同じ6匹、既存のふれあい機能、遠景の古民家を中心とする。

以下は制作時に決める。

- ワールドの広さ、道の長さ、配置、犬の行動範囲
- 添い寝・おもちゃ等の具体的な配置と残す機能
- トレーナーの「集まる」等の既存機能をこちらでも利用できるようにする範囲と権限設定
- 古民家ドッグランとの相互移動の導線
- プラットフォーム別の対応範囲、性能目標
- ポイント・購入商品・永続データの扱い

初期構想では1週間程度での制作を想定していたが、Terrainでの地形制作とスマホ対応検証を踏まえ、工期は改めて判断する。固定納期として扱わない。

## 9. 引き継ぎ先AIへの着手依頼

まず既存の古民家ドッグランを確認し、移植元候補と必要な依存関係を整理する。指定されたコピー元を記録して移植し、簡単なTerrain・軽量化した古民家の外観・犬を置いた試作で、眺めと移動、端の見え方、実機負荷を確認する。

試作では「山から古民家が見える」「犬と無理なく遊べる」「小さな空間でも散歩した感じがする」を優先する。画像に描かれた大量の遠景樹木などをそのまま実装要件にしない。未決定事項は現状のコードと試作結果を踏まえて提案し、不要な新機能や大規模再設計を追加しない。
