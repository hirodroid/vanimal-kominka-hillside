# PCVR試作の具体的フィードバックと次の設計

2026-09-20、ユーザーのPCVR体験後の報告。比較基準はコミット `e70d81f` / タグ `prototype-pcvr-2026-09-20`。この文書は報告と提案の記録。現行仕様は [game-design](../game-design.md)、実行順は [Issueサマリ](../development/issues/issue_summary.md)。今回の記録によってシーン・コードが変更されたわけではない。

## 残したい体験

- 首輪に先端を付け、外す動作はリアルらしく良い。物理的に近づく主操作は維持する。
- 紐が伸びるのが面白い。見た目の弾力を硬い長さ制限へ置き換えない。人を物理的に引っ張る要望ではない。
- 古民家から移した犬の基本動作が良い。広場でボールを投げて遊ぶ体験も非常に楽しい。
- 景観は現在くらいの軽い構成でよい。まず犬との体験に制作時間を使う。

## 犬の先行と自由な散歩の初期案 (追加相談前の履歴)

以下は最初の検討案。移動方向から往復を推定して前方へ出す主方式は、追加相談で「目的地を指定し、通過点をたどる自由な散歩」へ更新した。現行仕様は [game-design §4](../game-design.md) を正とする。

目指すのは、犬を視界の中で見ながら一緒に歩き、人が行きたい方にも連れていけること。自動で目的地へ運ばれるツアーにはしない。

1. **道を歩くとき**: 犬の目標をプレイヤー位置より道の少し先へ置く。既存の歩行・加減速・地面追従を使い、道脇の到達できる場所へ短い寄り道を挟む。広場へ向かう先行感を作る。
2. **人が止まったとき**: 犬も離れ続けず、リードの範囲を目安に待つ・周辺を見る。紐の伸びる表現は残す。
3. **人が別の方向へ歩くとき**: 人の実際の移動を優先し、先行目標を切り替える。道外では進行方向の斜め前・横、戻るときは帰り道へ。犬を見るために首を回しただけで目標を逆転させない。
4. **複数匹**: 全員が同じ点へ集まらないよう、前後・左右・寄り道のタイミングを分ける。6匹が全て後方へ並ぶ状態を避ける。

最初から利用者にモード切替を要求せず、道沿いの先行と自由移動の切替を試す案。近傍経路の選び方、曲がり角、往復方向、停止/再開、誤った自動切替は試作で比較する。上手く両立しなければ「犬に任せる／一緒に歩く」の明示選択と比較し、勝手に固定しない。

現コードでは `KH_LeashManager._WalkingTarget` が手とプレイヤー回転を基準にしたスロット位置を返し、Wanderが0.35秒ごとに追う。先頭以外のスロットは後方寄りで、進行先を予測する処理や道を先導する処理はない。速度だけを上げず、目標の作り方と停止・反転時の切替を試す。

首輪は現在 `headAnchor.parent` に剛体追従する構造。ずれの原因は動作中の再現で特定する。首の骨への付け替え、局所位置、必要ならウェイトを持つ首輪を比較する。購入リグを無断で変更せず、1姿勢の位置合わせだけで完了にしない。

## 追加相談で合意した方向 (2026-09-20、未実装)

ユーザーは、前方に見えることや正確な追従より、犬自身が「行こうよ」と先へ行きたがる自由さを重視した。人が来なければ待つ・戻って誘う、2匹や3匹で時々遊び始める動きを追加対象とした。

目的地はメニューから自分の接続犬へ指定し、犬ごとに保持する。最初は広場と古民家側の散歩入口。道に沿った通過点と接続関係を用意し、途中からでも到達できる近傍点へ入って目的地側へ進む方針を合意した。多少の遠回りは許容し、今後は草むら等の目的地を追加できる構成にする。

首や手で瞬時に進路を変える必要はなく、人の実移動を約1秒ごとに補助判断する案を残す。周期・初期目的地・再接続時の扱い・誘いや遊びの具体動作は未確定。仕様・残る判断の正本はgame-design §4、実装と検証はIMP-DOG-003へ整理した。

## 近い順の作業

1. ボールを上の平らな広場へ置き、再配置・リセットでもそこへ戻るようにする。
2. 目的地と通過点による自由な散歩を試作し、首輪ずれを調べる。必要な目的地操作の契約は先に設計する。接続/解除と伸びる紐の良さは維持する。
3. 古民家の構成を土台にメニューと接続補助を作る。集合の対象・優先順位を決める。
4. 動きの異なるおもちゃ、首輪・リードのおしゃれを増やす。専用ライブ・既存購入権利の調査は並行し、制作は基本の遊びと負荷の見通しを得て進める。

複数人・端末の検証は引き続き早期に行う。景観の大幅な増量は後回しにし、落下・足場・視認性など体験を妨げる箇所は直す。
