## 1. 方式の結論 (案)

| 層 | 方式 | 理由 |
|---|---|---|
| 見た目 | **犬の毛のマテリアルは変えず、上に重ねる自前の殻 (オーバーレイ)** を、胴体と同じメッシュ・骨を持つ 2 つ目の SkinnedMeshRenderer として足す (§1-3)。殻は犬ごとのマスク (RGBA) を読む | 毛のシェーダーは端末で Fallback になり得るので、既存マテリアルへ差し込む方式は端末差が出る。殻は geometry シェーダーを使わない頂点 / フラグメントのシェーダーで書け、購入アセットにも触らない |
| マスクの描画 | 犬ごとに RenderTexture 2 枚 (256²、R = 汚れ / G = 泡 / B = 濡れ) を入れ替えて使う (ダブルバッファ)。道具が当たった位置を **位置マップ** 経由で `VRCGraphics.Blit` により描く | 帯状の境目が操作についてくる (品質目標 c)。描いた後のマスクは UV 上にあるので体の動きへ追従する。新しく当たった点の変換は関節の近くで近似の誤差を持つ (§1-1) |
| 判定 | ボーンの子の部位 Collider (専用 Layer、Trigger) へ、道具から Raycast / SphereCast | 動く足・尻尾へ追従する。先行作で実績のある形 |
| 状態の正本 | 犬ごとに **UV 16×16 のセル × (汚れ・泡・濡れ)** を 1 セル 1 バイトで持つ。犬の Owner が確定し、Manual 同期。部位の値はセルの集計 | 清潔の判定とマスクが同じ場所を見る。途中参加はセルから塗れる。配列の素のデータ量は 1 匹 256 バイト (実際の送信量は別に測る) |
| 操作の共有 | 操作者が **ストローク (道具・部位・位置・強さ)** を間引いて全員へ送り、各自が自分のマスクへ同じ描画をする | 2 人が同じ犬を同時に洗える。Owner を奪わない |

### 1-1. 位置マップ

Editor で犬種ごとに 1 枚焼く (256²、RGBAHalf か RGBA32 に正規化)。各テクセルに、その UV を覆う三角形の **バインドポーズでのメッシュ座標** (RGB) と有効フラグ (A) を入れる。継ぎ目は外側へ数テクセル広げる。

実行時は、当たった点を次の順で変換して Blit のマテリアルへ渡す。

1. 当たった部位 Collider の担当ボーンの `worldToLocalMatrix` でボーンローカルへ
2. Editor で焼いた「ボーンローカル → バインドポーズのメッシュ座標」の行列 (部位ごと、bindpose の逆行列) を掛ける

シェーダーは位置マップの座標とブラシ中心の距離から、ブラシの強さを出す。2 点を渡せばカプセル形になり、間引いたストロークでも帯が途切れない。位置マップはバインドポーズの値なので `sharedMesh` の頂点から焼く (実行時に毎フレーム BakeMesh はしない)。2 段構成の犬は **メッシュ側の骨** を追う。

**近似であること (Codex の指摘、採用):** 実際のスキニングは複数の骨の重み付きなので、1 本の骨の逆変換は、その骨へほぼ剛体で追従する領域でだけ正しい。膝・肩・首ではずれる。また、バインドポーズで近い左右の足や腹へ、距離のブラシが貫通する。対策は次の順に入れる。

1. 位置マップの A に焼いた **代表の骨の番号** から部位 ID を引き、ブラシは「当たった部位と、その隣の部位」だけに効かせる (部位の隣接表を Editor で持つ)。硬く切ると関節に洗えない帯ができるので、隣の部位は許す
2. 誤差が残る関節だけ、上位 2〜4 本の骨で評価する方式へ上げる (初手にしない)
3. 点・半径・行列の単位を実寸へ揃える (`lossyScale` 100 の空間へ 0.08 をそのまま渡さない)
4. 犬や部位が変わった時、接触が切れた時は線分を切る (違う骨の空間の 2 点を 1 本のカプセルにしない)
5. 位置マップは sRGB・圧縮・ミップを使わない。継ぎ目の広げが別の UV の島と衝突しないかを検査する

### 1-2. マスクの操作 (Blit のパス)

Blit は、旧マスクと位置マップを読んで新マスクの全画素・全チャンネルを `Blend Off` で書き、2 枚を入れ替える。ブレンドだけで足し引きする方式は、「泡がある所は汚れが速く落ちる」のように他のチャンネルを見る計算が書けず、出力側の古い内容が保たれることにも依存するので採らない (Codex の指摘、採用)。RenderTexture は Linear・深度なし・MSAA なし、シェーダーは `ZTest Always`。

| 操作 | R 汚れ | G 泡 | B 濡れ |
|---|---|---|---|
| 泡をつける (スポンジ・手) | 変えない | ブラシの範囲で増やす (上限 1) | 少し増やす |
| 水で流す (シャワー) | ブラシの範囲で減らす。泡がある所は速く落ちる | ブラシの範囲で減らす | 増やす |
| ふく (タオル) | 濡れている所は少し減らす (足ふき) | 少し減らす | 減らす |
| 汚れる (Owner のセルから) | セルの範囲へ、模様のノイズを掛けて増やす | 変えない | 変えない |
| 乾く (時間) | 変えない | ゆっくり減らす | ゆっくり減らす |
| 途中参加・復旧 | セルから塗り直す | 同左 | 同左 |

矛盾を避ける規則: 泡は汚れを変えない (泡をつけ直しても泥は戻らない)。清潔 (R = 0) でも泡はつく。水だけでも汚れは落ちる (泡があると速い) ので、水から始めても成立する。

**内容が失われた時の復旧:** 新しい RenderTexture の内容は未定義で、アプリの休止からの復帰では内容が失われ得る。描く前に作成済みかと初期化済みのフラグを見て、必要ならセルから全面を塗り直す。更新の間隔が実時間で大きく空いた時も塗り直す。`IsCreated` / `Create` が Udon で使えるかは未確認 (試作の最初に確かめる)。

### 1-3. 殻 (オーバーレイ) のシェーダー

- **2 つ目の SkinnedMeshRenderer** を足す。`sharedMesh`・`bones`・`rootBone`・Transform・スキニングの品質を胴体と合わせ、bounds は押し出しの分だけ広げる。影は殻だけ無効 (落とさない・受けない)。汚れも泡も濡れも無い犬は `enabled` を切る。マテリアルの枠を 1 つ足す方法 (最後のサブメッシュを描き直す) は、覆えるのが最後のサブメッシュだけで、影を殻だけ切れず、VRChat のビルド後に枠が残るかも未確認なので採らない (Codex の指摘、採用)。追加のスキニングとカリングの負荷は測る
- RenderTexture はアセットで持つ (`new Material` は使えない)。描画用のマテリアルの参照と、Blit のパラメータを書き換える実行時のマテリアル (複製したもの) を区別し、アセットへ直接書かない
- 前後関係: 毛のファーには `ZWrite On` のパスがあり、描画順を後ろにするだけでは解決しない。殻は 1 層・明示の Queue・`ZTest LEqual`・`ZWrite Off` から始め、横腹・脇・足の交差・顔を見る。`ZTest Always` は反対側の足まで覆うので殻には使わない
- 頂点を法線方向へ押し出す。押し出し量 = 毛の長さ相当の基準 + 泡の量 × 泡の厚み。基準は毛の長さのマスク・向き・モデルのスケールを見て決め、毛が短く描かれる端末では浮かないよう端末別に持つ。泡の量で頂点を動かすには頂点の段でマスクを読む
- 色: 汚れ (茶、模様のテクスチャ × R)、泡 (白、ノイズで粒の輪郭、G で厚みと不透明度)、濡れ (暗く・つやを足す、B)。マスクが 0 の所は `clip` で捨てる
- PC は泡の殻を 2〜3 層、モバイルは 1 層から始め、実機で決める
- 顔は泡の上限と押し出しの上限を下げる (顔のマスクを明示的に持つ)。目と口は別 Renderer だが、泡が前へ張り出せば隠れるので、Renderer が別であることを根拠にしない
- 濡れは、外側の殻では毛そのものの質感を変えられない。暗さとつやの近似として扱う

### 1-4. 状態と同期

新しい `KH_DogWash` (犬ごと、Manual 同期)。Owner は **犬のルートの Owner に揃える** (現状はほぼインスタンスのマスターだが、保証ではない)。犬の Owner が移ったら `KH_DogWash` も揃え、交代後に再整合する。操作のたびに Owner を奪わない。

| 同期する値 | 内容 |
|---|---|
| `cells[256]` (byte) | UV 16×16 のセル。汚れ 2 bit・泡 3 bit・濡れ 3 bit。メッシュの無いセルは分母から外す (Editor で有効セルの表を焼く) |
| `epoch` / `appliedSeq` | セルの版と、その版に織り込み済みのストロークの番号 |
| `washingUntil` (サーバー時刻) | 最後のストロークからの猶予。洗われ中の判定 |
| `cleanSerial` | 「十分きれい」になった回数。満足の仕草を全員で 1 回出すためのエッジ |

ストロークは `[NetworkCallable(maxEventsPerSecond: 8)]` を `NetworkEventTarget.All` へ送る (既定の上限は 5 で、明記しないと 8 Hz は待ち行列が伸びる)。送る側でも 8 Hz へ間引き、道具・部位をまたいだ **操作者 1 人あたり** の上限にする (Raycast 1 本ごとに掛けない)。引数は 8 個以内で、ID は整数、位置は部位ごとの範囲へ正規化して各軸 10 bit を 1 個の `int` へ詰める (Vector3 のまま丸めても送信量は減らない)。

| 引数 | 内容 |
|---|---|
| `tool` / `part` | 道具と部位の ID |
| `from` / `to` | 区間の両端 (詰めた int)。部位が変わった・接触が切れた時は区間を切る |
| `amount` | **接触していた時間を含む量** (1 回の呼び出しの量ではない)。フレームレート・間引き・区間の長さで洗う速さが変わらないようにする |
| `seq` / `epoch` | 操作者ごとの連番と、見ていたセルの版 |

受け取る側は ID・座標の範囲・量・送り主と道具の持ち主の関係を確かめる。

- 操作者: 自分のマスクへ毎フレーム描く (即時の手応え)。`All` は送り主にも届くので、`CallingPlayer` と `seq` で **描画済みの自分の区間の描画だけ** を省く。自分が犬の Owner の時のセルの積算は省かない
- 他の人: 受け取った区間をカプセル形のブラシで描く。接触の音と飛沫も受け取った区間を主に使う (同期された道具の位置から打ち直すと、見える洗浄位置と音が離れる)
- Owner: 受け取った区間が届いたセルだけを更新し、1〜2 Hz で同期する
- **通常の受信ではマスクを塗り直さない** (洗った帯へ汚れや泡が戻るため)。塗り直すのは、途中参加の最初の受信・RenderTexture の作り直し・Owner 交代の時だけ。セル (16×16) を小さなテクスチャへ書き、UV 空間でマスクへ拡大して描く。その版より後のストロークだけを重ねる
- **制限として残すこと:** セルから復元できるのはおおまかな見た目で、帯の細部は復元しない。泡付けとすすぎは順序で結果が変わる (例: 0.9 へ +0.2 → −0.2 は 0.8、逆は 0.9) ので、2 人が同じ場所を同時に操作した時は各自の表示が一時的に違う。正本は Owner が受け取った順
- `cleanSerial` は最初の受信では演出しない。再洗浄での再発火は「汚れか泡が一定量へ戻ってから、もう一度きれいになった時」。閾値の近くの往復で連発させない (幅を持たせる)

**比較した別案:** (A) 先行作と同じ構成 → 帯が粗い。Owner を奪うのは先行作の入力の作りで、セルの同期とは別の問題。(B) Owner が同期された道具の位置から全部を判定 → 2 人で洗えるが、補間された道具の位置と Owner 側の犬の姿勢で判定するので操作位置とずれ、Desktop / Touch の視線の接触は道具の位置に現れない。帯を見せるには結局、結果を配る必要がある。(C) 本案。Codex への相談でも C を勧められた (2026-09-30)。

### 1-5. 犬の行動との切替

`KD_DogWanderController.Update` の実際の順序は、フレームのフラグの初期化 → Owner と速さの観測 → `WaterTick` → リード → Candy → Fetch / フリスビー → 近接の観測 → 選択済みの行動の継続 → 水遊び → 寝る → … 。行番号は `c1e232b` 時点。

- **リードを付けていない時:** 「洗われ中」の枝は、近接の `_paused` の更新 (1408 行) の後、`ContinueSelectedBehavior()` (1412 行) の前へ入れる。水遊びの直前へ入れると、選択済みの行動の継続 (約 0.1 秒) に遮られる。洗われ中は `_behaviorSelectionValid = false` にして毎フレーム処理し、終わったら選び直させる。早期 return では `NotifyPlay()` を呼ぶ
- **フラグの寿命を分ける:** フレームのフラグ (`_washActive`、姿勢の要求) は冒頭で毎フレーム下ろし、枝で立てる。`washingUntil`・反応の終了時刻・清潔の履歴はそこで消さない。Fetch などの入口が読むのはフレームのフラグではなく、Owner の有効期限から求めた状態。洗浄へ入る時に休憩・おやつの保留をどう畳むかを決め、古い演技が洗浄の後に再開しないようにする
- **リード接続中:** 1327 行で return するので上の枝には来ない。`UpdateHillsideLeash()` の中の、引き離された時の追従の後・休憩の前に、別の停止の判断を入れる。条件は、持ち主のストロークが有効・持ち主が止まっている・リードに余裕がある。歩き出したら直ちに通常の追従へ戻す。他人のストロークはマスクと値だけを変える。姿勢の選択は `LeashPose()` と非 Owner の return (`HillsideLeash.cs` 278〜279 行) で決まるので、洗浄の姿勢もそこへ反映する (Owner の移動だけ止めても、他の人の側の姿勢が揃わない)
- **水の中:** 出水・veto は洗浄の停止より強い。水の中では描画は受けるが停止へ入らず、上陸してから止まる。シャワーで増える濡れ (マスクの B) と、川の `WaterPose` は別物
- **門:** 自動の遊びへの参加と、明示的な要求を分ける。Fetch (`StartFetch`)・フリスビー (`CanPlay`)・新しいリード接続 (`ReqAttach`) は洗われ中を断る。集合・呼び戻し・ワープは洗われ中より強く、受けた時に洗浄の停止を解く (`Available()` は複数の用途で使われるので、一律に断ると集合で中断できない)
- **拘束しない規則:** 洗われ中は最後のストロークから 3 秒で解ける
- **書き手を増やさない:** ルートは動かさない。姿勢は既存の調停 (移動は `ApplyMoveAnim`、Sit などは LateUpdate の 1 か所) へ要求として渡し、洗浄側が直接 Bool を立てない。減速中に静止の姿勢を立てない

### 1-6. 反応

| 種類 | 出し方 | きっかけ (試作値) |
|---|---|---|
| 小さな反応 | `petController._SetGaze` で首をかしげる、尻尾を振る、表情の BlendShape。`_SetGaze` はそのフレームだけ有効なので、反応の間は毎フレーム渡す | ストローク中、部位が変わった時。反応の **開始** を 4 秒あける |
| コミカルな反応 | 足を上げる (`KD_PawHold_*`、お手のクリップ)、あくび・伸び | 足をふいた時、泡が一定量を超えた時 |
| ブルブル | **手続き的に新規**: 胴・首・頭の骨へ減衰する往復の回転、耳と尻尾は PhysBone に任せる。飛沫の粒子を出す。頭の骨は撫での制御も書くので、別の LateUpdate から書かず、既存の追加回転の処理へ合成する | 水を止めて 0.8 秒後に濡れが多い時、タオルの仕上げ後。すすぎ前の泡は落とさない (値は変えず見た目だけ) |
| 満足の合図 | 座って尻尾を振る + 表情、短い声 | `cleanSerial` が進んだ時に 1 回。操作は止めない |

### 1-8. 音と飛沫

| 音 | 鳴らし方 |
|---|---|
| 噴射 | ノズルのループ。放水中だけ。全員に聞こえる |
| 接触 (毛) / 接触 (泡) | 当たった位置へ置いたループ 2 本。当たっている間だけ、対象の泡の量で 2 本の音量を配分。音量は `MoveTowards` で滑らかに |
| 泡立て | スポンジの接触点のループ。動かす速さで音量と高さを少し変える |
| ふく | タオルの接触点のループ |
| 反応 | ブルブル、満足の声 (既存の犬の声の経路) |

- 他人の操作の音は、受け取ったストロークの位置で鳴らす (距離で減衰)。当たるたびの単発音は使わない
- 音量は個人音量の台帳へ登録する。分類は「効果音」を新設するか犬の声へ載せるかを実装時に決める
- 素材は新規に作る (合成か、利用条件を記録できる素材)。先行作の素材は使わない。記録は制作票へ
- 飛沫: 当たった位置へ `Emit`。空中へ噴射している時は水の筋だけ、当たっている時は跳ね返りの粒と接触の音が加わる。泡に当たった時は泡の粒が飛ぶ

### 1-9. 汚れの発生

Owner がセルの値を増やす (部位ごとのセルの表から)。足 4 本 → 腹 → 胴の順に汚れやすい係数。

| きっかけ | 内容 (試作値) |
|---|---|
| 散歩・走り | リード接続中と Fetch / フリスビー中の移動距離で足が汚れる。300 m で足が半分 |
| 土・泥の場所 | 採用地点の範囲内にいる時間で足と腹が汚れる |
| 川 | 川に入ると足の汚れが少し落ち、濡れる。**川だけで清潔にはしない** (未決定事項の案) |
| 猶予 | 洗い終えてから 120 秒は汚れない。門の外の待機範囲にいる間は汚れない |

## 3. 予算 (試作で測って確定する)

| 項目 | 目安 |
