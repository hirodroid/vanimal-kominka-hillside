## 実装したもの

### ボールの初期位置 (BUG-DOG-001)

- `KH_DogWalkingEditor.BallHome(i)`: 広場の平坦部 (`Flats[PlazaFlat]` 中心 72,127 / 半径 12 / 高さ 19) の北東 (75.5, 130.5) を中心に 3×2、間隔 0.9 m、地面 +0.07 m。道の終点から約 4 m、木陰の木 (63,136) から 12 m 離す。
- 設計値なので Build のたびに書く (以前は初回だけ犬の隣に置いていた)。`VRCObjectSync` の Respawn 先はシーン開始位置なので、戻し先も同じ広場になる。
- リセットボタン (古民家の `KD_TreatPouch` 側) は移植していない。遊びで散らばったボールを集める操作はこの Issue の範囲外。

### 道と目的地 (`KH_WalkRoute`)

- `Tools/KominkaHillside/Walking/4b Build Walk Route` が `KH_TerrainShape.SamplePath()` の道を 7 m ごとに通過点にし、Terrain と NavMesh へ吸着、隣接をリンクにして NavMesh 経路長でコストを付け、Floyd–Warshall で `nextHop` / `routeCost` の表を作る。17 点、道のり 113.9 m。[生成ログ](evidence/2026-09-20-free-walk/route.txt)。
- 目的地は `destinationNodes = {0 (門前), 16 (広場中心)}`。到着半径は門 3 m、途中 2.2 m、広場 5 m。
- 分岐や追加目的地 (草むら等) は同じ表に点とリンクを足せば入る。今回は一本道のみ。

### 目的地の共有と操作 (`KH_LeashManager` / `KH_WalkSign`)

- `destinations[6]` (同期、既定 1 = 広場) と `lastWalkers[6]`。接続時に前回と違う人なら既定へ戻す。同じ人の解除→再接続は保持。
- `ReqDestination(dest)` は Manager Owner が受け、送信者がつないでいる犬だけを変える。他人の犬・未接続犬には触れない。看板側は自分の接続犬が 1 匹以上あるときだけ要求を送り、板を 0.5 s 光らせる (0 匹なら何も起きない = 対象なしの合図)。
- 看板 `KH_WalkSign_{Entrance|Viewpoint|Plaza}`: 柱と 2 枚の板 (`PLAZA >` 緑 / `GATE <` 茶)。板を Interact すると自分の接続犬に伝える。Interaction text は「広場へ行こう」「古民家側へ帰ろう」。板のラベルは Unity 内蔵フォントの ASCII (日本語 TMP フォントが未導入のため)。DES-UI-001 のメニューができるまでの仮 UI。看板ルートの位置・向きは初回だけ書き、以後は手で直せる。板・ラベル・材質はコード所有で毎回書く。

### 犬の散歩 (`KD_DogWanderController.HillsideLeash.cs`)

Owner の判断順。数値は `KH_LeashManager` の Inspector 値 (Build が毎回書く)。

| 順 | 条件 | 動き |
|---|---|---|
| 1 | 手から 1.25×リード長 (3.75 m) 以上離れた | 手の手前 0.9 m へ戻る。1.6×以上なら `followSpeed` で走る。10 m 以上で到達可能な経路があれば従来どおり瞬間移動 (判定は 1 s ごと)。0.6× まで戻ったら経路へ入り直す |
| 2 | 人が長く止まっている (道中 50 s、到着後 20 s、犬ごとに +2 s×番号) か、誘いを 3 回使い切った | 誘いをやめ、手の 1.8 m 以内へ来て伏せる。人が動く (静止開始位置から 0.6 m) か目的地が変わると解除 |
| 3 | 目的地なし / 人が道から 6 m 以上離れた (4 m 未満で復帰) / 入れる点がない | 従来の手まわりのスロット追従 (横〜少し前へ変更。後ろに並ばない) |
| 4 | 経路未設定 | 到達可能で経路長 12 m 以内の点のうち「経路長 + 目的地までの道のり」最小の点へ入る。12 m 以内に無ければ最も近い到達可能点。無ければ 3 s 後に再試行 |
| 5 | 次の点の半径内 | `nextHop` で次へ。目的地点の半径内に一度入ったら到着状態を保持し、3 と同じ手まわり行動。目的地が変わるか、人が目的地の半径+6 m の外へ出るまで解除しない |
| 6 | 人が 8 s (+1.3 s×番号) 止まり、犬が人より先に 0.55×リード長以上離れて居る | 誘い: 手の手前 0.9 m へ戻り、1 回吠え (犬 Owner だけが送れるネットワークイベント)、2.5 s 人を見る。次回は 14 s × (1+0.3×回数) 後、3 回で打ち止め (番号 0 で約 8 / 25 / 45 s)。同じ人の他の犬が誘い中、または誘いを終えて 7 s 以内なら待つ |
| 7 | 歩行中で手から 0.5×リード長以内、4 s ごとの 25 % | 寄り道: 進行方向の斜め横 1.5〜2.7 m の NavMesh 上の点 (経路長 5 m 以内、手から 0.8×リード長以内) へ行き、1.5〜3 s 嗅ぐ。紐が 0.9× まで伸びたら中断 |
| 8 | 犬が人より先に居て、手から 0.78〜0.9×リード長 (犬ごとに違う) | リード端で待つ。止まったら人の方を向く |
| 9 | それ以外 | 次の点 (左右 ±1.1 m のゆっくり変わるずれ付き) へ NavMesh 経路で歩く。人より後ろなら `runSpeed`、近い (0.45×以内) なら速歩、それ以外は歩き |

- LookAt (止まって人の方を向いている) と伏せは、全クライアントが同期済みの事実 (犬の向き・速度・人の位置と静止時間) から導く。Owner だけの判断を非 Owner に見せる同期変数は増やしていない。
- 首や手の向きは判断に使わない。人の実移動は 1 s ごとに「静止を始めた位置からの変位」で見る (0.6 m 以上で移動。ゆっくり歩き続けても静止扱いにしない)。
- 犬同士の遊び (IMP-DOG-003 手順 3) は未実装。接続中に Fetch を始めない契約は不変。

## Editor 検証 (2026-09-20)

- C# / Editor コンパイル成功 (Editor.log に `error CS` なし)。UdonSharp 73 スクリプトのコンパイル完了、Udon 診断 0、Console エラー 0 ([診断出力](evidence/2026-09-20-free-walk/compilation.txt))。
- `Walking/5 Verify`: **99 項目、失敗 0** ([出力](evidence/2026-09-20-free-walk/verify.txt))。追加項目: ボール 6 個が広場の平坦部にあり NavMesh 上、経路の配列サイズ・門↔広場の `nextHop` 連鎖・全点が NavMesh 上・全リンクに完全な NavMesh 経路・間隔 ≤ 11.2 m・両端の位置、Route の backing 配列と Manager の `route` 参照、看板 6 枚の配線と目的地の内訳。
- `destinations` は `walkers` と同じく program 既定値で持つ (backing に override なし) ことを Inspect Compilation で確認。
- シーン保存後の `.unity` に `Node00..16` 17 件、`Board_GATE/PLAZA` 6 件。
- Editor 画像: [入口の看板](evidence/2026-09-20-free-walk/10-sign-entrance.png)、[広場の看板](evidence/2026-09-20-free-walk/12-sign-plaza.png)、[広場のボール](evidence/2026-09-20-free-walk/13-balls-plaza.png)。
- 文書リンク・Issue 整合の検査は合格 (更新後に再実行)。

既知の制限: 伏せ・LookAt の導出に使う「人の静止時間」は各クライアントが自分で計り始めるので、途中参加者にはその時点から 20〜50 s は伏せていない犬に見える (Codex D 指摘、2026-09-20)。同期変数を増やさない設計の代償として受け入れ、Play で気になれば静止開始時刻の同期を検討する。

Editor で分からないこと: NavMesh 上の実際の歩き (足滑り・段差)、リード端で止まる距離の体感、誘いの頻度、看板の Interact 距離、非 Owner 画面の LookAt/伏せ、ClientSim と実機の差。

## Play チェックリスト (ユーザー担当)

準備: シーン保存済み・Console エラーなし。**Build & Test し直す。** 端末・犬数・人数・接続手を記録。IMP-DOG-004 (新しい首輪・リード) の [制作票の表](2026-09-20-leash-asset-production.md) も同じ回で確認できる。

### 0. まず 1 人・1 匹で

- [ ] 開始時、ボール 6 個が上の広場に並んでいて、放置しても転がらない。投げて遊んだあとも坂へ流れない。
- [ ] 門で 1 匹つなぐと、自分から道を登り始める (引かなくても歩く)。リード端 (約 2.4 m) で止まり、こちらを向いて待つ。
- [ ] 近づくと再び先へ行く。歩き続けると犬が前を歩く時間が長い (後ろに隠れない)。
- [ ] 立ち止まって 8〜10 s: 犬が戻ってきて 1 回吠え、こちらを見て、また先へ行く。会話しているつもりで 1 分止まる: 誘いは 3 回 (約 8 / 25 / 45 s) で止まり、そばで伏せる。歩き出すと起きてついてくる。写真を撮りながらゆっくり歩く: 静止扱いにならず誘いが始まらない。
- [ ] たまに道脇へ寄って嗅いでから戻る。崖・境界の壁の方へは行かない。
- [ ] 広場に着くと、まわりをうろうろして落ち着く (先へ行こうとし続けない)。広場の中を歩き回っても中心へ戻ろうとしない。見晴らしは通過点なので、止まれば待つ・誘う。
- [ ] 広場の看板で `GATE <` を Interact: 板が一瞬光り、犬が道を下り始める (伏せていても起きる)。門の看板で `PLAZA >`: 登り始める。つないでいない状態で押すと光らず何も起きない。看板を押しても他人の犬・未接続の犬は動かない。
- [ ] 道から外れて草地を横切る: 犬は手のまわりについてくる。道へ戻ると散歩を再開する。
- [ ] 後ろへ引き返す: 犬は目的地を変えずについてくる。自分が止まればまた前へ出ようとする。
- [ ] 首だけ回す / 手だけ振る: 犬の進路が反転しない。
- [ ] 途中 (坂の途中・見晴らし) で外して付け直す: すぐ迷わず散歩を再開する。

### 1. 3 匹・6 匹

- [ ] 6 匹が同じ点に固まらず、待つ位置・寄り道のタイミングがばらける。
- [ ] 全員が同時に戻って吠えない (誘いは 1 匹ずつ)。
- [ ] 6 匹で歩いてカクつき・足滑りが許容範囲。

### 2. 2 人以上

- [ ] 相手の画面でも、待っている犬がこちらを見て止まり、伏せた犬は伏せて見える。
- [ ] 2 人が別々の目的地を指定でき、互いの犬に影響しない。
- [ ] 途中参加した人にも犬の目的地の状態 (登る/下る) が復元される。
- [ ] 接続者退出・Owner 退出後も残った人の散歩が続く。

### 3. Desktop / Touch

- [ ] 看板の板を Interact できる (距離 2.5 m)。ラベルが読める。

| 症状 | 最初に見るところ |
|---|---|
| 以前どおり手の周りにしか居ない | Build & Test し直したか。`Inspect Walk Route` で `manager.route backing=True` か。看板の InteractionText が出るか |
| 犬が道を無視して斜面を直登する | どの点に入ったか。`entryMaxPath` (12 m) と NavMesh。斜面横断は不具合として記録 |

| 誘いがしつこい / 来ない | `inviteAfter` 8 s、`inviteInterval` 14 s (回数ごとに +30 %)、`inviteLimit` 3、群れ共通の静かな間 7 s。静止判定は静止開始位置から 0.6 m |
| 相手の画面で犬が見ない・伏せない | 非 Owner の導出条件 (向き 40°、手から 0.8 m 以上、静止) を記録して報告 |

## 独立レビューと是正 (2026-09-20)

`vrc-codex-review` に基づき、別担当 (codex exec、D/M/X ロール) が未コミット差分を確認。1 回目 (gpt-6-astra) は "model at capacity" で最終報告前に停止し、途中所見 1 件のみ回収。2 回目 (既定モデル) で全ロールの報告を得た。

| 指摘 | 対応 |
|---|---|
| D 高: 休憩 (伏せ) 中に看板で目的地を変えても、人が動くまで再出発しない | 目的地変更を再出発として扱い、休憩・誘い状態と静止タイマーを初期化 |
| D 高: 到着状態が保持されず、人が広場内を歩くと犬が中心へ戻ろうとし境界で往復する | `_arrived` を保持。解除は目的地変更か、人が目的地の半径+6 m の外へ出たときだけ |
| D 中: 10 m 以上離れて経路不成立のとき瞬間移動判定が毎フレーム走る | 判定を 1 s 間隔に |
| D 中: 吠えイベントに送信者照合がない | 送信者が犬 Root の Owner でなければ無視 |
| D 途中所見: 伏せの導出に各端末ローカルの静止時間を使い、途中参加者は遅れて見える | 既知の制限として受容・記録 (上記) |
