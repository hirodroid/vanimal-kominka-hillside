# リード散歩の実装・検証記録

状態: PCVRで体験の楽しさを確認したプロトタイプ (2026-09-20、ユーザー報告)。項目別の動作・複数人・Quest単体・iOSの合格は未確定。

## 着手・範囲

ユーザーの「それで実装お願いします」に基づき、先端を持って首輪につける操作と、左右各3匹・計6匹で周囲を歩く機能を実装する。地形方式の実機確定を待つ従来の移植着手条件は、この実装指示により前倒しする。地形の完成・実機合格を意味しない。

## 首輪・先端の制作票

- 正本: [core-concept §3](../core-concept.md)、2026-09-19仮決め。秋の背景の中で犬と接続位置が見つかること。
- 分類: ACC (首輪)、PROP (持つ先端)。SHARED_MOBILE / DYNAMIC_LIT。最大6個ずつ、最短観察距離0.2m。
- 元の犬・リグ・毛の材質を維持。新規小物は非金属・低光沢の色付きベルトと金具色の先端。色だけで操作を伝えず、首輪に穴のある接続部を設ける。
- 犬種別の首位置・幅・高さ・傾きをEditor生成コードで管理。単一スケールの使い回しにしない。1骨に剛体追従し、物理の揺れは追加しない。
- 予算提案: 首輪1個600三角形以下、先端600以下、単色の共有Mobile/Standard Lite材質、追加テクスチャなし。UVは周方向と断面へ展開。実機性能は未測定。
- 確認条件: 門前の昼、6匹をプレイヤー目線、各犬の首輪を近距離の正面・側面・後方から。立ち姿はEditor、座る・伏せる・歩く・首振りの適合はユーザーPlayへ引き継ぐ。
- 既存犬材質の不足はUzumoreShader 1.0.20の依存追加で復元。購入材質の置換・編集はしない。

## 途中の検証

初回配線49項目合格後、Editor画像で毛シェーダー不足と首輪の円盤形状・位置ずれを検出。依存シェーダーの復元と犬種別の中空ベルトへの変更後、改めて配置・材質・接続輪を確認した。

## 初回実装の操作

入口の木のラックにある金具がリード先端。持って犬の首輪上の輪へ近づける。0.22m以内で0.25秒待つかUseで接続要求する。VRは持った手、Desktop/Touchはラック左側3個が左手用・右側3個が右手用。

自分の接続した犬の首輪をInteractすると解除。同じ左右の空いている先端がその場所に出るので、山上でボール遊びをしたあとも戻らず付け直せる。接続中はFetchを開始しない。犬は解除地点の周辺で自由行動する。

数値・復帰条件・同期契約は [game-design §4](../game-design.md) の初回実装値を参照。首輪の6色は仮の配色で、選択・保存・解放機能は未実装。

## 独立レビューと是正

`vrc-codex-review` に基づき、別担当 `/root/walking_code_review` がD (開発)・M (保守)・U (利用者)を確認。親担当のセルフレビューとは区別する。

| 指摘 | 対応・証拠 |
|---|---|
| D 高: Manager Ownerと犬Ownerが違うと接続とFetchが競合し、両方が移動を書き得る | Fetchは接続を検出した犬OwnerでGiveUp。WanderはFetch非Idle中は待機。再レビューで二重移動の解消を確認 |
| M 低: ManagerのroamRadiusが未使用 | 削除。自由行動値はWander.areaRadiusへ配線 |
| U 高: 山上で外しても先端が入口へ戻り、付け直せない | 本人の解除時に同じ左右の空いた先端を現地へ提示。保持中の先端は移動しない。再レビューで通常導線を確認 |
| D 中: Fetch解除後もWanderの出力キャッシュが残り、歩行アニメが再適用されない | Owner・受信側共通のApplyState enteredIdleでキャッシュ失効。次のApplyMoveAnimで全Boolを再適用。再レビュー問題なし |
| 親の独立データ検査: 参照配列がproxyにはあるがbacking.publicVariablesに無い | SDKの配列serializerが同じ長さのprogram defaultへコピーしてsetterを省く経路を特定。非同期参照配列の初期値をnullとしBuildで割当。別担当もSDKソースで原因・回避策を確認。同期配列は初期化を維持 |

- 後続の01:32確認ではConsoleにクライアントログ由来の例外1件が追加された。RuntimeLogWatcher経由で、01:31:28の古民家ドッグラン退出時のIsOwner例外だったことをクライアントの入退室ログで確認。裏山の実行結果ではなく、BehaviourはUnknownのため発生スクリプトは未特定。過去のerrors=0と現時点のConsole件数を混同しない。
- Scene: `Assets/Scenes/VRCDefaultWorldScene.unity`、Edit mode、Unity 2022.3.22f1。
- 6匹、Pet/Fetch/Pack、ObjectSync、首輪、材質、左右の先端、各犬から上の広場への完全経路、欠落スクリプト、ダミー非表示を別メニューで検査: **74項目、失敗0**。

- 犬のシェーダー不足に加え、導入前のlilToon最適化設定で毛のマスク・陰影が無効だった。Refresh shaders後、目と毛の描画復元をEditor画像で確認。素材の設定変更で隠さず依存とシェーダー設定を復元した。

## Playチェックリスト (項目別の結果は未取得・ユーザー担当)

### 0. Editorで判定できない条件

実際のVRC Pickup、VRの左右手、Touchの持ち物位置、他者の接続表示、Owner退出・途中参加、Uzumore/lilToonの両眼表示・モバイル描画、歩行アニメと地面追従は実機で確認する。

準備: シーン保存、Consoleの現行エラーなし、変更後にBuild & Testし直す。端末・入力方式・犬数・人数・開始時の接続状態を記録する。

### 1. 1人で確認

- [ ] ラックから先端を持ち、首輪の輪へ近づけて1匹につながる。顔や地面に近づけただけではつながらない。
- [ ] 左手3匹・右手3匹、計6匹をつなぐ。同じ手の4匹目は拒否され、既存の接続が外れない。
- [ ] 門→登り道→見晴らし→上の広場→門を歩く。停止・方向転換・小走りで、周囲についてきて足が動く。壁を横切らず、段差で沈まない。
- [ ] 1匹を首輪から外す。現地に出た先端で再接続できる。3匹・6匹の解除と付け直しも確認。
- [ ] 外した犬を撫で、ボールを投げて戻ってくる。遊んでいる最中の接続は待機し、接続済みの犬はボールへ走り出さない。
- [ ] 広場で立ち止まり、首輪や輪が毛に完全に隠れず、座る・伏せる・首振りで顔を貫通しない。サモエド・ポメなど毛量の多い犬も個別確認。
- [ ] DesktopとTouchでは左用・右用の先端を選んで接続・解除できる。先端を首の高さへ運べるかを確認。VRと同じ操作感とは仮定しない。

### 2. 2人以上で確認

- [ ] 同じ犬へ同時に先端を近づけ、一方だけが接続する。他人の犬の首輪を押しても解除できない。
- [ ] 遠隔側にも正しい人の左右へ線がつながり、犬が同じ位置を歩く。
- [ ] 接続している人が退出すると、その場で自由行動に戻り、残った人が接続できる。
- [ ] 最初の入室者 (Owner) の退出後も、残った人が接続・解除・散歩できる。
- [ ] 散歩途中に後から入室した人にも、現在の接続先と犬の位置が復元される。
- [ ] 片方がボールを投げ、他方が接続する競合を試す。犬の二重移動、持ちっぱなしのボール、脚を止めた滑走が残らない。

### 3. 対象端末

PCVR・Desktop・Quest単体・iOSそれぞれ、6匹散歩と複数人利用で描画、操作、メモリ・容量、継続利用時の快適さを測定する。現在はEditor構築確認とユーザーのPlay/PCVR総合評価まで。条件別の性能測定は未了で、モバイル対応済み・公開可能とは扱わない。

| 症状 | 最初に見るところ |
|---|---|
| 以前の挙動のまま | 最新変更後にBuild & Testし直したか |
| 犬がピンク／目が毛に隠れる | UzumoreShader導入とlilToon Refresh shaders。購入材質を変更する前に依存・設定を確認 |
