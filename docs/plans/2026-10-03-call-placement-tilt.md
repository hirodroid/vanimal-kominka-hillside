## 1. 結論 (推奨案)

- **VR では、置き始めたときの手の傾きを「水平」とし、そこから手を傾けた分だけ犬も傾ける。** 上限 30°、8° 未満は水平にそろえる。手のどの軸が上かを決め打ちしない方式なので、コントローラーの種類や持ち方に左右されない。
- **Desktop / Touch には手が無いので、自動で傾ける。** マーカーが地面から 0.15 m 以内にあれば、真下の地面の傾きに合わせる (上限 30°)。浮かせて置いたときは水平。
- **同期は、置き場所の板 (`KD_SleepSlot`) に傾き 2 つ (前後・左右、度) を足すだけ。** 犬の向きは今の `VRCObjectSync` が全員へ配るので、犬の側の同期変数は増えない。
- **犬は、置いた場所へ浮き上がる間に少しずつ傾き、起きたら必ず水平に戻す。** 今のコードには「水平へ戻す」処理が無い。足さないと、傾きが残る (§3.3)。
- 撫でる・あご乗せ・お手は、犬の体の向きを基準に計算しているので、傾けても破綻しない見込み。ただし、ユーザーの Play で確かめるまでは合格としない。

## 3. 設計

### 3.1 傾きの決め方

**VR (手)**

- `_Begin` のとき、右手の回転を基準 `R0` として控える。
- 毎フレーム、`ΔR = R_hand * Inverse(R0)` を求める。
- `ΔR` を、yaw (`_yaw`) で回した犬の前後軸・左右軸に分け、前後 (pitch) と左右 (roll) の角度を取り出す。手首をひねって向きを変えた分 (yaw 成分) は捨てる。yaw は今どおり ◀▶ で決める。
- 値の扱い:
  - 8° 未満は 0 にする (ふつうに置いた犬が、わずかに傾くのを防ぐ)。
  - 30° で止める (ひっくり返らない。ポーズのクリップが見られる範囲)。
- 傾き = `Quaternion.Euler(pitch, 0, roll)` を yaw の座標で組み立てる。最終の回転は `Euler(0, yaw, 0) * Euler(pitch, 0, roll)`。
- **基準を置き始めの手にする理由**: VRChat の手のトラッキングで「手のひらの上」がどの軸か、コントローラーごとの差は確かめていない。相対で取れば、その差を気にしなくてよい。持ち方を変えたいときは、板の [水平にする] (新規。押すと `R0` を今の手に取り直す) で直せる。

**Desktop / Touch (手が無い)**

- マーカーの真下へレイを撃つ。地面が 0.15 m 以内にあれば、その法線の向きに合わせる。
  - 上限 30°。それより急な斜面では 30° まで傾け、残りは浮かせる (置けない場所は作らない。032 の決定どおり)。
  - 8° 未満は水平。
- 地面から離れていれば (棚の上・宙・人の上)、水平にする。
- 新しい操作は足さない。

### 3.2 同期 (`KD_SleepSlot`)

- **同期変数を足す**: `float spotPitch, spotRoll` (度。±30 に収める)。増えるのは 8 B。Manual なので、送るのは確定と解除のときだけ。
- **要求の引数**: 引数がもう 8 個なので、足せない。`float yaw` を **`Vector3 angles` (x = pitch、y = yaw、z = roll)** に置き換える。Vector3 は今の引数 (`position`) でも使っているので、型は通る。呼んでいる場所 (約 10 か所。`0f` を渡している所) は `Vector3.zero` か `new Vector3(0, yaw, 0)` に直す。
- **受ける側 (板の Owner)**: `ValidPlacement` で値が有限か確かめ、±30 に clamp する。`PublishRelease` で 0 に戻す。
- **確定の照合**: `IsSubmittedCall` (`KD_SleepPlacement.cs` L157-163) に、pitch / roll を 0.01° で比べる処理を足す。
- **途中参加**: 板の同期値と、犬の `VRCObjectSync` の両方で届く。追加の処理は要らない。

### 3.3 犬の側 (`KD_DogWanderController.Sleep.cs`)

1. **向きのそろえ方を直す。** 今の判定は「犬の前方 (傾いていると斜め) と、水平の向きの角度 ≤ 12°」で比べている。犬を傾けると判定が外れ続け、`FaceTowards` が水平へ引き戻す、を繰り返す。犬の前方を**水平へつぶしてから**比べるようにする。
2. **浮き上がる間に傾ける。** Owner は、`rotation = Slerp(Euler(0, yaw, 0), 目標の回転, 浮いた割合)` を書く。浮いた割合は、置いた高さへの残り距離から出す。着いたら目標の回転に固定する。
3. **起きたら水平に戻す。** `GroundAfterPlacedSleep` を呼んでいる 3 か所で、`rotation = Euler(0, eulerAngles.y, 0)` を足す。**傾けない場合でも、今は戻す処理が無い。** 032 で宙に置けるようにすると、この処理が要る場面が増える。
4. **ほかの犬に押されて地面へ戻る件 (032 の段階で直す)。** `KD_DogPack.cs` L391 の「犬どうしの押し出し」は、寝ている犬も `SnapToGround` で地面へ押し付ける (向きは触らない)。032 で膝や胸の上に置いた犬が、隣の犬に押されて地面へ落ちる恐れがある。**置いて寝ている犬は、押し出しの対象から外す。** これは 033 ではなく 032 の不具合として扱う。
5. アニメーション (寝る・お手・あご・伸び) は、犬の根の座標で再生されるので、根と一緒に傾く。

### 3.4 撫でる・あご・お手・ほかの機能

| 機能 | 傾きへの対応 | 確認 |
|---|---|---|
| お手・あごの判定位置 | `root.TransformPoint` を使っているので追従する | ユーザーの Play |
| 撫での見る向き・ほおの向き | 犬の体の座標なので追従する。下を向く限度も、犬に対しての向きで決まる | 同上 |
| あご乗せの頭の動き | 手と骨の座標なので追従する。25° の限度はそのまま | 同上 |
| ハート | 世界の上向きに出る (見た目は自然) | — |
| 洗い場・水遊び・集合・フリスビー | 呼ばれて寝ている犬は対象外 (既存の除外) | — |
| リード | 呼ばれている犬はつなげない。つなげば呼ぶが解除される (既存) | — |
| 飾り | 骨に付いているので追従する | 見た目はユーザー |

### 3.5 マーカーと板

- マーカーの回転を、yaw だけから「yaw + 傾き」に変える。子のポーズの半透明も一緒に傾く。
- 傾いている間は、VR の板の状態の行に「かたむき 15°」と出す (新しいキー `KD_TreatPouch.WordSleepTilt`「かたむき {0}°」× 13 言語)。
- 板に [水平にする] を足す (新しいキー `KD_TreatPouch.WordSleepLevel` × 13 言語)。Desktop / Touch には出さない。

## 5. 工数とリスク

- **工数**: 032 に 0.5 日、033 に 1 日 (サブエージェント 1 本ずつ、続けて行う)。加えて、PCVR の確認 1〜2 回。
- **リスク**: 中。
  - 要求の引数の型を変える (呼ぶ場所が多い)。
  - 向きのそろえ方の往復 (§3.3 の 1)。
  - 手の相対回転の分け方が、体感と合うかどうか。
  - 犬の位置の書き手が複数ある (押し出し)。
- **公開日との関係**: 優先度は Low のまま。**032 の Play 確認が 10-06 までに済んだら着手し、済まなければ公開後に回す**ことを推奨する。032 で入れる「起きたら水平に戻す」「押し出しから外す」は、033 をやらなくても必要。

## 6. IMP-DOG-016 (法線 0.9) が勝った場合

016 が勝つと、マーカーはいつも地面に置かれ、法線 0.9 (約 26°) より急な所では確定できない。そのときは次のとおりにする。

- **手の傾きを使う意味が無くなる。** 犬を地面より傾けると、体が地面にめり込む。そこで 033 は「**すべての入力で、地面の傾きに自動で合わせる**」(§3.1 の Desktop / Touch の方式を VR にも使う) に縮める。[水平にする] と、VR の相対の計算は作らない。
- 地面に合わせて傾けるなら、ふせ・ごろんの体が斜面に沿う。法線の下限を 0.9 から 0.866 (30°) へゆるめられる。ゆるめるかどうかは別の質問になる。
- 工数は約 0.5 日に減る。同期の追加 (§3.2) は同じように要る。
