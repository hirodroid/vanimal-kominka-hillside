# plans/ — 実装計画書・実機チェックリスト

**必要になったときだけ**作る。作らないまま進めてよい。

## 作る基準

| 作る | 作らない |
|------|----------|
| 複数セッションにまたがる | 1 セッションで終わる |
| 手順の順序を間違えると壊れる | Issue の「完了条件」で足りる |
| **ユーザーの実施が挟まる** (Unity 操作・実機確認) | AI だけで完結する |

Issue に書けることを計画書へ二重に書かない。
**計画書は「順序と分担」を持つもの**で、何を作るかは Issue が持つ。

## 命名

```text
docs/plans/{yyyy-mm-dd}-{テーマ}.md
```

## 実機チェックリスト

VRChat で確認してもらう項目は、**必ず次の形式で書く**。

1. **§0 に「エディタで判定できない項目」を置く** — ここが NG なら他が全部通っても意味がない
2. **並び順は「何人必要か」順** — Issue 単位で並べない。上から順にやれば人数待ちで止まらない
3. **症状 → 見るところの表を付ける** — NG のとき何を疑うかを事前に書く

書式の詳細は共有リポジトリの `process/checklist-format.md` にある。

## 終わったら

- 完了した計画書は消さずに残す (前回何をどう確かめたかが次回の出発点になる)
- このフォルダには計画書のほか、実測・調査・報告の記録も置いてある。**完了した計画・実測は記録として残すもので、正本にしない** (仕様は game-design / world-ui-spec、状態は Issue)。**最新の現在地は [開発全体像](../development/overview.md) §3** を見る
- 一般化できる知見は**共有リポジトリの Skill へ**、残った課題は Issue へ
