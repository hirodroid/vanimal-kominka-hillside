# 洗い場へ犬を呼ぶ・高さを調整する — 設計と実装の約束

> 対象: [IMP-DOG-035](../development/issues/IMP-DOG-035-wash-call-dog-to-station.md)、[IMP-ENV-011](../development/issues/IMP-ENV-011-wash-height-adjust.md)。親は [IMP-DOG-024](../development/issues/IMP-DOG-024-walk-and-wash-experience.md)、方式は [設計書](2026-09-30-dog-wash-design.md)

2026-10-01。ユーザーの PCVR 確認 (2026-09-30 夜〜10-01) の指摘から。**実装していない。** 値は試作値。

## 1. ユーザーの指摘と決定

- 洗いたい犬を洗い場へ連れて来る方法が難しい → **犬を選んで呼べる。呼んだら洗い場に来て立ち、洗い終わるまでそこにいる** (決定)
- 犬を洗うには上下の位置合わせが要る。PCVR は OVR などで自分の位置を動かせるが、それ以外は難しい → **台の高さを調整できる** (犬を上げる。背の高い人向け)。**自分用の見えない床を作り、その高さも調整できる** (自分が浮く。犬を上から洗える) (決定)

統括の既定 (違えば変える): 操作は各洗い場の棚の **ボード** に置く (犬 6 匹のボタン、おわり、台 ▲▼、自分 ▲▼)。手元メニューには足さない。

## 2. 体験の流れ

1. 洗い場のボードで犬のボタンを押す
2. その犬が洗い場へ来る (遠ければ近くへ現れてから歩く。既存の「呼ぶ」「合流」の作法に合わせる)
3. すのこの上に、棚と平行 (体の両側へ人が回れる向き) に立ち、留まる
4. 台 ▲▼ で犬ごと台が上下する (全員に見える)。自分 ▲▼ で自分の足もとの見えない床が上下する (自分だけ)
5. 「おわり」を押すと犬は**すぐに**台を下りて (台が上がっていれば台と一緒に下りてから) 洗い場の外 (§6 の円の外) へ歩いて出ていき、そこから普段の行動へ戻る。座る・伏せる・その場で待つを挟まない。台は元の高さへ下りる (2026-10-02 ユーザー要望 §6)

## 3. 規則

| 事項 | 規則 |
|---|---|
| 1 つの洗い場に留まる犬 | 1 匹。別の犬を呼ぶと、前の犬は解放される |
| 呼べる犬 | リードを付けていない犬と、**呼んだ人が連れている犬**。他人が連れている犬は呼べない (拘束しない原則)。Fetch / フリスビーの最中の犬は、終わってから来る (5 秒待って来なければ「いまは来られない」)。**川で遊んでいる犬は、呼ばれたら岸へ上がって来る** (2026-10-01 ユーザー決定。水中のボール回収の最中は Fetch と同じ扱い)。2026-10-03 (IMP-DOG-037): **その洗い場から `callRange` (主 25 m・川辺 28 m・奥広場 25 m・展望のベンチ 25 m、試作値) 以内の犬だけ**。ほかの洗い場に留められている犬は断る、ほかの人が道具で洗っている犬は待つ。ボードに犬ごとの可否と理由を出す (§7) |
| 留まっている間 | Fetch・フリスビー・新しいリード接続は断る (洗われ中と同じ門)。体は回さない (決定済み)。頭の「たまに見る」と反応はこれまでどおり |
| 解放 | 「おわり」、別の犬を呼ぶ、集合・呼び戻し・ワープの明示的な要求、呼んだ人が退出、最後のストロークから 120 秒かつ呼んだ人が 10 m より遠い |
| 解放の後 (2026-10-02) | 洗いが終わった解放 (おわり・別の犬で交代・呼んだ人の退出・120 秒・洗い場の無効化・他人のリードで外れた以外の Owner の解放) では、犬はすぐ洗い場の外へ歩いて出る。集合・呼び戻し・ワープ、リード (呼んだ人の・他人の)、別の洗い場からの呼び出しで外れた時は、その用事・リード・別の洗い場が犬を連れていく (出ていく歩きは始めない)。§6 |
| 洗い場に近寄らない (2026-10-02) | 呼ばれていない・リードの無い犬は、どの洗い場の円 (台の中心から 4 m) も行き先・休む場所にしない。中に居たら歩いて出る。呼ばれた犬・リードの犬・道具で洗われている犬は対象外。§6 |
| 台の高さ | 0〜0.9 m、0.1 m 刻み。洗い場ごとに同期。犬がいない時は 0 へ戻る |
| 自分の床 | 0〜1.2 m、0.1 m 刻み。同期しない (自分だけ)。洗い場から 8 m 離れたら 0 へ戻る。動かす時は 0.5 m/s でなめらかに |
| 汚れ | 洗い場の 6 m 以内では汚れない (既存) |

## 4. 実装の約束 (担当間)

### `KH_WashStationCall` (新規 U#、洗い場ごと、`BehaviourSyncMode.Manual`)

洗い場のルートの子 `Call` に置く。Owner は奪わない (インスタンスのマスターのまま。犬の Owner と同じ想定で、違う時は犬のルートの Owner へ要求を回す)。

| 同期する値 | 内容 |
|---|---|
| `heldDog` (int) | 留まっている犬の番号 (0〜5)。無ければ -1 |
| `callerId` (int) | 呼んだ人の playerId |
| `lift` (float) | 台の高さ (m) |
| `arrived` (bool) | 犬が台に着いたか (着くまでは歩いている) |

| 配線する値 | 内容 |
|---|---|
| `stationIndex` | 0 = 主洗い場、1〜 = 道中 |
| `anchor` (Transform) | 犬が立つ点。台の上面の中心。`liftRoot` の子 |
| `liftRoot` (Transform) | 台 (すのこと、その Collider)。`lift` に合わせてローカルの y を動かす |
| `standYaw` | 犬が向く向き (棚と平行) |
| `dogs[]` (KD_DogWanderController、6) / `washes[]` (KH_DogWash、6) | 全犬 |
| `liftMax` = 0.9 / `liftStep` = 0.1 / `idleReleaseSeconds` = 120 / `callerFarMeters` = 10 | 調整値 |
| `callRange` (洗い場ごと。主 25 / 川辺 28 / 奥広場 25 / 展望のベンチ 25 m) | 2026-10-03 (IMP-DOG-037): 呼べる犬の水平距離の上限。Wash/11 が書く。0 以下 = 制限なし (§7.2) |

| 入口 | 内容 |
|---|---|
| `ReqCall(int dog)` | `[NetworkCallable]`。Owner が規則 (§3) で受けるか決める。送り主は `NetworkCalling.CallingPlayer` |
| `ReqRelease()` | `[NetworkCallable]`。誰でも解放できる (呼んだ人でなくてもよい。困った時に戻せるように) |
| `ReqLift(int steps)` | `[NetworkCallable]`。±1 刻み |
| `_Call(int dog)` / `_Release()` / `_Lift(int steps)` | ボードのボタンが呼ぶローカルの入口 (Owner なら直接、違えば上の要求を送る) |
| `_HeldDog()` / `_Arrived()` / `_AnchorPosition()` / `_StandYaw()` / `_Lift01()` | 犬の側とボードが読む |
| `_Availability(int dog, int player)` | 2026-10-03 (IMP-DOG-037): その人がその犬をいま呼べるか、呼べないなら理由。ボードの表示と Owner の受理が同じ関数を使う (§7.1) |
| `_ReleaseDog(int dog)` | 犬の側が、集合・呼び戻し・ワープの受理で呼ぶ (その犬を留めていれば解放) |

### 犬の側 (`KD_DogWanderController.HillsideWash.cs`)

- `public KH_WashStationCall[] washCalls;` (全洗い場)。毎フレーム、自分を留めている洗い場を探す (最大 4 個)
- 留められている時: 着くまでは既存の移動 (集合の「アンカーへ向かう」と同じ作法) で `anchor` へ。遠い (30 m 超) 時は既存の合流・ワープの作法で近くへ現れてから歩く。着いたら Owner が `arrived` を立てるよう洗い場へ知らせ、ルートを `anchor` の位置・`standYaw` に保つ (**台の高さへルートの y を書く**。地面への吸着は止める)
- 門: 留められている間は `WashHeld` と同じ扱い (Fetch / フリスビー / 新しいリード接続を断る)
- 集合・呼び戻し・ワープの受理のエッジで `_ReleaseDog`
- リード接続中で呼んだ人が持ち主の時: 留まる間はリードの追従を止め、解放で通常の追従へ

### `KH_WashPersonalFloor` (新規 U#、洗い場ごと、同期なし)

- `floor` (BoxCollider を持つ GameObject。5 × 0.1 × 5 m、見えない、プレイヤーが乗れる Layer)。台と棚の Collider とは重ならない高さの扱い (床が台より上へ行く時は台の周りだけ)
- `_Adjust(int steps)`: 0〜1.2 m。0 の時は無効。動かす時は 0.5 m/s。8 m 離れたら 0 へ
- 自分にだけ効く (各クライアントのローカルの Collider)

### ボード (ビルダー)

各洗い場の棚に World Space の Canvas。犬 6 匹のボタン (名前。顔の画像が既存にあれば使う)、おわり、台 ▲▼、自分 ▲▼、いまの状態 (誰を呼んだか、台の高さ、自分の高さ)。UI の作法は `vrc-world-ui` と `docs/world-ui-spec.md`。日本語のフォントは既存のものを使い、字形があるかを Verify で確かめる。

## 6. 終わったら出ていく・洗い場に近寄らない (2026-10-02 ユーザー要望)

Play の後の要望: 「終わりにしたら、犬は洗い場の台の上からすぐにトコトコトコって出ていくようにしてほしい」「洗い場には他の犬は勝手に近寄ってこないというか、台の上には休憩し始めたりとかもしないようにしたい」。実装は `KD_DogWanderController.HillsideStationLeave.cs` (犬の側)、`KH_WashStationCall.keepOutRadius` / `_LiftNow()`。同期変数は増やしていない (犬の Owner が決めて動かし、全員が同期済みの `heldDog` と固定の円から同じ判断をする)。

### 6.1 洗い場の円 (立入り)

- 各洗い場の `anchor` (すのこの中心) から水平に `keepOutRadius` (4 m。試作値、Wash/11 が書く)。すのこ・棚 (1.2 m 後ろ)・5 × 5 m の自分の床 (角まで 3.54 m) を含み、0.46 m の余裕。洗い場どうしは 20 m 以上離れているので重ならない
- 主洗い場では、おやつ `KD_Treat_0` (台の中心から約 2.3 m) とリード台 `KH_LeashRack` (約 3.1 m) が円の中に入る。おやつを食べに来るのは人の用事なので対象外 (食べ終わったら円の外へ出る)。リード台へは犬は行かない
- 円は 4 か所の `washCalls` から各犬が 1 回だけ読む (台は y だけ動くので水平の位置は変わらない)

### 6.2 おわりの後 (A)

| 解放の理由 | 犬 |
|---|---|
| おわり (`ReqRelease`)、別の犬を呼んで交代、呼んだ人の退出、120 秒 + 10 m、洗い場の無効化・再有効化 | 台の上 (または円の中) に居れば、すぐ出ていく。台が上がっていれば台と一緒に下りてから (はね落ちない) |
| 集合・呼び戻し (そばで寝る)・ワープの受理 (犬が `_ReleaseDog` を呼ぶ) | 用事が連れていく。出ていく歩きは始めない |
| 他人がリードを付けた / 呼んだ人のリードのまま解放 | リードが連れていく |
| 同じ犬を別の洗い場で呼んだ (新しい方が勝つ) | 新しい洗い場へ向かう |
| 呼ばれて向かう途中で解放 (円の外) | ただ自由になる (円の中なら 6.3 で出る) |

- 解放の瞬間 (全クライアント、同期済みの `heldDog` の変化): 洗われ中の保持を `KH_DogWash._ReleaseHold` で切り、満足の合図 (座る)・足上げを止める。`holdSeconds` の間その場に立つことはない
- 台が上がっている時: 犬の Owner が台の高さ (`anchor` の y) に合わせてルートを下ろす (台は全員の画面で `liftSpeed` 0.5 m/s で下りる)。台が下り切った後の残り (すのこの 0.03 m + すのこの下の地面の凹み。すのこの高さは下の地面の最も高い所に合わせてある) も同じ速さで地面まで下ろしてから歩き出す (2026-10-02 round 3。一度に落とさない)。洗い場が無効にされた時は台が下りない (Update が止まる) ので、犬が自分で同じ速さで地面へ下りる。この間は `WashHeld` (Fetch・フリスビー・新しいリードを断る) と `StationLocked` (押し合いで動かさない)
- 行き先: 円の外へ `stationLeaveMargin` (1 m) = 台の中心から 5 m。向きは立っている向き (`standYaw`、頭の方) から 45° ずつ 8 方向 (round 3: 見つからなければ 1.5 m・3 m 外の輪も 22.5° ずらして)。棚を通らない (棚の中心から 0.8 m より近づく線は外す。ただし犬がすでにそれより棚に近い所に立っている時は、今より棚に近づかない線なら可 = 棚から離れる向きは常に出られる。round 6: 棚のそばでリードを外した犬は 24 方向すべてが外れて出られなかった)、NavMesh の上 (1.5 m、外の輪は 2.5 m 以内で補正した点)、**補正した点がどの円からも 0.9 m 以上外**、補正した点への線も棚を通らない (2026-10-03 レビュー)、川の帯の外、(Owner) 人の 0.6 m 以内を通らない、の最初の点。犬の Owner が変わったら、新しい Owner が人をよけて選び直す。round 5 (統括: 線がきれいでなくても出る): 24 方向どれも条件を満たさない時は、棚を通らず川の帯でなく円から 0.9 m 外の候補のうち最初のもの (NavMesh の補正と人の判定は無視、まっすぐ歩く) へ出る。行き先が無くて止まることは無い (棚と川で 24 方向すべてがふさがる場合だけ)足は洗い場へ来た時と同じ (NavMesh の完全な経路があれば角ごと、無ければ直進)、速さは `stationLeaveGait` (0 = 歩き。**1 = 走りの脚に入る最低の速さ = 小走り (既定。2026-10-02 統括の決定「トコトコ」= 散歩の歩きではない)**、2 = 走り)。洗いが終わった時 (A と、下の猶予が切れた後) はこの足、円にふらっと入っただけの犬 (B) は歩き (`walkSpeed`。追い払われて見えないように)
- 終わり (round 3): **犬自身がどの円からも 0.5 m 以上外に出たら**普段の行動へ (行き先に着いたかではない。ワープ・置き直しで円の外へ出た犬の歩きもすぐ終わる)。締切 (3 s + 距離 / 速さ × 2) を過ぎてまだ円の中、行き先が見つからない、行き先に着いたのに円の外でない、は「失敗」。2 回続けて失敗したら 5 s (round 5 で 15 s から短縮) は円から出す歩きを始めない (普段の行動へ戻る。円の中で休まない・徘徊は円を横切らない、は続く)。出ていく歩きが終わると徘徊の今のホップは選び直す

優先 (上が勝つ): リード → Candy の演出 → Fetch / フリスビー → 洗い場に留まる (呼ばれた犬) → **台と一緒に下りる** → 道具で洗われている (保持・満足の合図) → 水遊び → そばで寝る (呼び戻し) → ライブ → 集合・かけっこ → おやつ → 催促 → あいさつの続き → **出ていく (A・B)** → 休憩 → 人のそばで立ち止まる → Fetch 明けの静穏 → じゃれ合い → あいさつ・立ち寄りの開始 → 徘徊。出ていく途中で上のどれかが犬を取ったら、出ていく歩きは捨てる (その後、円の中に居れば 6.3 でまた出る)

### 6.3 洗い場に近寄らない (B)

| 行き先・休む場所を選ぶ所 | 円 | やり方 |
|---|---|---|
| 徘徊の家 (`areaCenter`、round 3) | 適用 | 家が洗い場の中心から 半径 + 徘徊の半径 (3 m) + 0.3 m より近ければ、徘徊・じゃれ合いの計算でだけ外向きにずらす (円盤ごと円の外。主洗い場の家は中心から約 4.6 m なので約 2.7 m ずれる)。シーンの値は変えない |
| 徘徊の目標点 (`WanderTarget`) | 適用 | 円の中の点を円の外 + 0.3 m へ (中心から外向き、川の帯や他の円なら 45° ずつ回す。全部だめなら 1 m・2 m 外の輪、それも川の帯なら円の外の最初の点 = 川の帯の手前で止まる)。固定の円と川の帯だけから決めるので全クライアント・全犬で同じ点 |
| 徘徊の道筋 (round 3) | 適用 | 今いる所から目標点へのまっすぐな線が円を通るなら (線分と円の判定、ホップごとに 1 回)、同じ円盤の別の点を最大 3 回引き直す → だめなら円の縁を 45° (縁に近ければ 30°・18°) 回る回り道 → それも無ければこのホップは立ち止まる |
| じゃれ合いの共有の点 (`WanderAnchorAt` / `FleeHopTargetByHop` / 対面の待ち合わせ / 離れる先) | 適用 | 同じ関数。追いかけの回り込み点と対面の停止点は円の縁の内側へ数十 cm 入りうる (遊びの途中に通るだけ) |
| 休憩 (その場で伏せる。`waterPlace` は裏山に無い) | 適用 | 円の中と、円の縁から外へ `stationRestMargin` (1.5 m、round 7) までは休憩に入らない・伏せ続けない。出ていく歩きは縁の 0.5 m 外で終わるので、走った後の犬がその場で伏せないように (徘徊で離れてから休む) |
| 徘徊の窓の外の「足が止まったら伏せる」(`idleLieDown`、2026-10-03 レビュー) | 適用 | 休憩と同じ判定 (`KeepOutRestBlocked`: 円の中と縁の外 1.5 m) で伏せない。自由な犬が自分から伏せる・座るのはこの 2 つだけ (Fetch 明けの静穏・立ち止まり・あいさつは立ったまま。リード・立ち寄り先・そばで寝る・集合・Candy・洗われ中の反応は人の用事かリードで対象外) |
| 徘徊の窓の外の伏せ・目標点での立ち止まり・人のそばの立ち止まり・Fetch 明けの静穏 | 適用 | 円の中に居る自由な犬は、これらより先に円の外へ歩いて出る (じゃれ合いの最中は除く) |
| あいさつ・立ち寄り (人のそばへ行く) | 適用 | 始める時は相手の位置が円の中なら始めない (歓迎は 2 秒ごとに引き直す。立ち寄りはその周期の抽選を使い切る)。向かう途中は行き先 (相手の横の `SleepSpot`) が円に入ったら終える (中断の扱い `FinishInterruptedGreeting` で、次に引くのは 45 s 以上後) |

### 7.1 犬の状態 (受理の判定そのもの)

ボードの表示と Owner の受理は **同じ関数** (`_Availability(犬, 呼ぶ人)`) を、同じ同期済みの値に当てる。上から順に最初に当てはまったもの。

| 状態 | 判定 (どの同期値か) | ボード (色 + 2 行目) | 押した時 |
|---|---|---|---|
| ほかの人と散歩中 | `KH_LeashManager.walkers[犬]` が呼ぶ人以外 | 暗 + 金の文字「ほかの人と散歩中」 | すぐ断る (`RefuseLeashedByOther`、従来どおり) |
| この洗い場にいる | この洗い場の `heldDog` (`arrived` で「向かっています」/「ここにいます」) | 青 | 何もしない (呼び主は変わらない。従来どおり) |
| ほかの洗い場にいます | ほかの有効な洗い場の `heldDog` | 暗 + 金 | **すぐ断る** (`RefuseOtherStation`、新。従来は新しい呼び出しが勝って連れていった) |
| 遠すぎます | 犬のルート (VRCObjectSync で全員に見える) と `anchor` の水平距離 > `callRange` | 暗 + 金 | **すぐ断る** (`RefuseTooFar`、新) |
| ボールで遊び中 | Fetch の `dogState` ≠ Idle (水中のボール回収を含む) | 暗 + 金 | 待つ: 5 s 以内に空けば来る、空かなければ断る (従来どおり) |
| フリスビーで遊び中 | `KH_FrisbeeCatch.state` ≠ Idle | 暗 + 金 | 待つ (従来どおり) |
| 集合しています | 集合 (mode 1) の参加犬 | 暗 + 金 | 待つ (従来どおり。集合は 60 s なので普通は断られる) |
| 呼ばれて休んでいます | そばで寝る (`LiveSleeperOf`) | 暗 + 金 | 待つ (従来どおり) |
| ほかの人が洗っています | `KH_DogWash` の洗い保持中 (最後のストロークから `holdSeconds` 3 s) かつ、その保持を立てたストロークの人 (同期の `washBy`) が呼ぶ人でない。呼ぶ人がリードで連れている犬は除く | 暗 + 金 | **待つ** (新。保持が切れたら来る) |
| 呼べます | 上のどれでもない。**自分がリードで連れている犬・自由に水遊びしている犬を含む** | 緑「呼べます」(押した後、返事までは青「呼んでいます」) | 受理 |

- 順番の理由: リードは「留まっている」より先 (従来の Arbitrate と同じ。Codex 1: 再呼び出しで素通りさせない)。「遠すぎます」は遊びの理由より先 (遊びが終わっても呼べないので、より決定的な理由を出す)
- **出さない状態** (呼ぶと受理し、犬の側の優先 §6.2 で後から来る): 自由な水遊び (2026-10-01 ユーザー決定: 岸へ上がって来る)、おやつを食べている・催促、Candy の演出、あいさつ・立ち寄り、休憩、ライブの観客、撫でられている。いずれも短いか犬自身の行動で、断る理由にしない。ワープの予約はリードの犬だけなので「散歩中」に含まれる
- 色だけに頼らない: 3 つの見た目 (緑 = 呼べる / 青 = この洗い場の犬・呼んでいる / 暗い面 + 金の文字 = いまは呼べない) に、必ず 2 行目の文字を付ける。暗いボタンも押せる (押すと理由を出す)
- 押せない状態を押した時: ボードがその場で「名前：理由」を状態行に 3 s 出す (ネットワークを待たない)。要求は Owner へも送る (Owner が同じ規則で断れば同じ文、こちらの画面が一瞬遅れていて実は呼べたなら受理される)。待ちの末の断り (`RefuseBusy`) は、その時ボードが見ている理由 (「集合しています」など) を出し、分からなければ「いまは来られません」
- 待ちの終わりも同じ関数で見直す: Fetch が範囲の外で終わった・待つ間にリードが付いた・ほかの洗い場が先に留めた、はその理由で断る (来させない)

### 7.2 呼べる範囲

**以前**: 距離の制限は無く、30 m (`StationFar`) より遠い犬は洗い場から 6 m の所へ現れてから歩いた。川辺の洗い場から約 470 m 先の主洗い場 (門・古民家側) の犬も呼べた。

**規則**: `anchor` (すのこの中心) から水平に `callRange` 以内の犬だけ。円にしたのは、洗い場どうしが 80 m 以上離れていて境界の形で迷う所が無く、全員が同じ値から同じ答えを出せるため。洗い場ごとの値は Wash/11 が書く (`KH_DogWashSetupEditor.CallRanges`)。

|---|---|---|
| 主洗い場 | 25 m | 門の待機の輪・周回の始点 (約 6〜7 m)、リード台 (約 3 m) を含む入口の広場。展望のベンチの洗い場 (約 80 m) には届かない |

### 7.3 同期

使う値は同期値だけ: `walkers` (リード)、各洗い場の `heldDog` / `arrived`、Fetch の `dogState`、ディスクの `state`、集合の `mode` / 参加犬、そばで寝る、洗い保持 (`washMs` / `washSeen` / `washBy`)、犬のルート (VRCObjectSync)。

**増やしたのは `KH_DogWash.washBy` (int、4 byte) 1 本だけ** (2026-10-03、8faf572 の独立レビュー): 洗い保持を立てたストロークの playerId。Owner が `washMs` と同じ所で同時に書くので、途中参加の人・Owner が代わった直後でも「誰が洗っているか」が保持と一緒に届く。最初の実装は同期されないローカルの「この画面で最後に見たストロークの人」(`_lastWasherId`) を読んでいたため、途中参加の人のボードは「呼べます」、他の人は「ほかの人が洗っています」となり、その時に洗い場の Owner が代わると洗われている犬の呼び出しを受理しえた (規則 1「表示と受理が同じ同期値」に反する)。`_lastWasherId` は見つめる相手 (視線) のためのローカルのまま残す。断った理由は既存の `refusedReason` に新しい値 4 (`RefuseTooFar`) と 5 (`RefuseOtherStation`) を足しただけ。「呼んでいます」(自分が押して返事待ち) はボードのローカル (従来の `_myPick`)。

### 8.3 実装

- `KH_WashStationCall` (同期しないフィールド): `standTable` (= `Lift/WashTable`)、`standSize` (Vector3[6]、犬 index 順、(長さ, 幅, ずれ)。null で宣言し Wash/22 が確保)、`standIdle`、`standBaseSize` (1.3 × 0.03 × 0.7)、`standBasePos` / `standBaseScale` (シーンの WashTable の値)、`standSpeed` 1.5。`[NonSerialized] standKeep` (写真選択が書く)。`_StandSize()` (目標、Edit でも呼べる純粋な関数)、`_StandPose(s)` (transform へ書く)、`StandStep()` を `Update` の高さの処理 (`if (_liftNow == want) return;`) より前で毎フレーム。止まっている時はキーの比較だけ
- `KH_WashSelection`: `bathKeepsSize` (bool[]、item id 順、プールだけ true。null 可で `_Ready` に入れない) と `_KeepsSize(bath)`。`_Apply` がモデルを表示する前に `call.standKeep` を書き (各端末が同期済みの `selectedBath` から)、プールへ切り替わった時は `call._StandSnapNow()` で目標・現在値・transform をその場で元の大きさにする (Codex レビュー 2026-10-12: 2 つの Update の順によっては縮んだプールが 1 フレーム見えたため)。プールから外れた時は `StandStep` が普段どおり寄せる
- WashTable の BoxCollider (層 17) は transform と一緒に拡縮する (BoxCollider の API は呼ばない)。人と犬の地面レイは通り抜け、Pickup と落とした道具だけが当たる
- **WashPremium/21 の保全検査**: `KH_WashStationCall` を JSON にして基準と比べるため、新しい 7 フィールド (`standTable`〜`standSpeed`) を比べる前に両方から外す (`KH_WashPremiumEditor.StripStand`)。基準は取り直さない (足す前の基準も後の基準も同じ形で比べられる)。新しいフィールドは Wash/23 が見る

### 8.4 Apply / Verify

- **Wash/22 - Apply Stand Sizes** (シーンを保存しない。未保存の変更があれば何もしない): 6 匹の足を測り、4 か所の洗い場で前提を確かめてから書く。前提 (1 つでも外れたら何も書かない): Lift の拡縮 1、WashTable は拡縮 1・回転なし、固い BoxCollider 1 つ (1.3 × 0.03 × 0.7、層 17) で下にほかの Collider なし、WashTable の下に Behaviour なし、子はスラット 5 本・`ImportedPlatform`・写真選択の台のモデルだけ、Anchor が台の上面中央、`standYaw` = 洗い場の向き + 90 で犬の前が Lift の ±X、**照明の前提** (WashTable 以下の static フラグ 0・ライトマップの index なし・Light Probe 照明・Bakery の保存先に無い。このプロジェクトに Bakery は入っていない)。書くのは `KH_WashStationCall` の stand* と、写真選択の `bathKeepsSize`・`call` (未配線なら)。proxy → Udon へ写す。2 回目は changed 0
