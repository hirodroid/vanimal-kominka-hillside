## 7. 端末・空間・入力

移植候補は古民家のVR右スティック下長押し・DesktopのT・Touchのメニューボタン。閉じるは共通ボタンを置く。VR/Touchの再操作は手元へ再配置、DesktopのTは開閉という既存差も確認する。これは古民家の調査結果であり、裏山での動作確認ではない。片手で右スティックを使えない場合の入口、拠点から道具を受け取る操作、Desktop/Touchで左右を指定する操作はモックで具体化する (下の「取り出し操作」で解決済み)。下表のunknownはその未確定値を示す。

取り出し操作 (2026-10-03 確定、散歩の帯 (IMP-UI-002) の実装時にコードと照合): 各拠点に左用1個・右用1個の先端があり、VRは先端を取った手が接続先になる。Desktop/Touchは手元メニュー「さんぽ」の犬ごとの [左につなぐ] [右につなぐ] [はずす] で接続し (犬から4m以内)、先端を首輪へ近づけてもつなげる。拠点の板をInteractすると手元メニューが開く (`KH_MenuOpener`)。下に残す「拠点Interactで目の前に道具を出し、左/右を選んでPickupで持つ」試作案は採用しなかった。試作時の記述: 自動で手に持たせられると仮定しない。手首・しゃがみ操作が難しい場合はメニューから犬と左右を選んで直接接続する。同じ拠点を他人が使用していても各自が使える。右スティックを操作できない片手利用向けには拠点のメニュー入口を試作し、散歩先で再度開く導線も確認する。これらは新たなユーザー判断待ちにせず、実機の到達性・誤操作を開発側で比較する。

## 10. 設定の充足判定

- 対象画面について主目的と主要操作が書けている。
- 使用する役割トークンが具体値または追跡可能な参照で解決できる。
- 各数値に単位・適用する端末/距離/scale・根拠種別がある。
- 操作に対象・権限・状態・結果・復帰が対応する。
- 対応すると記載した全入力で入口と出口がある。
- 共有/CE/保存のunknownは、実処理接続前に解消する。
- provisionalとNOT_TESTEDをready/PASSに取り違えていない。

この判定は文章による契約。エージェントへ渡す時に自動検査コードが存在すると誤認させない。必要なら既存のワールド検証ツールへ未定義トークン・接続欠落等の検査を追加する。

## 初回の散歩案内（2026-10-10 / 実装済み・実機確認待ち）

### 目的と採用範囲

ユーザー採用: 初めて散歩する人へ、大きく弾む矢印でリードを示す → 持ったら首輪が光る → 接続後に「犬について歩こう」と短く伝える。最初の接続までを助け、行き先の変更は既存の「さんぽ」メニューで後から発見してもらう。下記の表示寸法・秒数・保存と例外処理は実装のための提案値で、実機の合格値ではない。

主目的は「気になる犬に近づいた人が、リードを取り、その犬へつなげられる」。動物への接近・撫で・他の遊びを妨げず、犬の行き先・進行速度・接続操作そのものは変更しない。道や洗い場の再配置は今回に含めない。犬を入口へ強制帰還させたり、案内専用に予約したりしない。

根拠: [core-concept §1・2](core-concept.md)、[既存の散歩仕様](game-design.md)、[現地案内](plans/2026-10-03-onsite-guides.md)。2026-10-10に本番シーンの実スポーン位置・向きからEditor撮影したところ、犬とリード台は既に正面にあり、持つ道具の認識が改善対象となった。犬の実行時の向き・反応は静止画で判定していない。

### プレイヤーに見える3段階

| 段階 | 表示と動き | 主文言 | 次へ進む条件 |
|---|---|---|---|
| 1 取る | 入口で実際に取れるリード先端1つを丸で囲み、その丸へ大きな下向き矢印を1本。矢印だけゆっくり上下し、軽く膨らむ。本人にだけ見える | **リードを取ってみよう** | 本人がいずれかのリード先端を持つ |
| 2 つなぐ | 台の矢印を消す。近くの接続可能な犬の首輪の接続リングへ、明るい輪を重ねる。近づけた先端の既存の緑表示も残す | **リードを、光った首輪へ近づけよう** | 既存Managerの裁定後、その犬の接続先が本人になったことを確認 |
| 3 出発 | 首輪の案内光を消し、つながった犬の近くに短い成功案内を出す。実際の紐と犬が見えることを優先 | **つながった！ 犬について歩こう** | 約5秒（仮）でフェードして終了。歩行距離・完走を要求しない |

台付近でリード先端を持つと周辺の空いている犬が台へ寄る常設の反応も追加した（[IMP-DOG-045](development/issues/IMP-DOG-045-leash-rack-invitation.md)、実機確認待ち）。この反応は個人用チュートリアルの表示・完了・再表示設定に依存しない。

段階3は次の課題を要求するチュートリアルではなく、接続成功と出発を伝える締めの表示。完了記録は接続成立時点に置き、再入室時の段階1・2の自動表示を止める。「首輪にタッチ」は素手で触る意味に読めるため、表示は「リードを…近づけよう」とする。現在の物理接続は先端を接続点付近へ置く操作であり、新たなクリック・ボタン押下を必須にしない。

**出発後の行き先ヒント（2026-10-10追加）**：接続成功を5秒表示した後、「メニューで行き先を変えられるよ」を5秒だけ表示する。この切替時に本人用メニューを一度だけ開き、さんぽタブを選び、犬の首輪より上（板の下端を首輪＋0.2m以上）へ据える。水平距離は本人から1.2〜2.5mに収め、以後犬には追従しない。行き先6ボタンの周囲を四隅の印で囲む。色はVAnimalのsite.cssに合わせ、温白 **#FFFDF8** と森の緑 **#364E3C** の縁。ゆっくり明滅させ、入力を遮らない。接続成功後に本人が閉じる・タブ変更・設定・呼び戻しを操作した場合、自動配置を取り消す。自動配置後にメニューを閉じる・別タブへ移ると印も消え、強制的に開き直さない。案内終了時は印だけ消し、メニューはその場に残す。行き先の選択は追加の達成条件にしない。

接続すると手に持った先端は台へ戻り、犬と本人を結ぶ既存の紐・持ち手表示へ切り替わる。この自動Drop・回収を失敗と判断して段階1へ戻さない。左右どちらの先端・どの犬でも成立する。一度に1匹をつなげれば完了で、複数頭・左右の使い分け・外し方・行き先変更は追加ステップにしない。既存の常設操作図とメニューは残す。

### 演出・配置の試作値

- 矢印は台全体ではなく、**実在する拾える先端**を指す。初期は入口台の近い先端1つを対象にするが、もう片方を持っても進む。対象が利用可能な間は同じ先端を指し続ける。直径0.21mの丸が先端を囲み、矢印先端はその中心の上0.13〜0.23mを動く。常設説明ボードへの重なりは許容し、取る物の特定を優先する（2026-10-10ユーザー修正）。遠い台・保持中・接続処理中の先端には誘導しない。返却先が変わるため、台の固定座標を成功条件や指示対象にしない。
- 試作値: 矢印の高さ0.45m・幅0.30m、上下幅0.10m、約1.2秒周期、拡縮1.0〜1.08。瞬間的な点滅や効果音の反復は使わない。矢印の先端と拾う物の間を空け、手や照準を覆わない。画面中央の固定HUDやカメラの回転で視線を強制しない。
- 色はcore-conceptの発見対象色を起点とし、明るい縁で暗い台・昼夜両方から区別する。既存の「緑=接続候補」の意味は保持する。首輪の案内は既存の首輪マテリアルを上書きせず、個人表示の輪を追加する。光の見た目にリアルタイムLightは不要。
- 主文言は暗い小面＋明るい文字、1文のみ。同時に3段を並べない。取る段階の面は台付近に置き、初期は幅1.2m・高さ0.24m、実字高約0.05mを出発点に入口約4mと接近時で調整する。数値はPCVRの試作値であり、低い目線・Quest・スマホへそのまま合格を流用しない。
- 持っている間の説明はリード先端そのものに貼り付けず、接続する手・犬の顔・首輪を隠さない近傍へ配置する。複数の首輪が見える場合も文章は1枚のみ。近い利用可能な犬の接続点を弱く示し、先端を近づけた相手を強くする。照準先を頻繁に切り替えない。
- 読むだけの矢印・光・本文には操作Colliderを持たせない。「閉じる」は本文脇の独立した小ボタンとし、既存WorldSpace UIの入力要件に従う。閉じるボタンは動く矢印や首輪へ追従させず、操作可能な位置を安定させる。

### 起動・終了と個人保存

- 対象は「裏山で初回接続の完了をまだ記録していない本人」。自動表示は入口の案内範囲内だけ。入室直後は個人データと共有接続状態の準備を待ち、準備後約2秒（仮）で始める。設定・言語選択などの操作面が開いている間は重ねない。
- 保存候補キー: `KH_WalkIntro.connected.v1`（本人の初回接続完了bool）、`KH_WalkIntro.hidden.v1`（本人が設定で自動案内をOFFにしたbool）。自動開始は未完了かつOFFでないとき。自分のPlayerDataへだけ書き、進行・矢印・首輪の光はネットワーク同期しない。
- **接続成立の観測は復元待ち中も行う。** その間に自力でつないで外した場合も、その入室中の成功を仮保持する。復元後に `保存済み完了 OR 今回の接続成功` で完了を確定し、成功があれば保存する。復元が来ない間は自動表示・保存を保留するが、散歩の操作は阻害しない。
- 「歩いたことがない」を歩行距離履歴として遡及判定しない。この機能の完了条件は初回接続。導入前の利用者の過去の散歩経験は、新しいキーだけでは判別できないため、一度表示され得る。既存の別の保存値から経験を推測しない。
- 入口の「閉じる」は**その入室中の案内だけ終了**。完了としては保存しない。同じ入室で入口へ戻っても再表示しない。既存メニューの設定内に「散歩の案内」→「もう一度見る」「自動案内 ON/OFF」を置く提案とする。入口に設定の選択肢を並べない。手動再表示でも保存済み完了は消さない。
- 案内範囲を離れたら台への矢印を消し、未接続のまま世界中へ追従させない。入口へ戻れば、閉じていない場合だけ現在の保持・接続状態から再開する。範囲境界には差を設け、仮に入口中心から水平10m以内で開始・12m超で中断する。Collider/地形・他の拠点との関係をシーンで調整する。
- 成功の記録は自動案内OFF・範囲外・メニュー経由でも行う。ただし非表示中の自力接続に対して、突然大きな成功案内を出さない。案内中だった人だけ段階3を見せる。

### 途中で止まらないための状態契約

内部状態は `復元待ち / 取る / つなぐ / 接続確認待ち / 出発案内 / 一時中断 / 終了` とし、可視の学習段階は増やさない。優先順位は「確認済み接続成功 → 接続要求待ち → いずれかの先端を保持 → 拾える先端への誘導」。片手を離しても、他方に先端を持っていれば「つなぐ」を続ける。

| 条件 | 振る舞い |
|---|---|
| 持たずに犬へ近づく・撫でる | 操作を奪わず、台の誘導を継続。犬の視界を覆わない |
| 未接続で先端を離す | 要求待ちでなければ「取る」へ。返却後の実物を指す |
| 接続要求中に離す | 結果の確認を優先し、台への誘導を再開しない。既存要求の解決・timeoutを待つ |
| 拒否・timeout・相手の状態変更 | 完了にしない。現在の保持/利用可能状態へ復帰し、必要時だけ短い案内を出す。チュートリアル側から勝手に再要求しない |
| 犬が他人と散歩・洗浄・遊び・集合・呼び寄せ中、水中など | 接続不可の犬の首輪を光らせない。接続可否は既存Managerの裁定条件と揃え、共有結果を最終判断にする |
| 入口付近に利用可能な犬がいない | 大矢印と首輪の光を停止。「近くに、いま散歩できる犬がいないよ」。強制招集しない。入口周辺に候補が戻るまで控えめな待機状態 |
| 犬はいるが入口に拾える先端がない | 内部では犬不在と分け、空の台を指さない。既存メニュー経由の接続を補助として案内。道具を他拠点から強制移動しない |
| メニュー等で段階を飛ばして接続 | 成立時に同じ完了へ進む。物理操作をやり直させない |
| 成功後すぐ解除 | 完了記録を維持。出発案内は紐がなくなった時点で閉じる |
| 他人の接続・切断・Owner交代 | 本人の成功と誤認しない。Owner本人の直接更新と非Ownerの受信の両方で確認する |

案内対象は入口の実在先端と入口付近の犬。首輪の光は本人から接続可能な距離内（現行attachReach=4m）の候補に限定する。局所表示の判定後に他人が接続する競合は起こり得るため、光ったことを接続保証・犬の予約と扱わない。

### Desktop・Touch・多言語

2026-10-10のユーザー修正により、端末にかかわらず最初の丸と矢印は実際のリード先端を示す。Desktop/Touchでメニューボタンへ矢印を出す分岐は廃止。同日の追加修正で、ウェルカム・設定・別タブを含めメニューボードの表示は物理リードの案内を止めない。開いているだけでメニュー接続案内へ切り替えず、丸と矢印・首輪の光を継続する。既存メニュー経由で接続しても同じ完了へ進む。入口台のメニューボタンは横棒の入口側へ移し、常設説明ボードと同じ向きに揃える。左右どちらでもよく、最初から両手の使い分けを教えない。

文言は既存KD_Languageへ追従し、13言語（ja/en/ru/uk/ko/de/zh-cn/es/fr/pt-br/it/pl/zh-hk）のキー・字形・枠内収まりを確認する。矢印や画像へ文字を焼かない。手動言語切替・非表示からの復帰でも現在の段階を正しい言語で描く。ここに記した日本語は設計文言であり翻訳/フォントの実装済みを意味しない。

### 既存コードとの接続と検収

新規候補は個人案内専用 `KH_WalkIntro`（独立GameObject、同期None）。`KH_LeashClip`の保持・要求待ち、`KH_LeashManager`の確定接続状態、PlayerData復元、既存メニューと言語の状態を参照する。表示のためにManagerのOwnershipを取得したり、接続先・行き先を書き換えたりしない。ローカル専用publicイベントは `_` 始まり。

コード調査（2026-10-10）で、Clipの近接候補条件はManagerのReqAttachより緩く、洗浄・呼び寄せ・集合・水・フリスビー等の全条件を含んでいなかった。**案内光をClipの既存候補だけから決めない。** 実装時にManagerの許可条件と整合する副作用なしの可否照会を用意し、Owner側の最終裁定は維持する。現在の接続半径0.22m・保持0.25秒・先端の緑表示をチュートリアル都合で変更しない。成功観測はOwner直接更新と非Owner受信の両方を入口にし、復元前の成功も落とさない。必要な既存イベント差込位置・初回共有状態の準備条件は実装時にコードで確定する。

実装後の確認対象: 1人で初回3段階/左右/途中Drop/先にメニュー接続/即解除/閉じる/再表示/再入室・復元待ち中の成功、2人で同時接続・先に相手が接続・他人の進行が見えない・全頭利用中・Owner交代。VR/低い目線/非VR/Touch/昼夜/13言語で、取る物と首輪が見つかり、犬と手を遮らず、最後の紐への切替が理解できるかを確認する。Editor検査や画像だけでこれらを実機合格にしない。

レビュー: 実装に関わっていない別エージェントが設計と現行Clip/Manager/保存処理を読み取りレビュー。利用不可の犬への発光、空の台への誘導、復元前成功の取りこぼし、入口へ設定を並べる過剰さの指摘を上記へ反映。設計後に実装・シーン配線・C#/UdonSharpコンパイル・独立レビューまで実施。実機確認は未実施。実装記録と確認項目は[IMP-UI-006](development/issues/IMP-UI-006-first-walk-intro.md)を参照。
