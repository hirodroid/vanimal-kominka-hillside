# 古民家の裏山 — 企画・散歩仕様

> **仕様の正本。** 根拠は後から受領した [11 項目の散歩企画資料](reference/VAnimal_KominkaHillside_Walking_Addendum.md) を優先する (2026-09-19 ユーザー指定)。以前の企画原本・会話・試作と食い違う場合も後の資料に合わせる。旧原本は履歴として保存する。
> 意図・ビジュアル方針は [core-concept.md](core-concept.md)。
> 資料受領後にユーザーが具体化した決定は本書へ反映し、§8 に日付付きで残す。

## 1. 目的と位置づけ

「古民家の裏山」は、古民家ドッグランの同じ 6 匹と秋の山へ散歩に出かける別ワールド。訪問数・バズより、犬への愛着を別の場所・過ごし方へ広げる拡張エリアとする。古民家だけでも遊びが完結し、もっと楽しみたい人には散歩先がある関係を守る。

別ワールド化は Quest 単体・iOS の快適さを守り、容量・負荷を配分する制作方針。同一ワールドでは技術的に不可能と確認した結果ではない。古民家は遊ぶ・くつろぐ・一緒に寝る、裏山は連れ出す・歩く・景色を楽しむ。

**PC に加え Quest 単体・iOS 対応を目指す。** 対応確認済みではなく実機で検証する。軽量な景観と必要なギミック、既存の仕組み・素材の再利用で管理し、自作・Terrain だから軽いとは判断しない。固定納期は設けない。

## 2. 散歩体験の中心

気に入った犬と少し歩き、遊び、休む。リード操作や犬の制御の難しさを遊びの中心にせず、周囲で自然に動く犬と一緒に出かけた感覚を重視する。

一緒に歩きたい犬のところへ行く → リードの先端を手に持って犬の首輪に取り付ける → 犬と山道を歩く → 止まって撫でる・おもちゃで遊ぶ → 再び歩く・休む・古民家へ戻る。

首輪へリードを取り付ける体験は 2026-09-20 にユーザーが決定。接続を成立させる細かな入力・判定、左右の割当方法、解除、端末別操作・UI は未確定。山から古民家を見る眺め、犬と遊べる場所、休める場所を必要な範囲で用意する。

## 3. 景観と現在の試作

秋の裏山を Unity Terrain で作る方向。木・草・岩は見た目と負荷を見て配置する。軽量化した古民家の外観を遠くに置き「あそこから来た」と感じられるようにする。不要な室内設備・ギミックは持ち込まない。購入済み秋山アセットと依存素材は必要に応じて採用し、完成シーンの丸ごと使用は前提にしない。

**コース長、周回か往復か、休憩場所の数、ワールド端の処理は未確定。** 後の資料を優先し、以前の配置の了承を最終仕様の固定とは扱わない。

現在の Terrain v4 は「門の前 → 一本の登り道 → 見晴らし → 上部の遊び場」。道 112.6 m、広場直径 24 m・標高 19 m は試作値に限る。2026-09-20に実物6匹を門前へ導入し、地形のダミーは非表示にした。画像・視点検討は [地形計画 §12・13](plans/2026-09-19-terrain-prototype.md) に記録。見た目の了承と Play・実機負荷の合格は区別する。木の追加も検討段階。

## 4. 犬・リード・遊びの仕様

### 決定事項

| 項目 | 内容 |
|---|---|
| 犬 | 古民家と同じ 6 匹をベースにする |
| つなぎ方 | リードの先端を手に持ち、一緒に歩きたい犬の首輪へ取り付ける |
| 接続中 | プレイヤーの周りを歩く。つないだ手を基準とする一定範囲内で行動し、手元の一点に固定しない。距離・前後左右の細かな動きは調整対象 |
| 未接続 | 自由行動。山全域を無制限に移動できる意味ではない |
| 上限 | 片手最大 3 匹、左右合わせて 1 人最大 6 匹 |
| 接続先 | 左右を選べる |
| リードの役割 | 一緒に歩く犬の選択と行動範囲の指定 |
| 物理 | 絡まり・引っ張り合いはシミュレーションしない |
| おしゃれ | 首輪・リードで楽しめるようにする |
| 睡眠部屋 | 専用の部屋は作る必要がない |

### 既存の遊びと未決定事項

既存の遊びに首輪・リードが増える方向。おもちゃは残したく、リードとの置き換えにはしない。撫でるなどは古民家の仕組みをベースにする。

| 項目 | 未決定の内容 |
|---|---|
| 操作 | 先端を首輪へ取り付ける際の成立判定・入力、左右の割当方法・解除、VR・デスクトップ・スマホそれぞれの方法 |
| 範囲・移動 | リード長、立ち位置・範囲内の動き、自由行動範囲・帰還、高速移動・段差・障害物対応 |
| 複数人 | 同じ犬を複数人が選んだ場合の扱い、接続者退出時の解除・帰還 |
| 遊びとの連携 | リード中の Fetch の可否、遊ぶ際の解除要否、呼び出し・集合との優先順位 |
| 同期 | 接続先・犬の状態の管理主体、既存移動との連携 (§5) |
| おしゃれ | 種類・選択方法・保存・公開範囲・解放条件。既存の飾りを持ち込むか絞るか |
| 屋外休憩 | 伏せる・一緒に休む動作と体験の範囲 |
| トレーナー機能 | 集合などの構想はあるが対象機能は未確定 |
| 性能 | 6 匹の散歩・複数人利用で対象端末の快適さを保つための予算と検証 |

具体値・挙動は既存の犬システムを確認して決める。設計課題は [DES-DOG-001](development/issues/DES-DOG-001-leash-walking.md)。

### 散歩の初回実装値 (2026-09-20)

ユーザーの実装指示に基づく調整用の初期案。以下の数値・補助操作をユーザー確認済みの最終仕様とは扱わない。上の未決定表のうち操作・移動・同期・Fetchについては、この案をPlayで評価する。

| 対象 | 今回の実装 |
|---|---|
| 接続 | 持った先端を首輪の接続点から0.22m以内に0.25秒置く。候補がある間のUseでも要求できる |
| 左右 | VRは実際に持つ手。Desktop/Touchは入口の左用3個・右用3個の先端を選ぶ |
| 解除・再接続 | 自分の接続した首輪をInteractで解除。対応する左右の空いた先端がその場に現れ、再接続に使える |
| 接続中の範囲 | リード長の初期値3m。手の周囲へ犬ごとに少し異なる目標を置き、ゆっくり変化させる。物理的な硬い長さ制限は設けず、追従遅延で一時的に伸びる |
| 移動 | 既存の歩行・加減速を使用。NavMesh経路を0.35秒ごとに再計算。追いつく速度4.8m/s。10m以上離れ、到達可能な経路があるときだけ安全な目標面へ復帰 |
| 未接続 | 初期位置または解除地点を中心に半径3mの既存自由行動。地形端全域の安全性は地形検証と合わせて確認する |
| 遊び | ボール6個と撫でを維持。Fetch中は接続を待ち、接続中は新しいFetchを始めない。遊ぶときは外す |
| 複数人 | 同じ犬への先着要求をManager Ownerが受理。片手3匹を裁定。本人以外は解除できない。退出した接続者は解除し、犬のその場を自由行動の中心にする |
| おしゃれ | 犬種ごとの首輪と仮の6色を配置。種類の選択・保存・解放はまだ実装しない |

実装・検証手順は [実装記録](plans/2026-09-20-leash-walking.md)、課題は [IMP-DOG-002](development/issues/IMP-DOG-002-leash-walking.md)。既存の飾り・屋外休憩・追加トレーナー機能・性能目標は引き続きDES-DOG-001で詰める。

### 古民家とのつながり

世界観は緩くつなぐ。厳密な地理設定より同じ犬たちとの過ごし方が増えることを優先する。出発・帰還の導線、元の古民家インスタンスへ戻る方法、名前・飾りの持ち越し、接続・遊びの途中経過を引き継ぐ必要性、帰還時のリセット許容範囲は未解決。

**世界観として同じ犬であることと、実行中の状態がそのまま移動することは別。** ワールド間の状態引き継ぎは実装済みでも実現確定でもない。

## 5. 移植と同期の開発方針

最初は古民家の確認済み実装をコピーし、裏山に必要な動き・遊びに合わせて育てる。コピー元の固定タグ・完全長 SHA・日付・範囲 (スクリプト・Prefab・設定等)・既知の不具合や注意事項・裏山側の変更を残す。古民家側にも切り出し元のタグを付ける。手順は [IMP-DOG-001](development/issues/IMP-DOG-001-port-dog-system.md)。2026-09-20に固定タグから移植した。範囲・差分・依存は [移植記録](development/imports/kominka-dog-system.md)。2026-09-20にユーザーがPlayはひとまず良好、PCVRでは楽しかったと報告。移植機能すべての項目別合格・複数人検証とは区別する。

初めから汎用ライブラリ化を進めすぎない。同じ修正が両ワールドで繰り返される部分が見えたら共通化を検討する。ワールド展開とコード共通化は別判断。

画面は同期しない。古民家の犬の位置 (Owner 権威 + VRCObjectSync)、ボール・犬の状態、ローカルの撫で判定・リアクション・UI を移植の土台とし、実際のコピー範囲を棚卸しする。他人の撫で反応を同期表示する契約は追加していない。

**今回の実装では接続先・左右・解除地点を1つのManual同期Managerが管理する。** 接続要求は送信者を照合してManager Ownerが裁定し、犬自体のOwnerは接続で変更しない。移動は元の犬OwnerとVRCObjectSyncを使う。競合・退出・途中参加の実機検証は未了。

## 6. 完成条件と検証計画

以下は開発側の検証計画。未決定の数値・操作は設計後に観測手順を具体化する。現在は未達で、文書整理・Editor 画像だけで公開可能とはしない。

| # | 条件 | 確認方法 |
|---|---|---|
| 1 | 見晴らしから古民家の外観を識別できる | Editor 画像とユーザーの Play。低い視点も別途記録 |
| 2 | 散歩道・遊び場から切断面や空白を見せず範囲外へ落ちない | 確定したコースと境界を Editor / Play で確認 |
| 3 | 左右各 3 匹、合計 6 匹まで接続・解除して散歩できる | 確定した VR・デスクトップ・スマホ操作で上限・解除・再接続を確認 |
| 4 | 接続中・未接続の犬が決めた範囲で自然に動く | 停止・移動・段差・障害物・放置と帰還条件を確認 |
| 5 | 撫で・採用するおもちゃが動きリードと競合しない | 2 人以上で確定した Fetch・呼び出し等の優先順位を確認。屋外休憩は採用した動作のみ確認 |
| 6 | 複数人の接続状態が整合し、競合・退出・途中参加に対応する | 2 人以上の実機で各ケースを再現し、確定した同期契約と照合 |
| 7 | 対象端末での性能と公開範囲の根拠がある | PC・Quest 単体・iOS ごとに 6 匹散歩・複数人利用を測定。数値目標は事前に決める。未検証端末を対応済みとせず、目標変更はユーザー判断として記録 |
| 8 | 公開対象ビルドにコンパイルエラーがなく診断 high 0、見た目の統合確認が済む | 診断ツールと core-concept の代表シーン確認。採用した首輪・リードの見た目・選択方法も対象 |

## 7. 初期範囲の境界

| 対象 | 扱い |
|---|---|
| 古民家の内部・専用睡眠部屋 | 作らない |
| リードの絡まり・引っ張り合い | シミュレーションしない |
| 大量の木・購入完成シーンの丸ごと使用 | 要件にしない。必要な素材を選ぶ |
| 犬種・頭数の追加 | 初期の 6 匹から増やさない |
| 犬の先導など追加行動・新しい大規模ギミック | 初期の必須条件にしない。今回のリード接続・範囲内行動は初期範囲に含む |
| 共通ライブラリ化・VPM 化 | 最初は行わず、反復する共通修正が見えたら検討 |
| 大きなワールド間連携・状態共有 | 必要性が見えてから育てる。現時点の公開必須条件にはしない |
| Animal Wash との連携 | 将来のアイディア。古民家の付属作品とは確定していない |
| 冬・季節切替 | 初期範囲外。古民家の季節運用を決めた際に再検討 |
