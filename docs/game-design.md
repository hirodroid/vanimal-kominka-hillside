> **仕様の正本。** 実装で迷ったらここへ立ち返る。

## 1. 何のワールドか

古民家ドッグランの続編。同じ 6 匹と秋の裏山を散歩し、遠くの古民家を眺める VRChat ワールド (`core-concept.md` §1)。

| 項目 | 値 |
|---|---|
| ワールド名 | 古民家の裏山 (英語の公開名は未決定) |
| Unity プロジェクト名 | VAnimal_KominkaHillside |
| 対応環境 | PC + **スマホ対応を目指す** (確約ではない。初期の実機確認で成立性を判断し、公開対象を決める。成立しなければ PC のみで公開する判断もあり得る。Android / iOS / Quest 単体の公開範囲は別途決める) |
| ジャンル | 動物コミュニケーション / 癒し / 散歩 |
| 規模感 | コンパクトな山の環境。工期は固定納期にしない (Terrain 制作とスマホ検証で改めて判断) |

## 2. 体験の核

`core-concept.md` §2 の 3 点を仕様に落とす。3 点は**並列**で優劣を付けない (原本 §9)。
**「仕様への落とし込み」欄は試作 (VER-ENV-001) 用の仮案**。広さ・道の長さ・配置・犬の行動範囲は原本 §8 のとおり未決定で、試作の結果で §4 に確定値を書く。

| 体験の核 | 仕様への落とし込み |
|---|---|
| 山から古民家が見える | 展望・休憩場所から古民家の外観 (屋根・建物の形) が識別できる距離・角度に置く。内部は作らない |
| 犬と無理なく遊べる | 段差の少ない広場を 1 つ用意し、古民家の撫で・ボール・添い寝をそのまま動かす。犬の行動範囲は広場 + 散歩道を仮案とし、試作で決める |
| 小さな空間でも散歩した感じがする | 短い周回路 (原本 §5 の候補) を仮案とする。歩ける範囲の外に景観用の余白を置き、地形の切れ目を見せない |

## 3. プレイの流れ (仮案。順序・配置は試作で決める)

1. 入室: 山道の入口 (古民家から散歩に来たと感じる起点)
2. 散歩道を犬と歩く (数分)
3. 展望・休憩場所: 古民家を眺める、ベンチで休む (添い寝の場所は移植時に決める)
4. 小さな広場: ボール・撫でで遊ぶ
5. 周回して入口へ戻る / フレンドと話す / 退室

滞在の目安: 一周 5〜10 分 (仮。道の長さは未決定)。長居はフレンドとの会話と犬で持たせる (古民家と同じ)。

## 5. 同期の設計

**原則: 画面は同期しない。同期するのは「共通条件」と「結果」だけ。**
(詳細は `vrc-networking` スキル)

| 区分 | 内容 |
|------|------|
| ローカル処理 | 撫で判定・リアクション表示・UI (撫でた本人にだけ反応が出る。他人の撫でを同期して見せる契約は**無い**) |
| グローバル同期 | 犬の位置 (Owner 権威 + VRCObjectSync)、ボールの位置、犬の状態 — 古民家の同期設計をそのまま引き継ぐ |

新しい同期は設計しない。移植後に山特有の差分 (斜面での移動、範囲制限) が要る場合だけ Issue を切る。

## 6. 完成の条件

「これができたら公開できる」。後から足さない。

| # | 条件 | 観測の仕方 |
|---|---|---|
| 1 | 展望・休憩場所から古民家の建物が見える | Editor でカメラをレンダリングし、屋根と建物の形が識別できる画像を残す |
| 2 | 散歩道を一周して地形の切断面・空白・スカイボックスの床が見えない | 経路上に確認地点を置き (入口 / 各カーブ / 展望 / 広場。試作で決める)、各地点で谷側・山側・進行方向のスクリーンショットを残す。Play で一周した歩行者 (ユーザー) の申告も併記 |
| 3 | 6 匹が決めた行動範囲内に留まる | Play で (a) 5 分放置 (b) ボールを範囲の端へ投げる (c) 追従させて散歩道を一周、のいずれでも範囲外へ出ない |
| 4 | 撫で・ボール・添い寝が古民家と同じ操作で動く | 2 人で入る。撫で: 各自が撫でて各自に反応が出る (ローカル。相手の画面での一致は求めない)。ボール: 投げた位置と犬が取りに行く先が 2 人で一致する。添い寝: 指定の場所で犬が寝て、もう 1 人にも寝ている姿が見える |
| 5 | プレイヤーが柵・斜面の外へ落ちない | 谷側の柵に沿って歩き、落下・すり抜けが無い |
| 6 | 公開対象プラットフォームが決まっている | Android 実機で一周し犬と遊ぶ負荷を測り (数値目標は §4 で決める)、**成立すればスマホを公開対象に加え、成立しなければ PC のみで公開する**。どちらでも判断と根拠を §4 に追補する (スマホ成立は公開の必須条件ではない: 原本 §6) |
| 7 | PC ビルドでコンソールのエラー 0、診断ツール high 0 | `Tools/VRC World Tools/` |
| 8 | ビジュアル方針の統合確認 | `core-concept.md` §3 の代表シーンを Play / 実機で確認し、結果を記録 |

## 7. 入れないもの (スコープ外)

> **ここが最も重要。** 作りながら思いつく機能は必ず出てくるので、
> 「入れない」と決めたものを理由つきで残しておく。
> 品質を上げること ≠ 機能を足すこと。

### 却下 (設計判断。維持する)

| 入れないもの | 理由 |
|--------------|------|
| 古民家の内部・家具・室内ギミック | 遠景専用。内部探索は初期範囲に含めない (原本 §4〜5) |
| Autumn Valley 完成シーンの丸ごと使用 | 舞台は「古民家が見える位置・散歩道・休憩場所」を目的に設計する (原本 §4)。完成シーンに体験を合わせない。必要な木・岩・素材を選んで使うことは妨げない |
| イメージ図どおりの大量の遠景樹木 | 図は雰囲気の参考。実装要件にしない (原本 §5, §9)。スマホ負荷にも反する |
| 草木の密度で豪華に見せる | 眺め・道・犬・古民家とのつながりで作る (原本 §6)。「Terrain だから軽い」とも判断しない |
| 犬種・頭数の追加 | 古民家の 6 匹で確定。識別 (ボール径・吠え声) が飽和している |

### 保留 (初期範囲外。再検討する。トリガーを書く)

| 保留するもの | 再検討のトリガー |
|---|---|
| 専用の散歩 AI (犬が先導する等) | 初期制作の必須条件にしない (原本 §3)。試作 (VER-ENV-001) で既存の追従・行動では「散歩した感じ」が成立しないと分かったとき |
| 新しい大規模ギミック | 初期制作の必須条件にしない (原本 §3)。公開後に体験の不足が具体的に観測されたとき。説明を要する機能は続編の価値 (続きの場所) から外れやすいので慎重に |
| 犬ギミックの共通ライブラリ化・VPM 化 | 一式コピーして個別管理 (原本 §7)。古民家・裏山・OurUsualPark で同じ修正を繰り返すなど、具体的な必要が出たとき |
| 古民家ドッグランとの相互移動の導線 (ポータル) | 完成条件 1〜5 が通り、公開の形を決めるとき |
| ワールド跨ぎのデータ共有 (ポイント・購入権・名前) | 古民家側の CE / Persistence 方針と OurUsualPark の複数ワールド購入権検証の結果が出たとき |
| トレーナー「集まる」等の権限設定 | 犬ギミック移植 (IMP-DOG-001) で機能一覧を棚卸ししたとき |
| Quest 単体 / iOS の公開範囲 | Android スマホ実機の負荷確認 (完成条件 6) の結果が出たとき |
| 冬・季節切替 | 古民家側で季節運用を決めたとき |

**保留と却下を区別する。**
「間に合わないから後回し」は再検討対象、「設計判断として不適」はそのまま維持。
