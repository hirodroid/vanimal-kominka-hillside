# 古民家の裏山 — 企画・散歩仕様

> **仕様の正本。** 根拠は後から受領した [11 項目の散歩企画資料](reference/VAnimal_KominkaHillside_Walking_Addendum.md) を優先する (2026-09-19 ユーザー指定)。以前の企画原本・会話・試作と食い違う場合も後の資料に合わせる。旧原本は履歴として保存する。
> 意図・ビジュアル方針は [core-concept.md](core-concept.md)。
> 資料受領後にユーザーが具体化した決定は本書へ反映し、§8 に日付付きで残す。

## 1. 目的と位置づけ

「古民家の裏山」は、古民家ドッグランの同じ 6 匹と秋の山へ散歩に出かける別ワールド。訪問数・バズより、犬への愛着を別の場所・過ごし方へ広げる拡張エリアとする。古民家だけでも遊びが完結し、もっと楽しみたい人には散歩先がある関係を守る。

別ワールド化は Quest 単体・iOS の快適さを守り、容量・負荷を配分する制作方針。同一ワールドでは技術的に不可能と確認した結果ではない。古民家は遊ぶ・くつろぐ・一緒に寝る、裏山は連れ出す・歩く・景色を楽しむ。

**PC に加え Quest 単体・iOS 対応を目指す。** 対応確認済みではなく実機で検証する。軽量な景観と必要なギミック、既存の仕組み・素材の再利用で管理し、自作・Terrain だから軽いとは判断しない。固定納期は設けない。

## 2. 散歩体験の中心

気に入った犬と少し歩き、遊び、休む。リード操作や犬の制御の難しさを遊びの中心にせず、周囲で自然に動く犬と一緒に出かけた感覚を重視する。2026-09-20の追加相談で、犬自身が目的地へ行きたがり、寄り道・待機・散歩への誘い・犬同士の遊びをする自由さを重視する方針に具体化した。人が引っ張って初めてついてくる動きや、常に視界の前方へ配置することを目標にしない。

一緒に歩きたい犬のところへ行く → リードの先端を手に持って犬の首輪に取り付ける → 犬と山道を歩く → 止まって撫でる・おもちゃで遊ぶ → 再び歩く・休む・古民家へ戻る。

首輪へリードを取り付ける体験は 2026-09-20 にユーザーが決定。接続を成立させる細かな入力・判定、左右の割当方法、解除、端末別操作・UI は未確定。山から古民家を見る眺め、犬と遊べる場所、休める場所を必要な範囲で用意する。

## 3. 景観と現在の試作

秋の裏山を Unity Terrain で作る方向。木・草・岩は見た目と負荷を見て配置する。軽量化した古民家の外観を遠くに置き「あそこから来た」と感じられるようにする。不要な室内設備・ギミックは持ち込まない。購入済み秋山アセットと依存素材は必要に応じて採用し、完成シーンの丸ごと使用は前提にしない。

**コース長、周回か往復か、休憩場所の数、ワールド端の処理は未確定。** 後の資料を優先し、以前の配置の了承を最終仕様の固定とは扱わない。

現在の Terrain v4 は「門の前 → 一本の登り道 → 見晴らし → 上部の遊び場」。道 112.6 m、広場直径 24 m・標高 19 m は試作値に限る。2026-09-20に実物6匹を門前へ導入し、地形のダミーは非表示にした。画像・視点検討は [地形計画 §12・13](plans/2026-09-19-terrain-prototype.md) に記録。見た目の了承と Play・実機負荷の合格は区別する。木の追加も検討段階。

### 目的地を持つ自由な散歩 (2026-09-20 合意、未実装)

**犬は道を知っていて先へ行きたがるが、人の寄り道にも付き合う。** 自分がつないでいる犬に目的地を伝え、犬は道沿いの通過点を目安に自由に動く。多少の遠回りや予想外の寄り道は楽しさとして許容する。旧案の「移動方向から往路・復路を自動推定して視界の前へ出す」ことを主方式にしない。

#### 目的地と指示の対象

- メニューで「広場へ行こう」「古民家側へ帰ろう」を選び、自分がリードでつないでいる犬に伝える。古民家側は本ワールドの散歩入口を指し、遠景の古民家へ歩く処理やワールド移動とは別。
- 指示先は自分の接続犬で、目的地は犬ごとに保持する。他の人の犬や未接続犬を一括変更しない。犬の動きは全員に共通で見える。犬1匹ずつを選ぶ追加UIは今回の必須にしない。
- 初期の目的地候補は広場と散歩入口。今後は草むら・休憩場所などを目的地と通過点の追加で広げられる構成にする。追加場所の制作自体は今回の範囲外。
- 「犬が行きたい目的地」と「人から離れすぎないために今向かう場所」を分ける。首や手の回転、一時的な後ずさり、道外への寄り道だけで目的地を変えない。

#### 道と通過点 (ウェイポイント)

制作側で目的地に至る通過点と接続関係を用意する。例は「入口 ↔ カーブ ↔ 坂の途中 ↔ 見晴らし ↔ 広場」。点の名前・数・間隔は仮で、確定配置ではない。往復や複数目的地で同じ区間を共用できるようにする。

1. どこから出発しても、近くにあり、実際に到達でき、目的地までつながる通過点から経路へ入る。目的地までの直線距離だけで点を選び、斜面や折り返しを横切らせない。
2. 入った後は接続関係を目的地側へたどり、今いる区間と次の点を覚える。毎回の最近傍選択で前後に振動させない。曲がり角を大きく飛ばさず、通過点間も歩行可能な範囲を使う。
3. 通過点は大まかな進路の目安で、全犬が点を正確に踏む隊列にはしない。周辺の安全な場所への寄り道や、犬ごとの立ち位置・タイミングの違いを許す。
4. 道外では人の近くで自由に動き、離れ続けない。道へ戻ったら直前の区間と到達可能性を考慮して再開する。使える経路がなければ無理に目的地へ直進せず、安全な近傍で待つ・人についていく。

多少の遠回りは許容するが、到達不能な場所への固執、崖や範囲外への進入、通過点間の往復ループ、人を置き去りにする移動は不具合として扱う。

#### 行動

| 場面 | 目指す振る舞い |
|---|---|
| 接続・散歩開始 | 有効な目的地に向かって自分から歩き出し、「行こうよ」という様子を見せる。人がリードを引くことを開始条件にしない |
| 散歩中 | 道の先へ進む・道脇へ寄る・立ち止まるなどを混ぜる。人に常時正確に追従することや、全犬を常時視界内に収めることを要求しない |
| 人がついてこない | 手を基準とする行動範囲を目安に待つ。長く止まったら戻って近寄る・吠えるなどで散歩へ誘う。反応の種類・待ち時間・頻度は試作で調整し、会話中ずっと催促し続けない |
| 複数匹 | 2匹・3匹での散歩中に、たまに犬同士で短く遊んでから散歩へ戻る。6匹でも全犬が同じ時刻・場所で同じ行動を始めない。最初の試作対象は同じ人につながれた犬同士とし、相手選択・具体動作・中断条件は設計する |
| 人が別方向へ歩く | 必要に応じて先行・寄り道・遊びを切り上げ、人の近くへ戻る。目的地は維持し、道へ復帰すれば目的地側への散歩を再開する |
| 到着 | 目的地付近の接続中の範囲で自由に過ごす。自動で反対側を目的地にせず、帰りは人が指定する。到着後も同じ目的地へ出発を催促し続けない |

移動方向の判定は補助とし、視線や手の向きに即応させない。最近の実移動を約1秒ごとに見る案から試すが、周期は確定値ではない。目的地・行動の判断周期と、歩行の描画・障害物や離れすぎへの対処の更新頻度は分ける。

接続/解除・伸びる紐・既存の歩行や撫で・ボール遊びの良さを維持する。犬同士の遊びは接続中の散歩行動として追加し、接続中に新しいFetchを開始しない初回実装の契約は変えない。

| 開始・再接続 | 未指定時の初期目的地、追加でつないだ犬への適用、解除・再接続・接続者交代・退出時の目的地保持/初期化をDES-DOG-001で決める。どこで接続しても即座に広場へ向かうとは固定しない |
| 経路 | 通過点の配置、入口候補の選び方、到着判定、道外との切替・復帰条件、経路不成立時の復旧をIMP-DOG-003で試作する |
| 自由行動 | 先行距離、寄り道範囲、誘いの頻度、じゃれ合いの動作・相手選択・終了/中断条件を試作する。集合・撫で等との優先順位はDES-DOG-001で整理する |

### 古民家とのつながり

世界観は緩くつなぐ。厳密な地理設定より同じ犬たちとの過ごし方が増えることを優先する。出発・帰還の導線、元の古民家インスタンスへ戻る方法、名前・飾りの持ち越し、接続・遊びの途中経過を引き継ぐ必要性、帰還時のリセット許容範囲は未解決。

**世界観として同じ犬であることと、実行中の状態がそのまま移動することは別。** ワールド間の状態引き継ぎは実装済みでも実現確定でもない。

## 5. 移植と同期の開発方針

最初は古民家の確認済み実装をコピーし、裏山に必要な動き・遊びに合わせて育てる。コピー元の固定タグ・完全長 SHA・日付・範囲 (スクリプト・Prefab・設定等)・既知の不具合や注意事項・裏山側の変更を残す。古民家側にも切り出し元のタグを付ける。手順は [IMP-DOG-001](development/issues/IMP-DOG-001-port-dog-system.md)。2026-09-20に固定タグから移植した。範囲・差分・依存は [移植記録](development/imports/kominka-dog-system.md)。2026-09-20にユーザーがPlayはひとまず良好、PCVRでは楽しかったと報告。移植機能すべての項目別合格・複数人検証とは区別する。

初めから汎用ライブラリ化を進めすぎない。同じ修正が両ワールドで繰り返される部分が見えたら共通化を検討する。ワールド展開とコード共通化は別判断。

画面は同期しない。古民家の犬の位置 (Owner 権威 + VRCObjectSync)、ボール・犬の状態、ローカルの撫で判定・リアクション・UI を移植の土台とし、実際のコピー範囲を棚卸しする。他人の撫で反応を同期表示する契約は追加していない。

**今回の実装では接続先・左右・解除地点を1つのManual同期Managerが管理する。** 接続要求は送信者を照合してManager Ownerが裁定し、犬自体のOwnerは接続で変更しない。移動は元の犬OwnerとVRCObjectSyncを使う。競合・退出・途中参加の実機検証は未了。

## 6. 完成条件と検証計画

以下は開発側の検証計画。未決定の数値・操作は設計後に観測手順を具体化する。現在は未達で、文書整理・Editor 画像だけで公開可能とはしない。

| # | 条件 | 確認方法 |

| 10 | 犬同士の短い遊びと、自分の接続犬への目的地指定が成立する | 2匹・3匹で遊びから散歩への復帰、6匹で集中・反復を確認。2人が別目的地を指定し、他人の犬への非干渉・途中参加・退出時の確定契約を実機で確認 |
