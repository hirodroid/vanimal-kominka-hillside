# IMP-DOG-019 同じ犬のボールとフリスビーはどちらか片方しか使えないようにする

[体験会の記録](../../plans/2026-09-26-group-playtest.md) (2026-09-26、15 人) でユーザーが報告: **ボールとフリスビーが一緒に置いてあるので、同時に使うと犬がどっちに行くか分からなくなる。**

決定: 2026-09-26 夜 (ユーザー) 「ボールとディスクは同時に使えないようにしたい。同じ犬に対してはどっちかしか出ないようにしたい」。→ 置き場を分けるのではなく、**同じ犬のボールとディスクを排他にする**。

## 仕様

- **使用中の定義** (犬 i、既存の同期状態から各端末がローカルに導出。新しい同期変数は増やさない)
  - ボール使用中 = 誰かが持っている (`IsHeldNow`) / 犬が追跡・回収中 (`!fetchers[i].IsIdle`) / かけっこのボール (`RaceBall == i`)
  - ディスク使用中 = 誰かが持っている / 飛行中 (`IsFlying`) / 犬が取りに動いている (`IsEngaged`)
- **手元メニュー**: ディスクを呼ぶときに同じ犬のボールが使用中なら拒否、逆も同じ。文言は既存の「犬が遊んでいます」(行は「遊び中」)
- **現地で拾う経路**: 相手が使用中の間、その犬のもう一方のおもちゃは `pickupable = false` (0.25 秒ごとに評価)。誰かが持っているものには触らず、`Drop` も呼ばない。相手の使用が終わり、そのおもちゃを普段管理している側 (Fetch / Catch) が休止状態に戻ってから `true` に戻す
- 置き場は変えない (ボール 3×2、ディスクはその 2.2 m 奥のまま)

## 実装 (2026-09-26)

- [KH_ToyRecall.cs](../../../Assets/KominkaHillside/Scripts/KH_ToyRecall.cs): `_GateToy` に相手側の使用中判定、`ApplyExclusive` で 6 匹分の `pickupable` をローカルに切り替え。変更はこのファイルだけ (文言 JSON・メニューは変更なし)
- Verify: `Walking/5 Verify` 490 項目 PASS (KH_ToyRecall の 6 匹配線は既存項目)。C# 0 / U# 0
- 独立レビュー (Codex): High 1 件 (かけっこの後にボールが拾えなくなる) を修正。Medium 2 件は制限として記録 (下)

## 既知の制限

1. 拾える/拾えないの切り替えは 0.25 秒ごと。`KH_FrisbeeCatch` と Fetch 側が自分の `pickupable` を書き直すので、最大 0.25 秒の隙間がある
2. 拒否された投げ (場外など) の飛行中は、投げた本人以外の画面ではボールが使える (犬はそのディスクを追わないので許容)
3. 犬が口にくわえて待っている間に人が取れる規則は、ディスクの使用中と重なった場合は犬が Idle に戻るまで待つ (public な判定が無い)

## 完了条件

- [ ] 1 人で: ボール追跡中に [ディスク] が拒否され現地でも拾えない、逆も同じ、持っている手から落ちない、他の犬に影響しない
- [ ] 2 人で: かけっこ・集合の後に各犬のボールが拾える、相手が持っているおもちゃを奪わない
- [x] Verify とコンパイルが通る (2026-09-26)
