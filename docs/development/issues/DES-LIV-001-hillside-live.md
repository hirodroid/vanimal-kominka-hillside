# DES-LIV-001 裏山のライブとワールド別の購入・利用を設計する

2026-10-12 ユーザー訂正: **ワールド共通の課金商品はトレーナーだけ。他の課金商品はすべてワールドごとに別購入。** 裏山の課金ライブは、古民家ドッグランで購入済みの人も裏山で別途購入する。古民家の購入権を引き継いで再生する要件は撤回する。今回は文書の訂正で、商品 ID・販売設定・コード・シーンは未変更。

履歴 (2026-09-20、購入権の方針は上記で置き換え): 裏山の場所に合う専用パーティクルライブを制作し、Candy Stepとハロウィンは古民家の購入者が裏山でも再生できる案だった。[当時の報告](../../plans/2026-09-20-pcvr-feedback.md)。演目・素材の流用と購入権の共有は別で扱う。

2026-09-23: 何を作るかという演目企画 (ハロウィン・Candy Step・ライブパック・散歩道の犬パレード) は [DES-LIV-002](DES-LIV-002-live-lineup-and-parade.md) に分離する。本 Issue は購入者の利用と開催・再生・競合・復帰の設計を担当し、下記の観覧・演出・公開範囲は演目企画と連携して決める。

決定: 2026-09-26 裏山専用曲 ([hillside-dusk](../../../../../vrc-live-generator/docs/v2/kominka-hillside/concepts/hillside-dusk/001/README.md)) はポイント 30pt の単品、夜で終わる (同期の暗転を使う)。犬の扱いは古民家の通常ライブ (ライブパック) と同じ仕様。リード接続中の犬はそのまま (遊んでいる・呼ばれている犬と同じく対象外。同日決定)。

調査: 2026-09-26 [配線計画](../../plans/2026-09-26-hillside-live-wiring.md)。再生・途中参加・開催許可・60 秒待機は移植済みの古民家の器 (`KD_LiveSystem` / `KD_LiveAccess`、未改変) をそのまま使える。夜は `KD_LiveNight` を置かず、同期時計から導く暗さを `KH_NightMode.liveDarkness` へ渡して「強い方を採る」で合成する。リード接続中・呼ばれている・Fetch 中の犬は犬の優先順位で観客より先に処理されるので変更なしで対象外。集合との排他も既存。ライブ中の新しいフリスビーだけ止める条件が無く、1 行足す。
調査: 2026-09-26 観覧場所の案は上の広場の中心 (72, 19, 127)、ステージと犬の集合地点は +Z を谷と古民家へ向ける (Y 190°)。座った目線で古民家が見えるか・暗くなり方 (3 秒か曲に沿うか)・観客へのリード接続の可否・終了後の犬の居場所は未決定 (計画書 §3)。

## 完了条件

- [ ] 裏山の対象演目・商品/Listingの対応・権利判定の正本を特定し、古民家の課金ライブとは購入権を分離する
- [ ] 裏山で購入済み/未購入/権利読込中/失効時の扱いを設計し、実機で検証する手順を記録
- [ ] 古民家の課金ライブだけを購入した人は裏山では未所持となり、裏山用の購入入口が表示される。裏山の商品を購入すると対象演目を開催でき、裏山での所持済み商品を重複購入させない。トレーナーの共通購入権は維持する
- [ ] 専用演目の観覧場所・視線・音量/演出軽減・負荷予算を決める
- [ ] 再生権限と途中参加、犬を使う演出の有無、散歩/Fetch/集合との競合・終了復帰を決める
- [ ] 採用する初期公開範囲と実装Issueを決める

単に元コードがコピーされていることは、再生機能や権利確認が配線済みである根拠にならない。現行の商品設定を調べ、裏山専用の商品/Listingへの対応を整理する。古民家側の既存商品は変更しない。価格・演目構成・実際の販売設定は別工程で具体化する。一般的な犬の名前・飾りの持ち越しはDES-WLD-001と分けて判断する。

決定: 2026-10-02 (ユーザー決定) ライブは初期公開に入れる。どの演目までを初期公開に含めるか (専用 1 曲だけか、Candy Step・ハロウィンも含むか) は未確認。課金商品の購入権は 2026-10-12 のワールド別購入の方針を適用する。

決定: 2026-10-03 (ユーザー決定)「ライブは最後に作るので保留。」初期公開の範囲 (10-02 決定) には残したまま、制作順を最後にする。どの演目を初期公開に含めるかは保留中で、未回答 (答えたのではなく先送り)。
