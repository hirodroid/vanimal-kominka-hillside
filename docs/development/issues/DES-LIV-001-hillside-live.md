# DES-LIV-001 裏山のライブと既存購入者の利用を設計する

2026-09-20ユーザー方針: 裏山の場所に合う専用パーティクルライブを制作する。特にCandy Stepとハロウィンの有料ライブは、古民家で購入済みの人が裏山でも再生できるようにする。[報告](../../plans/2026-09-20-pcvr-feedback.md)。今回は要件の記録で、ライブ・権利連携とも未実装。

2026-09-23: 何を作るかという演目企画 (ハロウィン・Candy Step・ライブパック・散歩道の犬パレード) は [DES-LIV-002](DES-LIV-002-live-lineup-and-parade.md) に分離する。本 Issue は購入者の利用と開催・再生・競合・復帰の設計を担当し、下記の観覧・演出・公開範囲は演目企画と連携して決める。

決定: 2026-09-26 裏山専用曲 ([hillside-dusk](../../../../../vrc-live-generator/docs/v2/kominka-hillside/concepts/hillside-dusk/001/README.md)) はポイント 30pt の単品、夜で終わる (同期の暗転を使う)。犬の扱いは古民家の通常ライブ (ライブパック) と同じ仕様。リード接続中の犬はそのまま (遊んでいる・呼ばれている犬と同じく対象外。同日決定)。

調査: 2026-09-26 [配線計画](../../plans/2026-09-26-hillside-live-wiring.md)。再生・途中参加・開催許可・60 秒待機は移植済みの古民家の器 (`KD_LiveSystem` / `KD_LiveAccess`、未改変) をそのまま使える。夜は `KD_LiveNight` を置かず、同期時計から導く暗さを `KH_NightMode.liveDarkness` へ渡して「強い方を採る」で合成する。リード接続中・呼ばれている・Fetch 中の犬は犬の優先順位で観客より先に処理されるので変更なしで対象外。集合との排他も既存。ライブ中の新しいフリスビーだけ止める条件が無く、1 行足す。
調査: 2026-09-26 観覧場所の案は上の広場の中心 (72, 19, 127)、ステージと犬の集合地点は +Z を谷と古民家へ向ける (Y 190°)。座った目線で古民家が見えるか・暗くなり方 (3 秒か曲に沿うか)・観客へのリード接続の可否・終了後の犬の居場所は未決定 (計画書 §3)。

## 完了条件

- [ ] 古民家側の対象演目・商品/Listingの対応・権利判定の正本を特定
- [ ] 購入済み/未購入/権利読込中/失効時の扱いとワールド間利用の実現性を確認し、実機で検証する手順を記録
- [ ] 購入者が再購入を求められず対象演目を再生できる設計にする。通常の保存値コピーを購入権利の代わりにしない
- [ ] 専用演目の観覧場所・視線・音量/演出軽減・負荷予算を決める
- [ ] 再生権限と途中参加、犬を使う演出の有無、散歩/Fetch/集合との競合・終了復帰を決める
- [ ] 採用する初期公開範囲と実装Issueを決める

単に元コードがコピーされていることは、再生機能や権利確認が配線済みである根拠にならない。既存商品を変更・再発行する前提を置かず、まず現在の設定を調べる。一般的な犬の名前・飾りの持ち越しはDES-WLD-001と分けて判断する。

決定: 2026-10-02 (ユーザー決定) ライブは初期公開に入れる。どの演目までを初期公開に含めるか (配線済みの専用 1 曲だけか、既存購入者の Candy Step・ハロウィン再生までか) は未確認。
