# BUG-DOG-012 泳いだまま浅瀬へ上がる途中に足が河床へ沈む (水遊び・Fetch の脚)

## 発端

2026-10-12、IMP-DOG-053 (リードで川へ) の限定ハーネス run 20261012-030041 の LR-swim-Corgi が minLift −0.155 m で落ちた。原因: 浮きの高さ (水面 + swimClear − Ms − 沈み) に床が無く、泳ぎは 0.6 M を 0.5 s 下回るか乾くまで終わらないため、泳いだまま岸へ上がる犬の足が水深 ≈ 0.02 m の浅瀬で喫水 (コーギー 0.175 m) ぶん河床へ沈む (−0.155 = 0.02 − 0.175)。リードの川の脚には `LeashRiverSwimFloor` (根を河床 − 0.03 m より下へ置かない) を入れて修正し、回し直し run 20261012-031139 で PASS。

**自由行動の水遊びと川の Fetch の脚は同じ式のまま** (担当の報告)。同じ沈みが起き得るが、未再現・未修正。

- [ ] 最小の修正 (床か泳ぎ終わりの判定) を入れ、同じケースで沈みが消えた。泳ぎの旗と姿勢の見え方が変わらない (床を入れ、Course/132 で修正後の最小 −0.030。Play の 78s は未実施。旗への直接代入は足していないが、床で保持値が変わるので `_swimSettled` の収束時期は変わり得る。高さは柴で最大 0.061 m 変わる)
- [ ] 既存の水遊びの群の期待 (82b T-swimresidue-* など) が変わらない (読みで確認。回していない)

## 記録

2026-10-12: 起票のみ (053 の担当の報告から)。

2026-10-12 (実装担当、コードと文書のみ。Unity・Play は統括):
- 再現 (シーンの値から式で。Course/132 が同じ関数で確かめる): 泳ぎの旗が立ったままの根 − 河床 = 水深 − 喫水。水深 0.02 m でコーギー −0.155 (053 の実測と一致)、ポメ −0.086、ダックス −0.165、柴 −0.286 (運搬中は 0.043 浅い)。泳ぎの終わりの深さでも −0.038 / −0.033 / −0.047 / −0.091 と床 (−0.03) の下。ラブ・サモエドは泳がない。
- 製品: `KD_DogWanderController.WaterSwimHeight` の泳ぎの枝で根を `_WaterSwimFloorY` (= `_WaterBedAt` − `WaterSwimFloorDepth` 0.03) より下へ置かない。河床は `WDepth` と同じ出どころ (水遊び場の格子、無ければ川全体)。旗・姿勢・`_swimSettled` への直接代入は足していない (ただし床で保持値が変わるので、settled の収束時期は変わり得る)。地面へ戻る補間には掛けない (補間は物理の地面へ収束する。地面が低ければ下がる)。間引きの脚のフレーム (河床を読まない) は、浮いている時は全セルが `_wrecFloatLow` = max(終わりの深さ, 喫水 − 0.03) 以上の深さの時だけ (`WaterLegsSwimOk`)。リードの川の脚の `LeashRiverSwimFloor` 一式は外して同じ床に一本化。式は `_WaterSwimRootY` を `WaterSwimHeight` からも呼ぶ (写しを 1 つにした)。
- 検査: Course/132 `Probe Swim Exit Floor` (新規)、78 に `W-swim-exit` (単独は 78s)、リードの検査 (`LrFloatY` / `LrObserve`) を実行時の関数に替えた。
- 見え方: 正規の泳ぎでも喫水 − 0.03 より浅い所では根が持ち上がる (柴 0.215〜0.276 m で最大 0.061 m、ダックス 0.017、コーギー 0.008、ポメ 0.003)。
- 自前のビルド確認: scratchpad の一時 csproj で実行側・Editor 側とも 0 エラー (U# のコンパイルは未確認)。

2026-10-12 (統括の検査と Codex 独立レビュー、高なし):
- 検査の記録を分ける。053 のリードの床は、共通化の前の版で 78m run 20261012-031139 が PASS。012 (共通化した版) は、コンパイル C#/U# 0 と Course/132 DONE findings 0 (コーギー 172 経路中 171 が修正前は河床 − 0.03 の下、最悪 −0.160 → 修正後の最小 −0.030)。共通化の後の Play は未実施。
- 中 (反映): W-swim-exit は修正前でも PASS できた。成立は「床なし < −0.03」、失敗は「根 < −0.04」で、床なし −0.035 でも成立・PASS になり、floorFrames は入水中から数えていた。→ 滞在を終えた後 (出水中) に、床なしの式が ≤ −0.06 (合格線 −0.04 を明確に下回る) の泳ぎのフレームを観測したことを成立の条件にした (無ければ NOT_EXERCISED)。出水中の「床が要った」と「床を実際に適用した (根が河床 − 0.03)」を分けて数える。
- 中 (反映): 救済の瞬間移動 (段階 3) の上陸でも合格できた。→ `recoverStage < 3` と、向かっていた出口の点から 1 m 以内まで来たことを要求。
- 低 (反映): 設計書の `_swimSettled` と補間の書き方を条件付きに直した。
- 別件の候補 (今回の対象外): `KD_DogPack.cs` の LateUpdate (394 付近) は、浮いた犬を高さを保ったまま横へ押す。床を掛けた後に河床が高い側へ押されると、次の更新まで床を下回り得る。複数匹の押し合いは 78s では保証しない。
- ハーネスの結論: 修正後に 78s → 既存 78l の LR 3 ケース (78m 全 7 と 82l は今回は不要)。
