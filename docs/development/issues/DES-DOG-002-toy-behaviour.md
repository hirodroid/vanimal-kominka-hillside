# DES-DOG-002 動きの異なるおもちゃを設計する

2026-09-20ユーザー要望。裏山ではおもちゃ遊びを充実させ、外見変更に加えて挙動が異なる種類を用意する。フリスビーは候補で、採用種類・数は未確定。[報告](../../plans/2026-09-20-pcvr-feedback.md)。

同日の追加ラフ案を [IMP-DOG-005 フリスビー飛行と基本ジャンプキャッチの試作](IMP-DOG-005-frisbee-jump-catch.md) として起票。平地・1匹・1種類の前方ジャンプから始め、飛行予測に犬の口を合わせる。フリップやドッグキャッチへの拡張は基本動作の評価後とする。おもちゃ全体の選択・同時数・犬の割当・リードとの競合・公開範囲は引き続き本Issueで扱う。

## 決まったこと (IMP-DOG-005 の試作から、2026-09-21)

- **フリスビーは「おもちゃの一覧に増えた、動きの違う 1 種類」**。ボール系 (まり・たい焼きなど見た目違い) とディスク系 (柄違い) の見た目のバリエーションは、それぞれの種類の中の話として後で足す。
- **犬ごとに 1 枚、色はその犬の識別色**。メニュー「おもちゃ」は 6 犬の行のまま、各行に「ボール」「フリスビー」。まだ無い犬は「まだ」。回収は `KH_ToyRecall` の「犬番号 + 種類」。
- **投げ方は照準モード** (軌道プレビュー + トリガー、強さは右スティック / ホイール)。物理投げは上級候補として `aimLaunch=false` に残す。
- **遊び場は広場** (平地前提の計画器)。持っている間だけ薄い輪、場外は灰色 + × + 一言。斜面・見晴らしへの拡張は別途判断し、1匹でのバリエーション試作の前提にしない。
- **取り合い**: 位置取り (Ready) は他の遊びを奪わない。追走〜持ち帰り中は Fetch・リード・集合・撫でを拒み、受理済みのリード・集合が勝つ。
- 残り: 他 5 匹への展開 (犬ごとの姿勢クリップ制作が必要)、ディスク複数、ダッシュ (並走) とフリップ、Quest/iOS、2 人。記録は [試作記録](../../plans/2026-09-20-frisbee-prototype.md)。

決定: 2026-09-28 DES-DOG-005 (IMP-DOG-023 M4) で置換 — 「遊び場は広場」と持っている間の輪: 遊び場はどこでも (その場の地面で跳ぶ・拾う・断る)、輪は削除、場外の灰色 + × + 一言は「犬が行けない所」の表示に変わった ([設計書](../../plans/2026-09-28-frisbee-anywhere.md))

## 採用結果 (IMP-DOG-008、2026-09-22)

- **通常版は「先回り型 + 動きの層」に作り替えた**: 投げた瞬間に取る点を決め、8 m/s で先回り / 追いながら勢いのまま跳ぶ (正面から来る球も)、待つのは高いロブだけ、跳べない低い球は立って取る、旋回は走行 240°/s でその場で向きを変えない。ユーザー評価「かなり良かった」「いい感じ」。
- **6 プリセット全部採用**: 待つ場所 (前 8 m / 横 / 遠く / 隣 = 並走)、ひねり (取り方)、横曲がり (投げ方、右へ約 1.7 m)。「ユーザーが選ぶ項目 / 自動で変わる動作」の切り分けと操作権は [DES-UI-002](DES-UI-002-frisbee-settings.md)。開発用の切替 (ヘッダの「試作」) は当面残す。
- **制限**: 購入犬の胴体追従 Constraint はフリスビーの犬で無効化する (ラブで硬さの指摘なし)。ハーネスは持ち主なし・VR 照準なし・1 人の範囲。複数人 (投げ手 ≠ Owner・途中参加)・Quest/iOS は未検証で、IMP-DOG-005 の項目として継続。
- **試さなかった候補**: フリップ、風、ドッグキャッチ (2 案: 手渡しキャッチ / 犬を受け止める)。必要になったら本 Issue で再検討。
- **6 匹展開**: [IMP-DOG-012](IMP-DOG-012-frisbee-six-dogs.md) (犬種別クリップ・facts、胴体固定、負荷、Catch の分割、犬種別ハーネス)。

## 遊ぶ犬の割当と複数ディスク (IMP-DOG-012、2026-09-24 開発側の決定。ユーザー確認待ち)

- **ディスクは犬別 6 枚** (ボールと同じ。色はその犬の識別色)。**各犬は自分のディスクだけを追う** — 誰のディスクをどの犬が追うかは色で決まり、別の犬のディスクは追わない。同じ人が 2 枚以上を続けて投げても犬ごとに独立して動く。
- **Owner 分裂** (犬の Owner と投げ手が別) は 1 匹版の仕組み (投げ手のクライアントから要求 → 犬の Owner が実行) を 6 匹に。同期変数は増やしていない。
- 6 プリセットの切替 (あそぶタブのトレーナー群) は「ディスクを持つ犬全部」に同じ値。犬ごとの設定は [DES-UI-002](DES-UI-002-frisbee-settings.md)。
- リード・集合・撫で・Fetch との取り合いは 1 匹版の規則 (上の「取り合い」) を犬ごとに適用する。
- 実装・検証記録は [6 匹展開の記録](../../plans/2026-09-24-frisbee-six-dogs.md)。PCVR (複数ディスクの同時・Owner 分裂) は未確認。
- 2026-09-26 体験会 (15 人) の報告: 色だけでは誰のディスクか分からない → 犬の顔を印字する [IMP-DOG-018](IMP-DOG-018-frisbee-dog-face.md)。iOS で色が全部同じ → [BUG-DOG-005](BUG-DOG-005-ios-disc-colors.md)。ボールと同じ場所に置いてあり同時に使うと犬の行き先が分からない → [IMP-DOG-019](IMP-DOG-019-ball-and-disc-placement.md)。「各犬は自分のディスクだけを追う」の決定自体は変えていない。

## 次の順序 (2026-09-21 追加合意)

1. **通常版の体験の仕上げはひとまずOK**。ユーザーのVR評価を受け、IMP-DOG-005を比較基準にする。項目別・2人などの未確認項目は同Issueに残す。
2. **同じラブ1匹で取り方・飛び方を一通り試す**。[IMP-DOG-008](IMP-DOG-008-frisbee-variations.md) で外から走り込むキャッチを最初に扱い、フリップなどの取り方と飛び方の変化を比較する。候補ごとに採否を決める。
3. **1匹で通常版と採用バリエーションがOKになってから6匹へ展開する**。犬種別の姿勢・口の位置などの調整は、その時点で別Issueにする。公開向けの未検証事項も引き継ぐ。

「外から走ってきてパッと取る」は通常版の必須修正ではなく、IMP-DOG-008の最初の試作目標。見た目の柄違い・複数ディスク・斜面対応は、上記の試作と分けて採否を決める。

## 2026-09-23 ユーザー決定: ボールの柄違いは古民家と同じ商品を採用 (DES-UI-003 より)

[DES-UI-003](DES-UI-003-menu-scope-and-polish.md) の 2026-09-23 ユーザー回答で、**おもちゃの柄違いは古民家と同じ商品をそのまま採用**と決まった。商品・価格はそのまま持ってくるが、裏山での持たせ方・置き場所は本Issueで決める。

**商品 (古民家と同じ)**

| 商品 | productKey | 価格 |
|---|---|---|
| 基本ボール | toy.basic_ball | 0pt (無料・初期品) |
| テニスボール | toy.tennis_ball | 10pt |
| ドーナツ | toy.donut | 20pt |
| 骨 | toy.bone | 30pt |
| 布ボール | toy.cloth_ball | 40pt |
| 手毬 | toy.temari_claude | 50pt |

別枠でぬいぐるみ3点 (肉球クッション / たい焼き / えび天) が **CE 200C の1セット** (`KominkaDogRun: Assets/KominkaDogRun/Editor/KD_ProductDefinitions.cs:50-60`)。ポイント価格は古民家と同じにする ([game-design §4](../../game-design.md))。

**古民家の作り (読取調査、HEAD 44505384)**

- 同じ fetch ボールの**メッシュ差し替え**。ボール本体 (SphereCollider + VRCPickup + VRCObjectSync) は1犬1個のままで、子ノード KD_ToyMesh_{key} を1つだけ SetActive する。当たり判定・物理は共通で、挙動差のある玩具は却下済み (`KominkaDogRun: Assets/KominkaDogRun/Scripts/KD_ToyBox.cs:39-42`、`KominkaDogRun: docs/development/issues/review/IMP-FET-009-toy-box.md:367`)。
- 選択は**全員共通の1つ**で、同期は `[UdonSynced] string` **1本**。見た目は同期変数からのみ作り、Late Joiner の Persistence が既存プレイヤーのボールを書き換えない設計 (`KominkaDogRun: Assets/KominkaDogRun/Scripts/KD_ToyBox.cs:47-51, 83-95, 16-32`)。
- **選択と購入は物理の棚 (KD_ShopShelf / KD_ShopItem) の実物タッチ**。メニューのおもちゃタブは犬6行 × [手元へ] だけで、「選択もタブへ」は共有物の切り替えだからと却下済み (`KominkaDogRun: docs/development/design/hand-menu.md:37, 192-244, 739, 744`)。
- **ディスク (フリスビー) の柄違いは古民家に前例なし** (`KominkaDogRun: docs/business-strategy.md:541` に将来候補として載るだけ)。

**本Issueで決めること (裏山)**

- **犬ごとの選択にするか、全員共通1選択にするか**。裏山は犬ごとにボールとディスクを持つため、同期変数が1本 → 6本になる帯域と Late Joiner の復元をどう設計するかが判断材料。
- **棚を門付近 (おじいさんの隣) に置くか**。古民家と同じ実物タッチを使うなら置き場所が要る。
- **ディスクの柄違いは前例がないため後回し**。ボール側の採用結果を見てから採否を決める。
- ポイント価格は古民家と同じ (変更する場合はここで理由を書く)。
