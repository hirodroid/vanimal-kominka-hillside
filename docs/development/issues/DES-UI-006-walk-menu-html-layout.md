# DES-UI-006 散歩を中心にメニューを整理し HTML で構成案を作る

## 現在地 (2026-10-15)

さんぽタブの2列化は2026-10-03に本番へ反映済みで、下記のPlay・実機確認が残る。追加で、2026-10-14の[かざり・移動・人一覧のHTML案](../../plans/mock/2026-10-14-menu-subtabs-and-people.html)を本Issueへ紐付けた。追加案の採用・Unity反映完了は確認できていない。設計と実装範囲の整理が残るため、Issue全体を `review` から `wip` に戻す。同日、現行実装との差分を整理し推奨案を作った ([差分整理と推奨案](../../plans/2026-10-15-menu-subtabs-and-people.md)、ユーザー承認待ち)。詳細は末尾の追記を参照。

## 依頼と目的

2026-10-02 ユーザー依頼。手元メニュー、特に散歩のところがごちゃついていて分かりにくい。メニューの構成を見直し、まず HTML で構成案を作って確認したい。

現在の実装を起点に、散歩を始める・行き先を変える・終えるときに必要な操作が見つかる構成を検討する。今回は構成設計と HTML モックを対象とし、Unity の画面変更は採用案を決めた後の作業とする。

## 検討と成果物

1. 現在のメニューを確認し、タブ・項目・犬の一覧・接続操作・目的地選択・状態表示を棚卸しする。過去のモックだけから現在の構成を推測しない。
2. 散歩でよく使う操作と補助操作を整理する。犬の選択、左右のリード接続・解除、行き先の選択について、何を選び、何に作用する操作かが分かる順序・まとまりを検討する。
3. 一画面に常時置くもの、選択後に見せるもの、別画面へ分けるものを比較する。情報を減らすために文字やボタンを小さくするのではなく、分類と表示の優先順位を見直す。ページ数・タブ名・配置はまだ固定しない。
4. メニュー全体のタブから散歩へ入り、必要な操作を終えてワールドへ戻る流れを HTML で確認できるようにする。散歩以外は導線の確認に必要な範囲を示す。
5. モックでは、犬が未選択・接続中・操作できない場合や、行き先の選択状態・操作結果を見比べられるようにする。押せない理由と次にできることが分かるかを確認する。実通信や犬の制御を実装したものとは扱わない。
6. ユーザーと HTML 上で構成・文言・操作の流れを確認し、採用案と Unity へ反映する範囲、残る判断を記録する。

## 維持する前提と関連資料

- 既存の犬・リード接続・操作権の仕様を、見た目の整理だけを理由に変えない。仕様変更が必要なら案と理由を分けて記録する。
- PCVR / Desktop / Touch の開く・閉じる・戻る操作と、片手で使う場合も考慮する。HTML の確認を VR 実機の操作性の合格にしない。
- UI 方針の正本は [world-ui-spec](../../world-ui-spec.md)、実装経緯は [メニュー再構築計画](../../plans/2026-09-23-menu-rebuild.md) と [IMP-UI-001](IMP-UI-001-menu-table-driven-and-settings.md)。過去の採用構成は [DES-UI-003](DES-UI-003-menu-scope-and-polish.md)。
- 入口のメニュー説明画像は [IMP-UI-002](IMP-UI-002-guide-board-capture-instructions.md) と整合させる。構成案の採用後、実装画面のキャプチャーへ更新する。
- 今後のギャラリー用メニュー入口は [IMP-WLD-005](IMP-WLD-005-auto-photo-and-gallery.md)、トレーナー・購入導線は [DES-UI-005](DES-UI-005-trainer-and-paid-items-purchase-flow.md)。全体構成の検討時に見落とさないが、機能の実装は各 Issue で扱う。

## 2026-10-15 追記: 10月14日のかざり・移動・人一覧のHTML案

ユーザーの依頼で、既存の[メニュー改善HTML](../../plans/mock/2026-10-14-menu-subtabs-and-people.html)を本Issueの追加検討範囲として記録した。今回の依頼はIssueへの追記であり、案の採用やUnityへの実装指示を受けた記録ではない。

### HTMLにある構成案

| 対象 | 提案内容 |
|---|---|
| かざり | 「犬の飾り / 首輪とリード / 撫でエフェクト」の3サブタブ。撫でエフェクト6種は一画面、品数の多い飾りは6件ずつのページ送り。購入確認と装着操作を分ける |
| 場所への移動 | 地図と5地点の選択。選択後に「ここへ移動」を押す。地点名・距離・地図は試作用の値で、現行の目的地構成との照合が必要 |
| 人への移動・呼び出し | 地図を外した別ボードで16人を4列×4段に表示。17人以上は16件ずつページ送り。相手を選んでから「この人のところへ行く / ここへ来てもらう」を選び、相手の了承後に移動する |

通常の板は1140×700、人一覧は1140×840の仮寸法。HTMLには在室人数1・8・16・32人、長い名前、受付OFF、申込取消・了承・お断りの試作状態がある。参加者・所持品・距離は仮データで、実通信は行わない。移動の契約は[既存の地図・移動設計](../../plans/2026-09-27-map-and-travel.md)と照合する。
