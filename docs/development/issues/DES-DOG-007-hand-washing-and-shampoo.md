# DES-DOG-007 シャンプーをつけて手で洗う体験を検討する

## 依頼と位置づけ

2026-10-02 ユーザー指定: 洗い方は「ちょっと検討が必要」。提供された調査メモと体験案をもとに、現行のスポンジ中心から **シャンプーをつけ、自分の手で犬をわしゃわしゃ洗う体験** を主役にするか検討する。**手洗いの採用・スポンジの撤去はまだ決定していない。**

目的は、古民家で覚えた「撫でる」の延長として、自分の手で犬を世話する感覚とASMR的な気持ちよさを高めること。現実の手順をそのまま必須工程にするのではなく、ワールドでの洗いやすさと犬とのふれあいとして比較する。

## 提供された体験案

- 主案: ボトルを持つ → 犬にシャンプーをつける → 空いた手または両手でわしゃわしゃする → 触れた場所から泡が増える → シャワーで流す
- 一周の例: シャワー → シャンプーボトル → 手洗い → シャワー → タオル。現行の自由な手順・水から始める・途中で泡を足す方針との整合を検討する
- スポンジを残す案: 泡を作る、泡をたっぷり犬に乗せる補助道具にする。既存の仕組みを再利用できるか調べる
- ラバーミット/ラバーブラシは追加候補。今回の手洗いを成立させる必須の道具にはせず、必要性を比較する

## 検討すること

1. シャンプーをつける操作と、手でこすって泡を増やす操作の関係。つける量・範囲・持続時間と、きれいな犬へ繰り返し泡をつける扱い
2. 手の接触・移動から泡立てを判定する方式。普通の撫でと手洗いの区別、頭・関節・動く足や尻尾でも自然に洗えるか
3. 片手・両手・座位のVR操作と、Desktop / Touch の代替操作。ボトルを持ったまま片手で洗えるか、手が使いにくい人の道具の選択肢
4. スポンジ中心・手洗い中心・併用の比較。ボトルや手の準備が増えることで、触れ合いの楽しさより操作の手間が増えないか
5. 既存の撫で反応、首輪操作、洗い場の保持、2人同時の泡立てとすすぎ、同期・描画負荷との整合
6. 少数の代表場面での試作と評価。片手/両手の泡立ち、自分の手で世話している感覚、すすぎへの切替、端末別の扱いやすさを比較する

## 初見の分かりやすさを含む検討 (2026-10-02、提案・未採用)

### 最新のユーザー指摘

スポンジは初見でも「これを使う」と分かる。一方、ボトルと素手になると次の操作が分かりにくい。犬を呼ぶ・高さを変える洗い場の操作ボード付近に、**一目で分かる図解**が必要ではないか、という懸念。

### 比較と推奨

| 案 | 初見での入口 | 犬に触れる感覚 | 変更の大きさ・判断 |
|---|---|---|---|
| 現行スポンジを主役にする | 道具が見え、触れれば泡が出る。ユーザー評価で分かりやすい | 道具越し | 最小。比較の基準として残す |
| ボトル＋手へ全面置換 | ボトルから手へ移ることを覚える必要がある | 手で触れられる | 素手の入力・同期と全端末の代替が必要。最初の試作では推奨しない |
| **ボトル＋手を案内の主役にし、スポンジも残す** | **3コマ図解と、ボトルで実際に出る泡で次の操作を示す** | **片手・両手で泡を広げられる** | **推奨する試作案**。PC/スマホや道具を使いたい人にも既存の入口を残せる |

スポンジを残す案でも、主説明で手とスポンジを同じ大きさの2経路として並べない。主説明は手洗い3コマ、スポンジは棚の脇と短い補助文で伝える。手洗いを誰も発見せず全員がスポンジを取るなら、図解・ボトルの位置・最初の反応を改善して再評価する。

### 推奨する最小の操作

1. ボトルを取り、口を犬の背中へ向けて Use を1回押すと、**見える泡がすぐ背中につく**。液だけ出て見えない「シャンプー済み状態」にしない。ボトルを持ったときだけ出る短い操作案内も候補とする。
2. 空いた手で泡に触れて動かすと、そこから泡が増えて周囲へ広がる。片手で成立し、両手で洗いたければ近くの棚にボトルを置ける。両手を必須にしない。
3. シャワーで泡をさっと流す。必要ならタオルで仕上げる。図解は洗い方の例で、濡らすことや全工程の完遂を開始条件にしない。

**「説明を読む前に反応から分かる」ことも必要。** ボトルの口・泡の出る場所・棚の置き場が見て分かり、触れた場所の泡と音がすぐ返る構成を試す。泡立ち・すすぎのテンポは IMP-DOG-025 の改善を使う。

### ボード付近の図解

主ラベルは **① 泡をつける → ② 手でわしゃわしゃ → ③ シャワーで流す**。

| コマ | 本制作で描くもの | 短い補助文 |
|---|---|---|
| ① | 犬の背中へ口を向けた実物と同じ形のボトル、背中に出た泡。手洗いの図とは別の手順として読める | ボトルから背中へ |
| ② | **道具を持っていない手が犬の体に触れる**絵、往復の矢印、触れた所で増える泡。手を単独で描くだけにしない | 泡を手でひろげる |
| ③ | 犬の体に水を当てるシャワー、流れる泡と現れた毛 | さーっと、きれいに |

- 犬を呼ぶ操作面の**上に、同じ木枠に収めた読む専用の帯**を第一候補とする。常設で、ボタンを押したりページを切り替えたりしなくても読める。上が高くなる場合はすぐ隣に置く案と比較する
- ビルダーの操作面の既定は **0.60 × 0.36 m**、下端約0.94 m〜上端約1.30 m (`KH_DogWashSetupEditor.Station.cs:638` 付近)。犬6匹・おわり・高さ調整があるため、既存の操作面に図解を詰めてボタンを小さくしない。これはコード既定で、現地寸法の確認ではない
- 図解帯はまず幅0.60 m・高さ0.22〜0.28 m程度を配置比較の仮値にする。操作面との間隔・実際の高さは、立位/座位、犬の見え方、ボトルへの手の届き方を現地で確認して決める
- 説明図はボタン風の枠にしない。操作面の暗い背景＋白文字を基本に、木の装飾は外縁へ。泡・手・水の形と①②③でも読めるようにする (VIS-01〜03 / XR-01〜02)
- 下端の補助文は「片手でも、スポンジでも洗えます」程度。ボトルを置く細かい操作や、タオル等を主3コマへ詰め込まない
- [IMP-DOG-037](IMP-DOG-037-wash-call-availability-and-range.md) の「呼べる/遊んでいる/遠い」の理由表示は操作面に置き、図解を理由表示で上書きしない
- 会話内の配置モック: `docs/_sessions/des-dog-007/wash-guide.html` (git管理外)。記号による配置の検討用で、犬の体と手の接触を描く本制作の絵・Unity画面ではない。再現に必要なラベルと配置の意図は本節を正本とする

### 撫で・すすぎ・2人を混同させない条件案

| 状態 | 操作の意味 (案) |
|---|---|
| 泡がない犬に素手で触れる | 今までどおり撫でる。勝手に泡を出さない |
| 洗い場の犬の**泡が見える部分**を空いた手でこする | 泡立てる。触れた場所から近隣へ泡を広げる。触れずに手を振る・手を置いたまま・道具を持った手は対象外 |
| すすいで泡がなくなった部分に触れる | 触れるだけでは泡を戻さない。もう一度洗うならボトルやスポンジで泡を足す |
| 2人で別の場所を洗う | それぞれの手の接触を独立に扱う。同じ場所で片方がすすぐ場合、手だけで即座に泡を復活させない判定を試作で詰める |

初回試作は洗い場で呼んで留めた1匹へ絞る。最終的に道中やリードを外した直後の犬へも手洗いを広げるかは後で判断する。道具を使う既存の洗浄範囲は維持する。見えない長いタイマーで「手洗いモード」を保つ案は避け、**泡があることと操作の意味が一致する**ようにする。これは挙動の提案で、泡の有無を取る技術方式・境界の閾値は未確定。

### 端末ごとの第一段階

- PCVR / Quest VR: ボトルのUseと空いた手の接触。片手・両手、手が小さい/大きいアバター、座位で試す
- Desktop / Touch: **現行スポンジの「持ってUseしながら視線を動かす」経路を第一段階の成立経路とする**。こちらに裸の手の操作を無理に見立てない。端末に合わせて補助案内を「スポンジで洗えます」にする案を比較する
- Desktop / Touchにも手洗いを作る場合は別の入力試作が必要。新しいボタンやモードを増やす価値があるか、VRの試作後に判断する。全端末で同じ入力が完成したとは扱わない

### ソースから分かった実装上の制約

- `KH_WashTool.cs:470` 付近: VRは道具先端の球と部位Collider、Desktop/TouchはUse＋視線。部位の接触から局所洗浄へ渡す処理は存在する
- `KD_DogPetController.cs:1092` 付近 / `vrc-character-rig` §7: ローカルの左右の手位置は既存の撫で処理で利用している。ただし撫での反応判定を、そのまま全身の泡の位置へ使えると確認したわけではない
- `KH_DogWash.cs:887` 付近: 接触履歴は道具種別ごとで、同種の両手が同じ履歴を共用する制限が明記されている。**左右の手と道具を区別する接触の履歴が必要**。離れた手の間に泡の線が引かれることや、片手を離すともう片手も切れることを防ぐ
- `KH_DogWash.cs:983` 付近: 他人からのストロークは道具を保持していることを検査する。素手の経路には開始条件・距離・送信量・状態の検証を設計する必要があり、既存の保持検査を単純に外さない
- `KH_DogWashSetupEditor.Station.cs:861` 付近: ボードビルダーは既知の子以外を削除する。説明帯を後から子として足すだけでは再生成時に消えるため、正式な生成対象または兄弟オブジェクトとして扱う
- 手洗いを使わない間は追加の全頭・両手走査を続けない。対象犬・洗い場の近接で処理を絞る方式を試作し、計測する

### 小試作と採否の見極め

1. **図解だけの確認**: 初めて見る人に短く見てもらい、口頭で教えず「最初に何を持つか」「ボトルの次に何をするか」を確かめる。手で犬に触れると読めなければ絵を直す。約5秒は提案上の目安で、可読性の規格値ではない
2. **柴1匹＋ボトル1本＋片手**: 泡が出た時点で成功が分かるか、片手で自然にこすり始めるか、ボトルを置き直す手間が大きくないか。現行スポンジと同じ場面で比較する
3. **両手・すすぎ・再洗浄**: 頭と背中など離れた部位を同時に触る、片手だけ離す、すすいだ所を撫でる、泡を付け直す。誤った接続・勝手な再泡立ち・反応の遅れを確認する
4. **2人と端末差**: 片方が泡立て、もう片方がすすぐ。途中参加・Owner交代・道具保持検査との関係を確認。Desktop/Touchはスポンジの経路を確認する
5. **負荷**: 手洗い無し/片手/両手/2人での処理回数・描画更新・送信量を比較し、Questの洗い心地も確認する。追加の6匹一周テストはこの試作には不要

採用の判断軸は「説明を増やさず始められる」「スポンジ以上に犬を世話している感覚がある」「片手でも成立する」「すすぎ・撫で・2人の操作を邪魔しない」。図解でしか成立しない隠れた操作が増えるなら、スポンジ中心を残す案へ戻る。
