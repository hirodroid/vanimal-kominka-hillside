# DES-UI-002 フリスビーの設定 (待つ場所・曲げ・取り方) と開発用切替の扱いを設計する

2026-09-22 起票。[IMP-DOG-008](IMP-DOG-008-frisbee-variations.md) で 6 プリセット (通常 / 走り込み: 横 / 遠く / 並走 / ひねり / 横曲がり) を手元メニューのヘッダの「試作」ボタン (同期 int、誰でも押せる) で比べ、ユーザーは**全部採用**、ボタンは**当面残す**と決めた。本 Issue は、これを公開向けの設定にどう見せるかを決める。実装は決定後に別 Issue。

## 決めること

- 「ユーザーが選ぶ項目」と「自動で変わる動作」の切り分け。Codex U2 の見立て: 投げ方 (曲げ) は自分で選びたい、待つ場所は必要なら選べる、回り込み・走り跳び・待ち・立ち取りは自動でよい、ひねりは自動の変化か「取り方: おまかせ / 指定」。ユーザー決定はまだ (PCVR 評価だけで確定しない)。
- 操作権: 個人の手元ボタンが他人の遊び方を変える (Codex U1)。対象犬と共有設定であることの明示、持ち主 / 今遊んでいる人だけが変えられる等の条件。Owner (通信の担当) をそのまま権限にしない。
- 6 項目を種類 (待つ場所 / 取り方 / 投げ方) で分けて見せる。開発用のプリセット番号をそのまま公開設定のデータ構造にしない。
- 縁で追わない・候補が落ちる時の短い理由の返し方 (「中央へ投げてね」「リード中」など。Codex U3)。照準を「必ず取れる表示」と読ませない。
- 「試作」ボタンの撤去時期 (6 匹展開の間は残す) と、Build Menu の古い子の掃除。
  - **2026-09-23: [試作] の入口は `KH_HandMenu` の退役 ([IMP-UI-001](IMP-UI-001-menu-table-driven-and-settings.md) 段階 0-b) で消えた** (`KH_FrisbeeCatch._DevVariant` 自体は残る)。**2026-09-24 ユーザー決定: 切替はトレーナー用なので、あそぶタブのトレーナー特典の群 (集合モードと同じ場所) に行「フリスビーの取り方」として置く。** トレーナーだけが押せ (集合と同じ権限)、押すたびに 6 プリセットを順送りで犬の Owner に頼む (`KD_ActivitiesMenu` 裏山改変、row 2、文言 `activities.hillside.frisbee*`)。誰でも押せた旧 [試作] からの変更。公開向けの設定 (投げ方・待つ場所・取り方の切り分け) の設計はこの Issue のまま残る。
  - 決定: 2026-09-29 (ユーザー) 旧 [試作] 入口の代わりは作らない。ディスクはおもちゃタブで呼び出せるので問題なし
  - **2026-09-24: 6 匹展開を実装 ([IMP-DOG-012](IMP-DOG-012-frisbee-six-dogs.md))。切替はあそぶタブのトレーナー群へ移設済みで、ディスクを持つ犬全部 (6 匹) に同じプリセットを頼む。**

- 上の「Unity ではコンパイルも実行もしていない」は `8faf572` で解消した (C# / U# エラー 0。下の検証)。
