# IMP-ENV-001 散歩道と休憩場所の居心地を磨く

[開発全体像](../overview.md) §3の景観改善案。PCVRで好評だったTerrain v4を基準に、[core-concept](../../core-concept.md)の3つの体験を守る。最終コース長・形状・休憩場所数は未確定。

2026-09-20 PCVR具体報告: 景観は現状の軽い構成でよく、犬との体験を優先する。景観の増量は後回しにするが、足場・落下・視認性の改善は継続する。

## 範囲と着手

2026-10-04 のユーザー指示が以下の旧着手順に優先する。他作業と性能調整は終了、Quest 3 で通常40〜50 FPS・高負荷箇所30 FPSとの報告を受け景観改善に着手する。詳細な描画・容量・端末負荷の調査と改善（下記③）は景観改善後の [VER-ENV-002](VER-ENV-002-scenery-performance.md) へ移管し、着手の前提から外す。足場・境界・視認性の確認は維持する。[制作記録](../../plans/2026-10-04-roadside-scenery.md)。

- 端末負荷の初回測定と、犬の移動・遊びに必要な足場を確認し、体験上の必要性がある箇所だけ追加を検討する。密度の増加自体を目標にしない。
- **VER-ENV-001 から引き継いだ項目別の確認 (2026-09-22)。「負荷の初回測定後」の前提としてここで取る**: ①項目 2 の残り = 南東・南西の隅で Terrain の縁と遠景の継ぎ目が見えないか (Play)、②項目 4 = 柵・斜面の外へ落ちない (柵に沿って一周)、③項目 6 = PC・Quest 単体・iOS の実機負荷の目安 (`vrc-performance` の手順。Editor 側の描画コールも取る。**Quest 単体・iOS の実機分と境界の端末確認は [VER-WLD-001](VER-WLD-001-quest-ios-devices.md) と同じ場で取る**。ここの項目は取り下げない)、④項目 9 の残り = 往復の所要時間の記録とコース長の確定。PCVR の総合評価は上記の合格ではない (不変条件 7、経緯は [VER-ENV-001](VER-ENV-001-prototype-view-and-edges.md))。
- 入口、登り道、見晴らし、遊び場ごとに視線・足元・木陰・休める場所を整える。
- 木・草・岩は必要な箇所に絞る。古民家の眺めや犬の発見性を隠さない。
- 古民家外観の不要な室内・Udon、ワールド端、ボールが落ちる斜面を整理する。購入原本を直接変更せず、ワールド側で扱う。
- 環境音は候補。増設ギミックや広大なコースは要件にしない。
