# IMP-UI-006 — 初回散歩のリード接続案内

2026-10-10のユーザー採用。実装・シーン配線済み。Unity側の検証と独立レビューを行い、同日のユーザー実機確認で案内体験は了承済み。未報告の例外条件・端末別確認は下記に分けて残す。仕様の正本は[world-ui-specの初回散歩案内](../../world-ui-spec.md#初回の散歩案内2026-10-10--実装済み実機確認待ち)。

## 実装

- 初回は個人データと共有接続状態の準備後2秒、入口10m以内で開始。12m超で中断。端末にかかわらず、実在する拾える先端1つを直径0.21mの丸で囲み、その上に大きな弾む矢印を出す。利用可能な間は同じ先端を指し続ける。
- 持つと近くの適格な首輪へ緑の輪を出す。候補判定は0.15秒間隔、位置は犬の更新後のPostLateUpdateで追従。本人4m以内と入口周辺の犬の存在を分け、遠い犬がいるだけで「犬がいない」としない。
- 接続先が本人に確定した時点で完了を保存し、5秒の出発案内に続き、5秒の行き先ヒント。自動Drop・即解除・復元前成功を取りこぼさない。Ownerの直接更新と受信側の両方を観測する。
- 接続要求中にDropして持ち直しても、既に送った要求と申請時の手を保持する。既存2秒timeout・接続半径0.22m・保持0.25秒は変更しない。
- 表示・進行・保存は本人用。閉じるはその入室中だけ。設定の「散歩の案内」から再表示／自動案内ON・OFF。行き先変更の紹介は出すが、実行を求める追加課題にはしない。
- Desktop/Touchも初期はリードを指す。メニューを開いたまま物理リードの案内を継続し、接続後に行き先欄を紹介。17キーを既存13言語表へ追加。ja/enは共通フォントに焼き込み、他11言語は既存のVRChat内蔵fallback方針を維持。

## 保守と再構築

`Assets/KominkaHillside/Scripts/KH_WalkIntro.cs`、`KH_LeashManager.Intro.cs`、`Scripts/Editor/KH_WalkIntroEditor*.cs`。既存Clip/Managerへの差込は成功観測・保持状態・要求待ちの参照と持ち直し対応。メニューには行き先紹介時の一度限りの配置と、本人操作を優先するrevisionを追加。

Unityメニュー `Tools/KominkaHillside/Course/Walk Intro/` の順に実行する。

1. `1 Create Program`（初回のみ）。`bash scripts/unity-compile.sh --udon`でコンパイルする。
2. `2 Setup`で配線。既存の案内板・閉じるボタンの位置は保持し、寸法・参照・時間はコードから書く。入口MenuPlateと閉じるボタンの向きは常設説明板に合わせ、MenuPlateは横棒の入口側へ置く。既存構築済みシーンの丸追加・入口配置だけの更新は`4 Apply Pickup Cue`。
3. `3 Verify`で別検査後、シーンを保存する。

`KH_WalkIntroEditor.ProbeTransitions()`は一時複製で実際の成功観測処理を検査する。PlayerData入出力を呼ばない。`Capture()`はEditモードの静止プレビューで、夜の一時マテリアルも元に戻す。どちらもPlay/実機合格の代用ではない。

## 例外・端末別の実機確認（個別結果は未報告）

既に接続済みの人は「設定 → 散歩の案内 → もう一度見る」で表示を確認できる。再表示は完了履歴を消さない。初回の自動起動・再入室の検査は、この機能の完了履歴がないテスト利用者で行う。

- [ ] PCVR: 入室→左右いずれかのリード取得→首輪へ近づける→接続→出発表示。動く首輪と光が重なり、顔と手を隠さない。
- [ ] 途中Drop／片手Drop・他方保持／要求直後Drop→反対の手で再Pickup。成功とtimeoutの両方。即解除しても完了は残る。
- [ ] 閉じる→入口へ戻っても再表示しない。設定から再表示でき、ON/OFFが再入室で復元される。接続済みの自動案内は再入室で出ない。
- [ ] 復元を待つ間に自力で接続して外す、案内OFF／範囲外／メニューから接続する。いずれも完了を保存し、非表示中の大きな成功案内は出ない。
- [ ] 2人: 同じ犬へ同時要求、他人が先に接続、全頭利用中、Owner交代。本人以外の矢印・輪・進行が見えない。
- [ ] Desktop/Touch: 最初の丸と矢印はボタンでなくリードを示す。メニューを自分で開いて近くの犬を接続した場合も、取得ステップを強制されない。設定・言語選択中でも案内が継続し、メニューの入力を遮らない。
- [ ] PCVR／低い目線／Quest／iOS、昼夜、13言語: 初回の読める距離、閉じるの操作、文字の欠落・枠あふれ。11言語のクライアントfallbackは必ず実機で確認する。

## 2026-10-10 メニュー併用と行き先ヒント

ユーザーの実機報告で、メニューを閉じるまで初回の矢印が出ないことを確認。原因はウェルカム等でPauseし、さんぽタブではMenuAttachへ切り替える表示条件。これらを外し、メニューを表示したまま物理リードの丸・矢印・首輪案内を継続する。

追加依頼により、接続後5秒の「犬について歩こう」の後、行き先ヒントを5秒表示。この時点でメニューを一度だけ犬の上へ据え、さんぽタブと行き先6ボタンの印を出す。入力や行き先変更を追加の完了条件にしない。閉じる／別タブで印は消え、開き直しは強制しない。自動配置で「自分でメニューを開いた」記録は付けない。

印は公式サイト `public/assets/site.css` の温白 #FFFDF8＋森の緑 #364E3C。四隅の短い線とゆっくりした明滅で目立たせる。読む面に新しいCollider/Raycasterは追加しない。新文言は13言語に追加し、既存の言語テーブルへ反映。

確認対象：入室時のメニューと矢印の同時表示、先端を持つ→接続→出発→行き先紹介、行き先ボタンの入力、メニューを閉じる／別タブ／通常の呼び戻し、低身長アバター・斜面での板位置、接続即解除・再表示。実機の見え方と操作は未確認。

追加改修の検証：C# / UdonSharpエラー0、保存・再読込後Verify 81/81 PASS、既存の完了状態プローブ＋出発→行き先の切替 11/11 PASS。文書リンク・Issue整合・消費処理チェックは合格。独立レビュー担当 /root/onboarding_review の指摘（最初の5秒内の閉じる・タブ操作が遅延表示に上書きされる）を、操作revisionによる自動配置取消で修正し、担当が再確認。Editor合成プレビュー Temp/KH_WalkIntro/destination-layout.png で案内文1行と6ボタンを囲む印を目視確認。プレビューは共有接続を模擬せず、保存済みメニュー内容を使う。保存差分は言語・案内の各proxy/backing、印の子階層とその親のみで、既存オブジェクト削除なし。実機は未確認。
