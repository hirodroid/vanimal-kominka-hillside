# IMP-DOG-021 川のどこでも回収と、水中の犬のおもちゃの呼び寄せ

2026-09-28 ユーザー要望 (IMP-DOG-020 の段階 5〜8 が ClientSim で通った後)。

> 「水遊びしている犬のボールを取り寄せられないのは仕様? → 1 (口に無いときは呼べる) を入れたい」
> 「ボールを川の真ん中に投げると沈んでいって、犬が拾いに行かなくなる。川のどこに投げても大丈夫なようにしたい」

何をどう作るかの正本は [設計書 §E](../../plans/2026-09-27-river-play-and-floating-fetch.md#e-川のどこでも回収-2026-09-28) (本 Issue と同時に追記)。数値は設計書を見る。

## 今の挙動と原因 (2026-09-28 調査)

- ボールが浮くのは水遊び場 (z 278〜301 の 22.5 m) の中だけ (`KH_WaterSpot._FloatsAt`)。その外の川の帯へ落ちたボールは重力のまま河床 (水面の 0.4 m 下) へ沈み、10 s 後に Owner の `KH_ToyRecall` が岸へ戻す (IMP-DOG-020 段階 1 の規則)。沈んだ間は水面が不透明なので見えない。犬は水遊び場の外の川には入らない。
- 水遊び場の中でも、大型犬 (ラブ・サモエド) は歩ける深さ 0.45 M (0.25 / 0.23 m) より深いボール = 流路の中央 (0.40 m) のボールを追わない (`reason=deep-ball`)。小型犬は泳いで取る。
- 水中 (`waterPose` ≠ 0) の犬に割り当てたボール・ディスクの呼び寄せは、口にあるかどうかに関わらず断り、犬を出水させる (設計書 B-1「要求自体は水中では受理しない」)。処理上の制約ではなく、水中の犬への操作をひとつの規則にそろえた設計上の選択。

## 決定と前提 (2026-09-28)

- **川のどこへ投げても犬が取りに行く。** 帯の中のボールは川全体で浮かせ、犬は最寄りの安全な岸から入り、流路を歩く / 泳いで取り、投げた人の側の安全な岸へ上がって持ち帰る。
- **例外はいまの岸戻しに落とす**: 橋の帯 (寄り道禁止帯と同じ z ±8 m) の中、犬が入れる安全な岸 (輪切りの検査に通る岸) が両側とも一定距離内に無い区間。ボールは 10 s 後に岸へ戻る (今と同じ)。犬が入れない場所へは行かせない。
- **大型犬は泳がないまま、流路 (0.40 m) までは歩いて取る** (統括の前提。ユーザーの「大型犬はチャプチャプ」を泳がない意味に取った。口の余裕はラブ 0.16 / サモエド 0.10 m。口 − 水面 < 0.03 m の歩を進めない sink-guard は残す)。ユーザーが「大型犬は浅瀬だけ」を維持するなら、歩ける深さの比を戻すだけで戻せる (設計書 §E の値)。
- **自由行動の水遊び (WaterPlay) は水遊び場のまま。** 広げるのは「投げたボールの回収」と「浮き」だけ。
- **水中の犬のおもちゃの呼び寄せ**: ボール・ディスクがどの犬の口にも無ければ受理する (浮いていても岸にあっても)。追っている最中の犬は目標を失って水中の GiveUp → 出水 (既存の経路)。水遊び中で追っていない犬は出水しない。くわえている最中 (WaterReturn / Drop の放す前) はいままでどおり断る。
- 同期変数は増やさない (焼いたデータは全端末が同じものを持つ)。

## 順序と完了条件

各段は、コンパイル・Console エラー 0・保存後の Verify が通ってから次へ進む。Unity のメニュー実行・保存は統括の担当。

### 1. 水中の犬のおもちゃの呼び寄せ

- [ ] `KH_ToyRecall` の門 `InWater` は、口に無いとき (`_BallInMouth` / ディスクの保持) は通す。犬が追っている最中なら Fetch 側が目標の消失を GiveUp として扱う
- [ ] 手元メニューの文言: くわえているときだけ「水遊び中 — 上がったらつなげます」。それ以外は通常の呼び寄せ
- [ ] ハーネス 78: W4-toy を「浮いているボールを呼び寄せ → 手元へ来る、犬は出水しない」に変え、「追っている最中に呼び寄せ → 犬は GiveUp して出水、ボールは手元」を足す

### 2. 川全体の河床格子と岸の輪切り (Editor)

- [ ] `KH_RiverData` に、川全体の河床格子 (0.5 m、帯 + 2 m) と、1.5 m ごとの輪切りの「入れる岸」(左右それぞれ: 岸の点・復帰点・合否) を焼く。検査は Course/76 と同じ (出水点の傾き ≤ 25°、道から岸への完全経路、石なし、橋の帯の外)。勾配の上限は課さない (浮くだけなので)
- [ ] `Tools/KominkaHillside/Course/90 - Build River Fetch Data` と `91 - Verify River Fetch Data` (輪切りの合否の一覧、格子の欠け 0、容量の記録)
- [ ] 容量: 焼いた配列のサイズを記録 (見積り: 格子 ≤ 130 KB、輪切り ≤ 30 KB)

### 3. 川のどこでも浮く

- [ ] `_FloatsAt` を「川の帯の中、橋の帯の外、格子あり」に広げる。水面の高さは `KH_RiverData._SurfaceY`
- [ ] 例外 (橋の帯・入れる岸が無い区間) は今の岸戻し (10 s) のまま。岸戻しの先は投げた人の側
- [ ] 漂流 (0.15 m/s) は下流へ。橋の帯へ入る手前で止める (今の下流端で止まる規則を橋の帯の手前にも適用)

### 4. 川のどこへでも取りに行く

- [ ] Fetch の WaterChase: 入水点 = ボールにいちばん近い「入れる岸」(ボールと同じ橋の区間)。NavMesh でそこまで走り、流路をボールへ (格子の深さで歩き / 泳ぎを切替、既存の規則)。出水点 = 投げた人の側の、ボールを取った位置にいちばん近い「入れる岸」。復帰点から NavMesh で持ち帰る
- [ ] 大型犬の歩ける深さを流路 (0.40 m) まで広げる (設計書 §E の比。sink-guard は残す)。泳ぎに入る条件は変えない (泳がない)
- [ ] 時間の契約: 追跡 / 持ち帰りの上限を距離で伸ばす (岸までの経路長 ÷ 走り 2.4 m/s + 水中の距離 ÷ 泳ぎ or 歩き + 余裕)。上限を超えたら GiveUp → 出水 (既存)
- [ ] 押し合い・別の犬の Fetch との干渉は既存の規則のまま

### 5. 検証

- [ ] ハーネス 88 に追加: 下流 (z ≈ 150) と上流 (z ≈ 400) の中央へ投げる (小型犬 1・大型犬 1)、橋の帯へ投げる (岸戻し)、入れる岸が無い区間へ投げる (岸戻し)、対岸側に立って投げる、水遊び場の中央へ大型犬 (取りに行く)
- [ ] 89 (フリスビーの帯判定) と W5 (帯へ入らない) が通ったまま
- [ ] 容量が +0.2 MiB 以内 (Android / iOS 代理)
- [ ] Codex の独立レビュー (同期・所有権・GiveUp の経路・時間の契約)
- [ ] PCVR チェックリストに追加 (設計書末尾): 遠くへ投げたときの犬の走りと入水、上陸の場所、大型犬が流路で取る見え方、橋の近くの岸戻し
