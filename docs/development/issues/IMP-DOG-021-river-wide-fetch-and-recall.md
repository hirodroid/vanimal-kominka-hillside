# IMP-DOG-021 川のどこでも回収と、水中の犬のおもちゃの呼び寄せ

2026-09-28 ユーザー要望 (IMP-DOG-020 の段階 5〜8 が ClientSim で通った後)。

> 「水遊びしている犬のボールを取り寄せられないのは仕様? → 1 (口に無いときは呼べる) を入れたい」
> 「ボールを川の真ん中に投げると沈んでいって、犬が拾いに行かなくなる。川のどこに投げても大丈夫なようにしたい」

何をどう作るかの正本は [設計書 §E](../../plans/2026-09-27-river-play-and-floating-fetch.md#e-川のどこでも回収-2026-09-28) (本 Issue と同時に追記)。数値は設計書を見る。

## 今の挙動と原因 (2026-09-28 調査)

- ボールが浮くのは水遊び場 (z 278〜301 の 22.5 m) の中だけ (`KH_WaterSpot._FloatsAt`)。その外の川の帯へ落ちたボールは重力のまま河床 (水面の 0.4 m 下) へ沈み、10 s 後に Owner の `KH_ToyRecall` が岸へ戻す (IMP-DOG-020 段階 1 の規則)。沈んだ間は水面が不透明なので見えない。犬は水遊び場の外の川には入らない。
- 水遊び場の中でも、大型犬 (ラブ・サモエド) は歩ける深さ 0.45 M (0.25 / 0.23 m) より深いボール = 流路の中央 (0.40 m) のボールを追わない (`reason=deep-ball`)。小型犬は泳いで取る。
- 水中 (`waterPose` ≠ 0) の犬に割り当てたボール・ディスクの呼び寄せは、口にあるかどうかに関わらず断り、犬を出水させる (設計書 B-1「要求自体は水中では受理しない」)。処理上の制約ではなく、水中の犬への操作をひとつの規則にそろえた設計上の選択。

## 決定と前提 (2026-09-28)

- **川のどこへ投げても犬が取りに行く。** 帯の中のボールは川全体で浮かせ、犬は最寄りの安全な岸から入り、流路を歩く / 泳いで取り、投げた人の側の安全な岸へ上がって持ち帰る。
- **例外はいまの岸戻しに落とす**: 橋の帯 (寄り道禁止帯と同じ z ±8 m) の中、犬が入れる安全な岸 (輪切りの検査に通る岸) が両側とも一定距離内に無い区間。ボールは 10 s 後に岸へ戻る (今と同じ)。犬が入れない場所へは行かせない。
- **大型犬は泳がないまま、流路 (0.40 m) までは歩いて取る** (統括の前提、2026-09-29 ユーザー了承。ユーザーの「大型犬はチャプチャプ」を泳がない意味に取った。口の余裕はラブ 0.16 / サモエド 0.10 m。口 − 水面 < 0.03 m の歩を進めない sink-guard は残す)。ユーザーが「大型犬は浅瀬だけ」を維持するなら、歩ける深さの比を戻すだけで戻せる (設計書 §E の値)。
- **自由行動の水遊び (WaterPlay) は水遊び場のまま。** 広げるのは「投げたボールの回収」と「浮き」だけ。
- **水中の犬のおもちゃの呼び寄せ**: ボール・ディスクがどの犬の口にも無ければ受理する (浮いていても岸にあっても)。追っている最中の犬は目標を失って水中の GiveUp → 出水 (既存の経路)。水遊び中で追っていない犬は出水しない。くわえている最中 (WaterReturn / Drop の放す前) はいままでどおり断る。
- 同期変数は増やさない (焼いたデータは全端末が同じものを持つ)。 前提の同期方式 (Codex 補足 2026-09-28): `KD_DogFetchController` は Manual (`dogState` / `waterPose` など)、犬の `KD_DogWanderController`・`KH_ToyRecall`・`KH_RiverData`・`KH_WaterSpot` は None。川の水中 Fetch の計画 (`_wfRiver`・入水点・出水点・上限) は犬の Owner のローカルで、他の端末へは既存の `dogState` / `waterPose` と犬の位置 (`VRCObjectSync`) だけが届く。

### 4. 川のどこへでも取りに行く

- [x] Fetch の WaterChase: 入水点 = ボールにいちばん近い「入れる岸」(ボールと同じ橋の区間)。NavMesh でそこまで走り、流路をボールへ (格子の深さで歩き / 泳ぎを切替、既存の規則)。出水点 = 投げた人の側の、ボールを取った位置にいちばん近い「入れる岸」。復帰点から NavMesh で持ち帰る
- [x] 大型犬の歩ける深さを流路 (0.40 m) まで広げる (設計書 §E の比。sink-guard は残す)。泳ぎに入る条件は変えない (泳がない)
- [x] 時間の契約: 追跡 / 持ち帰りの上限を距離で伸ばす (岸までの経路長 ÷ 走り 2.4 m/s + 水中の距離 ÷ 泳ぎ or 歩き + 余裕)。上限を超えたら GiveUp → 出水 (既存)
- [x] 押し合い・別の犬の Fetch との干渉は既存の規則のまま

実装 (2026-09-28、Opus。コンパイル・実行は未):
- `KD_DogFetchController.HillsideWater`:
  - 追跡中にボールが場の外の川で浮いたら (`KH_RiverData._FloatsAt`) 「川の水中 Fetch」(`_wfRiver`、Owner のローカル、同期しない) で 6 へ。入水点 = ボールに最も近い合格の輪切り (左右それぞれ) のうち、犬から NavMesh の完全経路が短い側の岸の点 (どちらも経路が無ければボールに近い方)。岸の点へは NavMesh (`GatherStep`) で走り、着いたら (0.5 m、または帯の水に入ったら) 川の規則で歩く / 泳ぐ。
  - くわえたら出水点 = 投げた人の側 (投げた人の z の中心線で判定) で、今の位置に最も近い合格の輪切り。その側に 30 m 以内が無ければ反対側 (その後は既存の 8 の規則で復帰点に置く)。上陸後 1.2 s で陸の Return。
  - 時間の契約: 6 = 入水点までの経路長 ÷ 走り 2.4 m/s + 入水点からボールまで ÷ 水中の速さ + 4 s。7 = くわえた所から出水点まで ÷ 水中の速さ + 4 s。水中の速さ = 泳ぎ (泳ぐ犬種) か歩き 1.1 m/s から漂流 0.15 m/s を引いた値 (下限 0.2)。川の上陸後の陸の Return は、投げた人までの経路長 ÷ 2.4 + 4 s が 20 s より長ければそれを上限にする。超えたら既存の GiveUp (`water-timeout`)。ずらした点: 設計の式に「漂流の分を引く」を足した (流れていくボールを追う分)。
  - 場の中の大型犬の深いボールの判定と、川の同じ判定は、Fetch の上限 (`fetchWadeRatio` × M = 0.85 M) で見る。
  - 投げた瞬間に犬が帯に当たったとき、ボールがまだ帯の中で動いていれば最大 3 s 待つ (飛んでいる間に岸へ着いてしまい、浮いたボールを誰も追わなくなるのを防ぐ。止まっているボールなら従来どおり即 `river-band`)。ずらした点 (設計に無い追加)。
- `KD_DogWanderController.HillsideWater`:
  - `_WaterRiverStep` / `_WaterRiverHold`: 川の Fetch の足。帯の水 (`_FetchWater`: 帯の中・橋の帯の外・河床あり) の中は水遊び場と同じ深さの規則 (sink-guard 0.03 m、泳がない犬は Fetch の上限まで)。橋の帯など帯の水でない所へは入らない (既にいれば外向きだけ)。入水点に着く前 (NavMesh で走る間) は川の規則を掛けない (直進の保険が川へ入らないように)。
  - 深さは水遊び場の格子がある所はその値 (従来の値のまま)、それ以外は川全体の格子。濡れた判定 (`waterPose`、リード裁定の `_WetAtRoot`) も場の外の川で効く。
  - Fetch 中 (Fetch の水中の状態と押し合い) は、泳がない犬の歩ける深さを 0.85 M に広げた (水遊び場の中も同じ。自由行動の WaterPlay は 0.45 M のまま)。泳ぎに入る条件は変えない。
  - 場の外の川で濡れたまま遊びの無い犬 (川の Fetch の GiveUp の後など) は、最寄りの合格の輪切り (自分の側 → 反対側、60 m 以内) の岸へ出水する。無ければ岸の点を NavMesh に 4 m で投影 (C-6b)。復旧 2 段目は別の輪切り、3 段目はその復帰点へ移す (既存の 3 段と同じ)。
  - 押し合い: 川の Fetch 中の犬も同じ川の規則で判定し、浮いている犬を橋の帯へ押し込まない。
