# DES-UI-001 古民家と揃えたメニューと接続補助を設計する

2026-09-20ユーザー方針: メニューは古民家と基本構成を揃え、中身を裏山向けにする。しゃがめない人にもUIから接続できる救済策が必要。物理的な先端→首輪接続は残す。トレーナーの集合も採用する。[報告](../../plans/2026-09-20-pcvr-feedback.md)。

## 設計すること

目的地選択の要件は [game-design §4](../../game-design.md) を正とする。IMP-DOG-003の散歩試作に必要な操作契約を先に決め、メニュー全体の完成を待たせない。

- 古民家の最新のメニュー構成・開き方・権限を読み、持ち込む機能と置き換える内容を棚卸しする。
- 自分の接続犬へ「広場へ行こう／古民家側へ帰ろう」を伝える目的地選択を設計する。犬ごとの目的地と操作対象、接続犬なし、現在値が混在する場合、処理待ち・拒否・要求中の接続変更を扱う。他人の犬や未接続犬へ適用しない。初期目的地・追加接続・再接続の契約はDES-DOG-001と揃える。
- 個人メニューから犬を選び「左につなぐ／右につなぐ／外す」を行う。散歩先でも再接続でき、低い姿勢を要求しない。固定ボードは案内・入口の候補。
- 近くの犬へ接続 (現行の4mを試作基準)、自己解除は距離不問。片手3匹、他人の接続、集合/Fetch中、処理待ち・拒否を共通の接続裁定へ揃える。補助UIが上限や所有関係を迂回しない。
- 集合はトレーナー特典として古民家と同じ隊形選択を用意し、接続犬は自他とも対象外にする。Fetch/ライブ中の優先順位、対象頭数・除外理由、終了操作と終了後の自由行動を示す導線を決める。トレーナー機能すべての採用は意味しない。

## 2026-09-20 追加相談

合意の正本は [game-design §4「集合と拠点のリード」](../../game-design.md)。集合終了後もその周辺で犬と過ごせる。各目的地に1個のリード取り出し口を置き、各自がローカルで持ち出す。メニュー接続補助と物理接続は同じ接続上限・権限を使う。

古民家の調査根拠: `C:/work/unity/vcc/KominkaDogRun/docs/development/design/hand-menu.md`、`Assets/KominkaDogRun/Scripts/KD_ActivitiesMenu.cs`。現行は7タブ、集合は「あそぶ」内のトレーナー特典で隊形選択へ進む。開く入口はVRの右スティック下長押し・DesktopのT・Touchのメニューボタン。裏山への権利確認移植・片手操作・画面配置は未設計。

画面候補・操作契約・未設計の範囲は [world-ui-spec §4〜7](../../world-ui-spec.md) に集約する。犬の挙動のQ1〜Q5は回答済みで、残る実装詳細は [DES-DOG-001](DES-DOG-001-leash-walking.md) を参照。戻し先は解除地点の最寄り利用可能拠点で合意済み。全タブ構成と「さんぽ」の名称・配置は引き続き具体化する。

## メニュー側の残件

- 古民家7タブのうち、おやつ・呼ぶ/休憩・かざり・パーティクル・あそぶの他機能をどこまで持ち込むか。採用していない機能や商品をタブ継承だけで追加しない。
- ボール操作は古民家と同じ「1個ずつ手元へ」で決定。一括で広場へ戻すリセットは不要。既存の使用中判定を継承し、斜面での安全な置き先を検証する。
- 接続補助の画面配置と4mの試作値は操作確認で調整。利用権を要求する集合と、通常の散歩の補助操作の表示を混同しない。
- 権利読込中・未所持・集合対象なし・対象の一部除外・要求結果不明でも理由と戻り先を示す。実行可否は表示だけでなく受付時に再判定する。
