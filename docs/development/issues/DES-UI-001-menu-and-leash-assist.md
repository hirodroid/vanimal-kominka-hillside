# DES-UI-001 古民家と揃えたメニューと接続補助を設計する

2026-09-20ユーザー方針: メニューは古民家と基本構成を揃え、中身を裏山向けにする。しゃがめない人にもUIから接続できる救済策が必要。物理的な先端→首輪接続は残す。トレーナーの集合も採用する。[報告](../../plans/2026-09-20-pcvr-feedback.md)。

## 設計すること

目的地選択の要件は [game-design §4](../../game-design.md) を正とする。IMP-DOG-003の散歩試作に必要な操作契約を先に決め、メニュー全体の完成を待たせない。

- 古民家の最新のメニュー構成・開き方・権限を読み、持ち込む機能と置き換える内容を棚卸しする。
- 自分の接続犬へ「広場へ行こう／古民家側へ帰ろう」を伝える目的地選択を設計する。犬ごとの目的地と操作対象、接続犬なし、現在値が混在する場合、処理待ち・拒否・要求中の接続変更を扱う。他人の犬や未接続犬へ適用しない。初期目的地・追加接続・再接続の契約はDES-DOG-001と揃える。
- 個人メニューから犬を選び「左につなぐ／右につなぐ／外す」を行う案を第一候補とする。固定ボードは案内・入口の候補。散歩先でも再接続でき、低い姿勢を要求しない。
- 片手3匹、他人の接続、Fetch中、距離、処理待ち・拒否を既存の接続裁定と揃える。補助UIが上限や所有関係を迂回しない。UI用の距離条件は設計する。
- 集合できる人・犬、他人につながれた犬、Fetch/ライブ中の優先順位を決める。トレーナー機能すべての採用は意味しない。

## 完了条件

- [ ] 古民家の構成との対応と採用範囲をworld-ui-specへ記録
- [ ] 座位・立位・片手・小さいアバター、Desktop・Touchで入口と出口を定義
- [ ] 犬/左右選択・接続/解除の結果・拒否・失敗時の復帰を定義
- [ ] 目的地選択の対象・現在値・対象なし/混在・処理待ち/拒否と権限再判定を定義し、別の人の接続犬に影響しないことを確認する手順を用意
- [ ] 集合の権限・対象と散歩/Fetch/ライブとの優先順位を定義
- [ ] モックと実装Issue・実機確認手順を用意

既存の新規UIを増やさない仮方針は、この補助操作を禁じる理由にはしない。画面レイアウト・具体値は未決定。
