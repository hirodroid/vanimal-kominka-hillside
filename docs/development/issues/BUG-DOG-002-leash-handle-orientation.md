# BUG-DOG-002 リードの輪と紐の接続部を腕から手の前方へ向ける

2026-09-20 ユーザーの PCVR 報告: 首輪・リードの本制作版は「あれでいいレベル」だが、持ち手が右手でも左手でも左向きに付いて見える。最後の微調整として扱う。

## 2026-09-23 追加要望

リードを持ったとき、持ち手の輪と紐を取り付ける部分が横を向いている。**肘 → 手へ伸びる方向の延長上、手の前側へ輪と紐の接続部が向き、そこから紐が伸びる見た目**にしたい。左右どちらの手でも同じ感覚になるようにする。

- 調整対象は手側の持ち手の輪・紐の接続部と、そこからの紐の出方。単に「左向きでなくする」だけでなく、腕から手へ続く向きと揃える。
- 「前」はワールドや視線の前方ではなく、持っている腕・手を基準にした前側。紐全体を直線に固定する意味ではなく、犬へつながる紐の伸び・たるみは維持する。
- 輪の面の傾き・握り位置・接続部の位置は、実装時に左右の手で見て調整する。肘の位置を必ず取得する等の実装方式は、この要望だけで固定しない。

## 実装時の確認先

既存の調査メモでは `KH_LeashCollar.UpdateModeledGeometry` が持ち手を手の追跡回転そのままに置く。着手時に現行実装を再確認し、モデルの軸・手ごとの回転オフセット・紐の接続位置を合わせて調整する。(9/23 午前の記録) この時点では要望の記録のみで、実装・実機確認は未実施だった。実装内容は次の「2026-09-23 実装」を見る。

## 2026-09-23 実装

持ち手を手の追跡回転そのまま置くのをやめ、**腕から手へ伸びる向き**を軸にして置き直した (`KH_LeashCollar.HandleRotation`)。VR のときだけ適用し、Desktop/Touch は従来どおり `GetRotation()` のまま。

- **紐の軸**: 前腕ボーン (`LowerArm` → `Hand`) の向きを「前」とし、持ち手のローカル −Y (紐の接続部) をその向きへ合わせる。`Quaternion.Euler(-90,0,0)` の軸対応 (ローカル +Y → −Z / −Y → +Z / +Z → +Y / +X → +X) を数値で確認して使っている。
- **輪の面**: 手の追跡回転の +Y を上参照にするので、手首を回すと輪の面も一緒に回る。紐の軸は前腕のままなので接続部の向きは崩れない。
- **握り位置**: 持ち手のローカル `(0, +handleGripOffset, 0)` (輪の後ろ側の帯) が手の点に来るよう、持ち手の原点を前へずらす。既定 0.062 では輪が手の点から前へ約 12.4 cm 伸び、紐の接続部は手から約 14 cm 前 (0.062 + 0.077)、輪の前端から接続部までが約 1.5 cm になる。**合否の見方は距離の数字ではなく「輪の後ろ側の帯を握れている」「輪と接続部が拳の前へ出る」**。
- **フォールバック**: ボーン位置が取れない (`Vector3.zero`) / 前腕が 5 cm 未満 (人の腕ではありえない値なので、実質ボーン欠落の検出) のアバターでは、手の追跡回転の +Z を「前」として使う (`KH_Frisbee.AimDirection` と同じ読み方)。手首を深く曲げて上参照が前腕へ近づくと輪の面の基準が痩せるので、しきい値での切り替えではなく **手首の曲げ約 64° から 84° にかけて上参照を +X 方向へ連続的に混ぜる** (約 72° で半分)。切り替え方式だと境界で輪の面が 90° 跳んだため、混ぜる方式にしている。
- 紐のたるみ (`UpdateGeometry`) と「持ち手は holder+手ごとに 1 個」は触っていない。

### 実機で向きが合わないときの直し先

調整値は `KH_LeashManager` の 2 つだけ (6 匹すべてに効く。`Walking/3 Build` が既定値を書き、`Walking/Production 3 Verify` が値を記録して範囲を見張る)。

**手順**: Inspector で値を変えて Play で見る → 決めた値を `KH_DogWalkingEditor.Build` の tuning 行 (`manager.handleGripOffset=...;manager.handleRollDegrees=...;`) へ書き戻してから再 Build する (**Build は値を上書きするので、書き戻さないと次の Build で消える**)。

| 症状 | 直す値 | 目安 |
|------|--------|------|
| 輪が縦に見える / 横に見える (面の傾きだけおかしい) | `handleRollDegrees` | ±90 は縦横の大まかな切替、残りは小刻みに、**必ず両手で**見る。右手の値で、左手は自動で符号反転 |
| 輪が手に食い込む / 手から浮いて前へ出すぎる | `handleGripOffset` | 0.062 を基準に ±0.01 ずつ。**増やす = 輪が前へ / 減らす = 手元へ。上下・左右のずれはこの値では直らない**。0 で輪の中心が手に来る |
| 特定の手首角度で輪が急に跳ぶ | — | **調整値では直らない。**実装側の基準切替 (`HandleRotation` の上参照の混ぜ方) を確認する |
| 紐が横へ出る・左右で向きが違う | 実装側 (前腕ボーンが取れていない可能性) | **アバター名と左右どちらの手かを報告する** (ランタイムではどちらの経路を通ったか見えないため) |

### PCVR 確認チェックリスト (ユーザー)

- [ ] 右手で持つ: 輪と紐の接続部が肘→手の延長上・手の前側を向く
- [ ] 左手で持つ: 同じ感覚になる (左右で向きが違わない)
- [ ] 腕を前へ出す / 下げる / 左右へ向ける: 向きと握り位置が不自然にずれない
- [ ] 手首を回す: 輪の面が一緒に回り、紐の接続部は前腕方向に留まる
- [ ] 手首を深く曲げてゆっくり戻す: 輪が跳ねない (基準の混ぜ方の確認)
- [ ] 犬が前 / 横 / 後ろへ移動: 紐が接続部から切れず、伸び・たるみが保たれる
- [ ] 片手 3 匹: 持ち手は手ごとに 1 個のまま (重なって点滅しない)
- [ ] 途中で 1 匹外す: 持ち手が消えず、残りの紐が同じ接続部から出ている
- [ ] 2 人目 (観察者) から見て、左右とも同じ向きに見える
- [ ] Desktop から VR 保持者を見る: 持ち手と紐がおかしくない
- [ ] Desktop/Touch で自分が持つ: 見た目が以前より悪くなっていない
- [ ] Quest 単体 (VER-WLD-001 と合わせて): ボーン取得も含めて同じ見た目になる
