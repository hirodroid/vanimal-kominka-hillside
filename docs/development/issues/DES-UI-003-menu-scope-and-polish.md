# DES-UI-003 古民家から持ち込むメニュー機能を選び、裏山のメニュー全体を整える

2026-09-23 起票。ユーザー要望: メニュー全体の専用Issueを作り、古民家ドッグランの機能を一つずつ裏山へ持ち込むか検討する。多くを持ち込む意向だが、全機能の一括採用ではない。**おやつを持ち込むことは決定。飾りなど他の項目は推奨案を見て個別に決める。**

現在の「さんぽ / あそぶ / おもちゃ」は [DES-UI-001](archive/DES-UI-001-menu-and-leash-assist.md) で実装・PCVR確認済み。本Issueはその完了を取り消さず、追加する機能の採否・メニュー全体の構成・仕上げを扱う。今回は調査と提案の段階で、Unity実装は変更しない。

## 判断基準と調査元

- [コアコンセプト §1〜2](../../core-concept.md)、[散歩企画追補 §2・6・11](../../reference/VAnimal_KominkaHillside_Walking_Addendum.md): 古民家は遊ぶ・くつろぐ・一緒に寝る場所。裏山は同じ犬を連れ出し、歩き、遊び、景色を見ながら休む場所。犬への愛着を深める機能を優先し、室内設備は持ち込まない。古民家だけでも遊びが完結する関係を守る。
- 現行仕様の正本は [game-design](../../game-design.md)、画面・入力・状態の正本は [world-ui-spec](../../world-ui-spec.md)。採否の相談は本Issue、決定後の仕様は正本へ反映する。
- 古民家側の棚卸し根拠 (2026-09-23 読取調査): `C:/work/unity/vcc/KominkaDogRun/docs/development/design/hand-menu.md` §3-1〜3-8、同ディレクトリの `world-ui-spec.md` §4-3。現行は **かざり / おやつ / 呼ぶ / おもちゃ / ライブ / パーティクル / あそぶ** の7タブと設定。古民家側の価格・権利・端末条件は参考であり、裏山で動作・購入・保存の互換性を確認した意味ではない。

## 2026-09-23 追加決定と提案の書き方

- **最新決定: おじいさんとの初回会話で支度用ポイントを付与し、遊んで追加の飾りなどを解放する。** 初期付与は200または500ポイント程度の仮候補で、価格と合わせて調整。基本の散歩・遊びはポイント稼ぎ不要、付与・獲得は古民家より余裕を持たせる。ポイント・所持品の引き継ぎは今回導入しない。正本は [game-design §4「支度用ポイントと解放」](../../game-design.md)。同日の先行方針「ポイント解放なし」と全ポイント対象品の初期開放案は置換済み。CE購入権・トレーナー特典は既存要件と分けて扱う。
- **ラジオは今回の対象外 (ユーザー決定)。** 保留候補や実装待ちにはしない。
- 「広く持ち込む」「休憩として持ち込む」では変更箇所が分からないとの指摘を受け、下表を更新した。提案を採用済みに格上げしない。
- **そのまま移植** = 見た目・操作・利用条件を変えず移植する案。裏山への参照配線・動作確認は必要だが、仕様変更は含めない。ポイント条件を外す場合も **変更して移植** と明記する。
- **変更して移植 / 保留 / 今回対象外 / 既存実装を維持** を区別する。機能の採否と変更内容は別々に合意する。

## 次に一つずつ決める順番

1. **かざりと初回の支度**: 移植する品物と価格を選び、初回付与の仮候補200/500ポイントで好きな装いを選べるか比較する。全品を最初から開放する案は取り下げる。干渉品の調整・保留、CE品の利用と購入導線は別に判断する。
2. **おやつの範囲**: 採用自体は決定済み。古民家のどの種類を入れるか、裏山でどう補充するか、無料/購入・消費・在庫を決める。推奨は裏山へ直接来た人も利用開始できる導線を用意すること。古民家の在庫・ポイントの自動持越しは前提にしない。9/23追加相談で、おやつから近くの1匹を呼び、撫でる/首輪を外す→次の1匹、という用途を具体化した ([IMP-DOG-006](IMP-DOG-006-leashed-treat-approach.md))。メニューのポーズ選択「呼ぶ」とは別の、おやつへの反応として扱う。
3. **呼ぶ・ポーズ**: 上表の変更移植案 (既存ポーズと選択操作を保ち、接続を保った休憩/散歩再開と地形制限を追加) を相談する。無料の基本動作と追加解放の対象は個別判断。「休憩」という別機能の新設とは扱わない。
4. **撫でFX・追加おもちゃ・トレーナーの追加遊び・犬目線**をそれぞれ判断する。
5. **ライブ・設定・商品導線**の公開範囲を既存の担当Issueと揃え、最後にタブ名・並び・階層を決める。機能数とタブ数を同じにする必要はない。

採用した機能ごとに、対象犬 / 自分と他人への影響 / 使用中・所持なし・読込中・失敗 / 終了と復帰 / VR・Desktop・Touch をUI仕様へ落とす。ポイント・所持品の引き継ぎは今回対象外と決定。装着状態等の残る往復の扱いは [DES-WLD-001](DES-WLD-001-round-trip.md) と分担し、所持品の共有を前提にしない。
