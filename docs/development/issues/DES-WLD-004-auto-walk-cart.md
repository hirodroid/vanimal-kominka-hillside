# DES-WLD-004 犬と景色を楽しむ一人乗り自動散歩カートを設計する

2026-10-11 ユーザー依頼「Issue化お願いします。」により起票。仮称は「おさんぽカート」。一人で操作せず過ごす時間と、後から合流したフレンドとの会話・ツーリングを両立する。受領した体験・機能・品質要件の全文を下に収録する。

## 追加相談: 犬の散歩設定を共用する (2026-10-11)

ユーザー提案: 「犬の目的地をそのまま流用したらいいんじゃない？」「犬の設定で動きますって感じでいいんじゃない？」。**周回専用から、自分の犬の散歩設定 (目的地・周回・周回方向) に従ってカートも動く方針へ広げる。** 同日の「基本は推奨でOKです」で具体化した決定を下記にまとめる。受領要件の周回専用という前提より優先する。

- 行き先は既存の「さんぽ」の選択を共用する。カート専用の目的地一覧や独立した周回方向の設定を増やす前提にしない。
- 既存の選択肢は、広場・古民家側の入口・奥の広場・川辺と、山道から周回・川から周回。目的地へは短い側を選び、周回は選んだ方向で続ける既存の意味を流用する ([周回版の制作記録](../../plans/des-env-002/implementation.md))。
- 共用するのは利用者の行き先の指示。犬の寄り道・くん活・一時的な足取りをそのまま車体の動きにすることではない。カート自身で走り、犬が一緒に歩く方針、全員共通の巡航速度、利用者による速度変更なしは維持する。
- カートが安全に通れる道幅・旋回・斜面への調整は引き続き必要。既存の行き先や経路情報を利用できても、犬用の移動処理をそのまま転用できると確定しない。

**到着時の扱い (ユーザー決定)**: 目的地を選んだ場合は到着でいったん散歩を終了する。以前の AI 推奨「乗ったまま次の行き先を選んで続行」は採用しない。周回を選んだ場合は指定方向で連続周回する。受領要件 §11 の連続周回の確認は「周回を選んだ場合」に適用し、目的地指定時の到着・終了も後続の体験確認へ加える。

設計で詰めること:

- 走行中に行き先や周回方向を変えた際の反映時点・安全な向きの変更。急反転や視点の飛びを避ける。
- 合流中は下記のマスターの設定を優先する。本人の元の設定は保持し、離脱後に戻す (同日の①〜④への了承)。参加者が独自の行き先を選ぶ場合は離脱し、乗り場で自分の散歩を開始する。設定を戻すだけでその場からカートを再出発させない。変更の反映時点は設計で決める。
- 犬なしでも利用できる。複数の接続犬の目的地が混在・乗車中の接続解除の場合に参照する設定と、犬なし時の行き先選択を具体化する。
- 目的地到着時の安全な停止・終了・降車・車体回収と、犬の通常行動への切り替え。

## 決定: 合流グループのマスターに合わせる (2026-10-11)

ユーザー指定: 「合流。にした場合は合流のマスター（最初の人）の目的に合わせる。」。続けて「開始したらグループができあがる。そのグループに合流。」と明確化。**自動散歩を開始すると、開始した本人をマスターとする1人グループができる。合流は既存グループへの参加であり、参加中の目的地・周回・周回方向はそのグループのマスターの設定に合わせる。** 1人で走る場合もグループとして扱い、ほかのグループの設定には影響しない。

ユーザーの A・B・C の例は、C が B のグループに合流する場面として整理する:

| 利用者 | 合流前 | C が B のグループに合流した後 |
|---|---|---|
| A | 開始時に A の1人グループを作り、自分の設定で走行 | A のグループのまま、自分の設定で走行を続ける |
| B | 開始時に B の1人グループを作り、自分の設定で走行 | 同じ B のグループに C が加わる。マスターは B のまま |
| C | B のグループへの合流を選ぶ | B のグループの参加者となり、B の目的地・周回・方向に合わせて走る |

- 合流先として選ぶ対象はグループ。表示名や一覧の見せ方は未決定だが、同じグループの参加者を別々の合流先として扱わない。
- 既存グループに追加参加した人も、そのグループのマスターの設定に従う。参加者が増えても、合流のたびにグループや設定の基準を作り直さない。
- 合流中はマスターの行き先設定を基準とする。変更時の反映タイミングや安全な方向転換は別途設計する。
- ここでの「マスター」はカートの合流グループ内の役割を指す。インスタンス全体の最初の入室者や技術上の同期権限の指定ではない。
- マスターが停止して離脱・降車・退出したら、参加順が次の人へ役割を引き継ぐ。引き継いだ時点のグループの行き先を維持し、新マスターの元の設定へ急に切り替えない (同日の推奨採用)。
- 個人の停止・降車は本人と本人の犬だけが離脱し、残りは継続する。再利用は乗り場で自分の散歩を開始するか、乗り場から既存グループへ合流する。合流・再合流とも乗り場から行う (同日の①への了承)。最後の参加者が抜けたときの解散処理と車体の回収方法は設計で決める。

## 決定: 利用条件・開始場所・終了・対応端末 (2026-10-11)

ユーザー回答「基本は推奨でOKです」と、続く個別指定を反映。個別指定を以前の推奨より優先する。以下と食い違う受領要件の暫定案・未決定表は履歴として扱う。

| 項目 | 決定した内容 |
|---|---|
| 利用料金 | **無料**。長居する理由になる体験として提供する。トレーナー資格や課金アイテムの所持を利用条件にしない |
| 新規開始 | **乗り場だけ**。現在ワープできる各ポイントに乗り場を設ける。道中の任意位置に呼び出して新規開始する案は採用しない |
| 乗り場の対象 | 既存のワープ先 1 古民家側の入口 / 2 広場 / 3 奥の広場 / 4 上流の橋 / 5 川辺。既存のワープ地点を利用する方針であり、専用ワープ先の新設を必須にしない。現在ワープできない 6 下流の橋はこの指定だけでは追加しない ([IMP-WLD-004](IMP-WLD-004-warp-all-five-points.md)) |
| 合流・再合流の入口 | **乗り場からグループを選ぶ**。途中で降りた人も乗り場から再合流する。道中へカートを呼び出す操作は設けない (①への了承) |
| 目的地への到着 | **各車が安全な到着位置まで進み、停車・降車して終了**。後続を道中で終了させない。終了処理に入ったグループは新規合流を受け付けない。次の行き先を選んで継続する操作は設けず、新たな出発は乗り場で通常の開始を行う (②への了承)。終了開始の判定点と停止位置・降車の具体手順は設計する |
| 周回 | 選んだ方向で連続周回する。目的地到着による終了と区別する |
| 合流受付 | **初期ON、変更はマスターだけ**。OFFでも既参加者は残り、マスター交代後も受付状態を維持する (③への了承)。切替中に処理している合流の受理時点は設計で定める |
| 参加者の設定変更 | 自分の行き先で走りたい場合はグループを離れ、自分の散歩を開始する。マスターによる設定変更はグループ全体に適用する |
| 個人設定の保持 | **合流前の自分の設定は保持し、合流中だけグループ設定に従う。離脱後は元の設定へ戻す**。マスターを引き継いだ場合はグループの行き先を維持し、自分の元の設定を適用しない (④への了承) |
| 個人の停止・降車 | 本人と本人の犬だけ離脱し、ほかの参加者は継続する。マスターの離脱時は次の参加者へ引き継ぐ |
| マスターの引き継ぎ | 参加順が次の人へ引き継ぎ、その時点の行き先を維持する。新マスターの元の個人設定には自動で切り替えない |
| 犬 | **犬なしでも利用可能**。連れるのは自分の接続犬。一台あたりの上限は配置と道幅を試して決める。既存の犬の総数や所有・接続ルールは変えない |
| カメラ | **新しい連携開発は不要**。ユーザー確認では現在の仕組みで問題なし。既存カメラを任意に利用する。カメラの対応端末拡張は本 Issue に含めない |
| 対応端末 | **マルチプラットフォーム・全端末**。カートは PCVR・PC デスクトップ・Quest 単体・Android / iOS のスマホを対象として設計・検証する。対応方針の決定であり、動作確認済みではない |

具体的な巡航速度・車間・最大台数・犬数・横並びの可否・端末別の性能合格値は、設計・試作・試乗で詰める。乗り場での合流操作、終了時の安全な降車や回収、受付切替と処理中の合流、乗車中のリード・撫で・おやつ、外観・広告の具体化も残る。乗り場から走行中のグループへ途中合流できる要件は維持する。

## 実装着手前に決める必須事項: すれ違い・既存移動との併用

2026-10-11 ユーザー指摘「この辺はほっといていいの？」を受け、対向するグループと乗車中のワープ・リスポーンは、試乗まで未整理のまま送らず、**実装着手前に利用ルール・状態遷移・失敗時の扱いを決める必須設計項目**とする。AI の前回答で「今決めたい4点」から外したのは優先事項の説明漏れ。①〜④への了承は、以下2案の採用を意味しない。

以下は AI の推奨案で、まだユーザー合意済みの仕様ではない。

| 対象 | 推奨する利用ルール | 設計で確定すること |
|---|---|---|
| 逆方向のグループとのすれ違い | 十分な幅があればすれ違い、狭い区間は先に入ったグループを優先。対向側は手前で穏やかに待機し、通れるようになったら自動再開する。車体・搭乗者・犬をすり抜けさせたり、利用者に運転操作を求めたりしない | 同時進入時の優先順位、待機場所、グループ全車と犬が抜けた判定、長時間待機や前方の停止車・徒歩利用者への対処。**交通上の自動待機は個人の停止・離脱操作と分け**、所属・目的地・マスターを維持する。速度や待機距離などの値は試作で調整 |
| 乗車中の既存地点ワープ・通常合流・リスポーン | 本人の移動を優先し、移動に伴って本人と犬のカート散歩を終了する。本人の座席・グループ参加を解放し、マスターなら残る参加者へ引き継ぐ。残りのグループは継続する | ワープの取消・失敗では不要に離脱させない適用時点、犬の移動と接続の既存規則との整合、移動完了後にカートへ引き戻されないこと、空車回収、同時退出や移動中断。強制的なリスポーン等でも後始末が成立することを別に確認 |

方式を決めた後は、逆方向2グループ・同時進入・途中停止・徒歩と犬の通行、および一般参加者/マスターそれぞれのワープ成功・取消・失敗・リスポーンを確認手順へ落とす。「確認項目へ追加済み」だけで設計解決とは扱わない。

## この Issue の範囲

設計判断をまとめる親 Issue として管理する。今回は起票のみで、実装・モデル制作・試乗は未着手。優先度 Medium は起票時の仮分類であり、制作順・初期公開への追加・公開日の変更を確定するものではない。

- 受領要件の「確定」は合意済みの体験方針として扱う。「暫定」「品質要件案」「受け入れ確認の基準案」を確定仕様へ繰り上げない。
- カート走行中の前方配置・くん活停止の抑制は、この乗車体験の要件。通常の自由な散歩まで常時整列へ変更しない。
- 既存の 6 匹・所有や選択のルールを前提に、一台あたりの犬数や複数台利用時の割り当てを設計する。人数分の犬の複製を暗黙に前提にしない。
- 個人停止・降車時の離脱と残りの継続、マスターの引き継ぎ、無料・全端末対応・既存カメラ利用は上記の追加決定を適用する。
- 速度・周回時間・最大規模・性能合格値は未決定。通常歩行で一周約 20 分という背景をカートの必須値にしない。
- コード・同期方式・経路計算・コンポーネント構成は後続のローカル設計で検討する。本票の起票で方式を固定しない。

## 受領要件 (2026-10-11)

以下は添付「Pasted text.txt」の全文。確定・暫定・未決定の区別を含め、受領時の内容を保持する。周回専用の前提・グループ運用・開始場所・到着終了・料金・カメラ・対応端末等は上記の追加相談と決定で更新しており、以下をそのまま最新仕様とは扱わない。

---


古民家の裏山に、犬と一緒に景色を楽しめる一人乗りの自動散歩カートを追加する。操作せずに過ごす一人の時間と、途中から合流したフレンドとの会話・ツーリングを両立する。

作成日：2026年10月11日。名称「おさんぽカート」は仮称。対象は体験・機能・品質の要件であり、コード、同期方式、経路計算、コンポーネント構成などの実装方法は別途ローカルプロジェクトで設計する。

「確定」はこの会話で合意した方針、「暫定」は整合性を取るための初期案、「未決定」は実装前または試乗後に決める項目を表す。暫定案を確定仕様として扱わない。

## 1 目的と利用場面

犬と森へ出かけ、座ったまま散歩の時間を楽しめるようにする。犬が引く乗り物ではなく、カート自身が進み、犬が一緒に歩く体験とする。

- 一人で作業しながら自動散歩し、ふと画面を見ると自分の犬と山の景色が見える。

- フレンドと会話しながら、操作に追われず一緒に進む。

- 先に出発している人へ後から合流し、複数人で連なってツーリングする。

- 気になる場所では止まって降り、犬と遊び、再び散歩へ戻る。

- 自動追従カメラと組み合わせ、犬・搭乗者・カートの隊列を撮影できる。

- カートの自然な掲示面で、課金アイテムやばにまるトレーナーの体験を知ってもらう。

通常歩行では一周約20分という現在の体験を背景とする。カートの一周時間は未決定で、20分を保証値や必須値にはしない。

## 2 合意した基本方針

| 項目 | 確定した内容 |
| - | - |
| 定員 | カートはすべて一人乗り |
| 移動 | 決まった散歩ルートを自動で進む |
| 速度 | 全員共通の巡航速度。利用者による速度変更は設けない |
| 周回 | 一周後も再操作なしで周回を続ける |
| 合流 | 出発時刻が違っても、散歩中の相手の近くに自分のカートで合流できる |
| 複数人 | 複数台で連なり、ツーリングのように過ごせる |
| 途中停止 | 自分の意思で止まって、その場で降りられる |
| 犬の見え方 | 搭乗者の通常の前方視界に、犬が自然に入る |
| 走行中の犬 | くん活による立ち止まりを抑え、散歩を続ける |
| 接触の見え方 | 犬をカートが巻き込む、車体が犬を突き抜けるような見え方を避ける |
| 撮影 | 自動追従カメラと組み合わせて楽しめることを想定する |
| PR | カートに課金アイテムやトレーナーの案内を置く場所を確保する |
| 快適性 | VRでの上下動・旋回などに配慮し、酔いに関する短い案内を用意する |

固定速度とは通常走行時の速度を指す。発進・停止時の穏やかな速度変化を禁止するものではない。

## 3 乗車から周回まで

- 利用者が自分の意思で乗車し、出発できること。勝手に乗せたり、移動を開始したりしない。

- 走行中は移動操作を続ける必要がなく、作業や会話に集中できること。

- 一周の終点で、再出発の確認・強制降車・毎周の演出待ちを挟まない。

- 周回のつなぎ目で不自然な飛びや向きの急変が起きないこと。

- 犬は搭乗者と一緒に移動し、途中で置き去りにならないこと。

- 正面以外も見回せること。自動走行を理由に視線を犬や進行方向へ強制固定しない。

- 利用者が止めたいときに、走行中でも停止操作へすぐアクセスできること。

暫定の基本操作は「出発・停止・降りる・合流する」とする。ボタン配置、乗車と出発の操作を分けるかどうかは未決定。停止後の再開も分かりやすく扱う。

## 4 合流と複数人での散歩

出発地点に戻ったり、次の周回まで待ったりせず、現在散歩している相手の近くへ自分のカートと犬で合流できること。合流先を利用者が識別し、選べること。

- 合流する人の到着のために、走行中の相手へ停止や再出発を強制しない。

- 合流後は同じペースと適切な間隔を保ち、時間経過で相手から離れ続けない。

- 他のカート、搭乗者、犬と重ならない空き位置に入る。

- 既に複数人で走っている場合も、その隊列に参加できる。

- カートだけでなく、それぞれの犬が歩く空間も含めて間隔を確保する。

- 想定するグループ人数では会話を続けられる配置にする。無制限に長い隊列全体の会話を保証するものではない。

- 既にワールドにいる人の途中合流と、インスタンスに後から入った人の途中合流の両方を扱う。

暫定案：道幅がある区間では横または斜めに並び、狭い区間では前後に連なる。常時横並びを必須にせず、景観・道幅・犬の空間・会話のしやすさを優先する。隊列変更で急な横移動が起きないようにする。

合流対象を同じインスタンスの誰まで表示するか、参加を受け入れる設定、隊列の最大人数、合流時の見せ方は未決定。「フレンドと利用する」という体験上の目的から、フレンド判定機能の存在を前提にしない。

## 5 停止と降車と再合流

自分の都合で止まり、周回の途中でもその場所で降りられること。降車先は、崖・川・障害物の内部などを避けた近くの立てる場所とする。

暫定案として、停止・降車は本人と本人の犬にだけ適用する。ほかの参加者は自動散歩を継続できる。隊列先頭の人が止まったり退出したりしても、残りの人が操作不能にならないこと。

- 個人の停止は隊列からの一時離脱として扱い、残る車両は重ならず進める。

- 降車後は、犬との普段の散歩・ふれあいへ戻れる。

- 再開時は、その場所から一人で散歩を再開するか、走行中の相手へ再合流できることを暫定案とする。

- グループ全員を止める専用操作は初期の必須要件に含めない。

- 空いたカートをいつ残す・片づけるか、再乗車までの扱いは未決定。

停止中の車両をほかの車両が通過する際も、犬や乗車中の人を突き抜ける見え方を避ける。停止可能地点や退避位置の詳細は、実際の道幅に合わせて決める。

## 6 犬の挙動と配置

最優先は、犬と一緒に散歩している感覚が続くこと。犬を見るために毎回大きく横や後ろを向く必要がない配置にする。

| 状態 | 挙動 | 状態の確度 |
| - | - | - |
| 自動走行 | 少し斜め前など、通常の前方視界に入る位置を歩く。くん活による停止をしない | 基本方針は確定。位置は要調整 |
| 停止して乗車中 | カートの近くで止まる。くん活を許可する場合も、他車の進路には出ない | 暫定 |
| 降車後 | 通常の散歩・ふれあいへ戻す | 暫定 |
| 再出発や合流 | 犬も対応する安全な位置に入り、置き去りや車体との重なりがない | 追加の品質要件案 |

- 犬が車輪・足元・車体の内部に入り込まない。

- 自分と他人の犬が、カートの直前を急に横切らない。

- 犬の歩行の見た目とカートの進む速さが合い、常に走って追いつく状態や足滑りが目立たない。

- 車体、広告、前走車によって犬が長時間隠れない。

- 曲がり角・坂道・停止・再開・合流時も、犬との距離が不自然に崩れない。

- くん活以外の自然なしぐさは、停止や進路逸脱を生じない範囲なら妨げない。新しいしぐさの追加は必須にしない。

一台が連れる犬の数、リードの表示や接続先、乗車中の撫で・おやつなどの可否は未決定。既存の犬の数や所有・選択ルールを、この要件書で変更確定しない。

## 7 走行ルートとVRでの快適性

秋の裏山をゆっくり眺める散歩に適したルートとする。通常の散歩道を基本に検討し、急坂・段差・狭い場所ではカート向けの経路調整を許容する。具体的なルート、分岐、周回方向は未決定。

以下はVR酔いを抑えるための品質要件案とし、実機試乗で調整する。一定速度や低速だけで酔わないことを保証しない。

- 細かな路面の凹凸を、そのまま視点の上下振動にしない。

- 坂の入り口・出口、カーブ、周回のつなぎ目で移動や向きが急変しない。

- 左右の揺れや車体の傾きを、演出のためだけに強く付けない。

- 視点の急な上下回転・横傾きを抑え、頭を動かして周囲を見回せる状態を保つ。

- 発進・停止は穏やかにする。ただし停止・降車操作への反応を不必要に遅らせない。

- 合流時に長距離を急加速して追いかける演出や、激しいカメラ移動を必須にしない。

- 身長・アバターサイズによって、視界が車体へ埋まったり犬が見えなくなったりしないよう確認する。

- 気分が悪くなったときは、容易に停止・降車して移動をやめられること。

乗車前に確認できる位置へ、短い注意書きを配置する。文案：「自動で移動するカートです。VR酔いを感じたら、停止して降りてください。」

案内を毎周表示することや、注意書きだけで快適性の確認を済ませることはしない。必要なら旋回区間などの速度調整を検討するが、利用者が選ぶ速度設定とは区別し、隊列全体の間隔を崩さない方針とする。この区間調整の採否は未決定。

## 8 カートの外観と広告

一人で座り、ゆっくり森を巡ることが伝わる外観にする。背もたれのある小型の電動カートを暫定の方向性とし、古民家や秋の山になじむ色と素材を検討する。車体の正式デザインや名称は未決定。

PR用の掲示面を、車体の設計段階から確保する。課金アイテムとばにまるトレーナーを紹介でき、後から内容を更新できること。

| 掲示候補 | 用途 | 状態 |
| - | - | - |
| 座席の背面 | 後ろを走る人に写真と短い紹介を見せる | 暫定 |
| 手元の小さなパネル | 本人が興味を持ったときに案内を開く | 暫定 |
| カート乗り場 | 写真つきで体験や特典を紹介する | 追加候補 |

- 犬と景色を見る正面の視界を、大きな広告で塞がない。

- 視線を強制的に向ける演出、点滅、大音量の広告を初期要件に含めない。

- 商品名だけでなく、犬とどんな時間を過ごせるのかが伝わる見せ方にする。

- 走行・停止などの操作と、広告の詳細表示を混同しない。

- 散歩中に広告を開くことや購入操作を行うことを必須にしない。

- 初期案は静止画と短文を中心にする。動画広告や広告専用カメラは必須にしない。

- 掲示内容と実際の価格・特典に食い違いがないこと。

カート自体を無料にするか、課金・トレーナー特典にするかは未決定。広告を置く方針は、カートの課金区分を意味しない。

## 9 自動追従カメラとの組み合わせ

自動追従カメラを利用する場合に、犬・搭乗者・カートが自然に一つの場面として映り、複数人なら隊列の楽しさが伝わることを目指す。

- 単独では、自分の犬と自分が散歩する様子を撮れる。

- 複数人では、犬とカートが連なって進む様子を撮れる。

- 撮影中も、自動散歩・会話・停止・降車を妨げない。

- カメラを使わなくても、自動散歩の体験が成立する。

- カメラは必要な人が任意で利用することを暫定案とする。

- カメラ越しでも犬が車体に隠れすぎず、広告が主役になりすぎない。

新たなカメラ機能を初回導入の必須条件にするか、既存または別開発のカメラとの連携に留めるかは未決定。カメラの方式・保存・配信・プラットフォーム別の可否は、この要件では確定しない。

## 10 性能と複数人利用の品質

容量、実行時メモリ、描画、移動処理、通信の負担を抑え、既存の散歩・犬とのふれあいを損なわないこと。軽量な構成を目指すが、容量増加やFPS低下の数値は実測して決める。

- 未使用のカートや未使用の撮影機能による継続的な負荷を抑える。

- カート本体と広告の素材は、複数台での共通利用を基本方針とする。

- 多人数が近くに集まり、カート・犬・アバターが同時に見える場面を評価対象にする。

- 一人では滑らかでも、隊列になると移動や犬の位置が大きく乱れる状態を避ける。

- 後からインスタンスに入った人にも、カートの利用状態や隊列が整合して見えること。

- 合流先が退出した、合流中に停止した、同時に複数人が合流した場合に、重複乗車・位置の重なり・操作不能を起こさない。

- 座席が取れない、合流先が利用できないなどの場合は、利用者に短く状況を伝える。

- 長時間周回しても、移動のずれや使用資源が際限なく増えないこと。

評価では同じ場所・人数・犬数・表示条件で、カート未使用／走行中／カメラ併用を比較する。PCVR・デスクトップ・Quest・スマホを評価候補とし、実際の公開対象に合わせて対応範囲を確定する。カートとカメラを一律に同じ対応範囲とみなさない。

最大台数、隊列人数、犬数、許容する容量・メモリ増加、目標FPSまたはフレーム時間は未決定。性能測定方法と合格値はローカルプロジェクトの基準に合わせる。

## 11 完成時に確認する体験

以下を受け入れ確認の基準案とする。数値を伴う合格値は、想定端末と人数を決めた後に補う。

- [ ] 一人で乗って出発し、操作せず一周以上進んでも自動周回が続く。

- [ ] 前方の自然な視界に自分の犬が入り、一緒に散歩していると感じられる。

- [ ] 走行中のくん活による停止がなく、犬が置き去りにならない。

- [ ] 後から来た人が、出発地点へ戻らせず走行中の相手へ合流できる。

- [ ] 複数人で走っても、時間経過で隊列の間隔が崩れず、想定人数で会話できる。

- [ ] 一人が停止・降車しても、ほかの参加者の散歩が継続する。

- [ ] 先頭や合流先の人が退出しても、残った人が移動・停止・降車できる。

- [ ] 犬が車体・車輪へ入り込まず、曲がり角や合流時にも不自然な接触がない。

- [ ] 途中で降りて普段どおり犬と遊び、再開または再合流できる。

- [ ] 坂道・カーブ・発進停止・周回のつなぎ目で、急な視点変化や細かな揺れが目立たない。

- [ ] 不快感が出たときに、停止・降車の操作へ迷わず到達できる。

- [ ] 案内が犬や景観を邪魔せず、課金アイテムやトレーナーの存在に気づける。

- [ ] カメラなしでも体験が成立し、併用時の性能差を把握できる。

- [ ] 公開対象の端末と最大想定規模で、既存の散歩体験を損なわないことを確認する。

試乗で酔いが出なかった場合も、すべての利用者が酔わないという保証や表記にはしない。

## 12 未決定事項と今回の対象外

| 決める項目 | 現時点の扱い |
| - | - |
| 巡航速度 | 犬の歩き、景観、VR試乗を見て共通値を決める |
| ルートと方向 | 安定して周回できる経路を選ぶ。周回時間は結果として調整 |
| 区間ごとの速度調整 | 快適性上必要な場合のみ検討。利用者の速度設定は設けない |
| 台数と隊列の上限 | 道幅、会話、端末負荷から決める |

| 合流の対象と受け入れ設定 | 表示対象、参加可否、選択方法を決める |
| 乗り場とカートの呼び出し | 配置場所、途中利用、空車の扱いを決める |

| カメラの導入範囲 | 初回必須か別途連携か、対応端末を決める |
| デザインと名称 | 小型の一人乗り電動カートを起点に検討 |

初期の必須機能には、複数人乗り、自由運転、利用者による速度変更、レース、犬による牽引、動画広告を含めない。将来の追加を決定したものでもない。
