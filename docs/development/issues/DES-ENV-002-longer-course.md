# DES-ENV-002 散歩コースの延長 (周回・川) とワールドの広さを決める

[体験会の記録](../../plans/2026-09-26-group-playtest.md) (2026-09-26、15 人) でのユーザーの要望:

- 散歩コースが短い。もっと長くていい。**周回コース**が欲しい。**川**が欲しい
- いまは 2〜3 分で終わるが、**10 倍くらい、20 分くらいかかるコース**があってもいい
- もっと広く。**ワールド自体を少し広くしてもいい**
- ただし**容量と FPS と関連で考える**必要がある。スマホでも快適だったので、それは保ちたい

## いまの前提 (変える場合はここで決める)

### 2026-09-27 追加相談と提案

- ユーザーの目標は **犬としっかり歩いて一周約20分**。寄り道・休憩込みなら30〜40分でもよく、何周も続けて楽しめる散歩にする。
- 今のルートを保全し、広場の裏から奥へ進み、右側の川沿いを小橋で渡りながら古民家側へ戻る構成を検討する。今回は完成品質までの変更計画を **案だけ** 提示する依頼。
- [HTML提案書](../../plans/des-env-002/index.html) / [現状調査と根拠](../../plans/des-env-002/survey.md)：実シーンを読み取り、既存113.8808m・17点を確認。提案は約1.81km、比較用外枠600×720m。平均1.5m/sなら約20分だが、実際のプレイヤーの歩行速度は未測定。
- 初回提示時点では未採用で、シーン・コードも未変更だった。続く相談で **周回構成を採用** した（下記）。寸法・性能予算の最終確定は実歩行と端末確認を待つ。下の「検討した案」は元の選択肢で、「短い周回から判断」を今回の合意に読み替えない。

### 2026-09-27 コース採用と軽量化の優先順位

- ユーザーがHTMLの周回構成を了承。犬が主役、景観は背景とし、現在程度の簡素さを許容する。美しさを多少落としても容量・処理負荷を優先し、Androidを含む16人参加・犬6匹での快適さを検証目標にする。
- 要所に犬と遊べる小さな発見を置く方向。内容は未選定で、新しい犬行動の実装を一括承認した意味にはしない。
- 川用の軽量シェーダーを検討。専用制作は必須とせず、既存品の適合確認後に判断する。不透明・流れ模様・色と岸の形を出発点に、VR両眼と各端末で検証する。
- 方針をcore-concept / game-designへ反映。容量・区画非表示の計画と代表区間の検証をHTMLへ追記。構成採用と実装済み・性能合格は区別する。寸法と性能予算、実装Issue化が残るため本Issueは対応中。

- 道は門前〜広場中心 113.9 m、通過点 17 (7 m 間隔) ([game-design §4 道と通過点](../../game-design.md#道と通過点-ウェイポイント))
- 2026-09-19 v4 でユーザー訂正: **円形の周回路は不要**。門から登る道と上部の遊び場 ([core-concept](../../core-concept.md) 記録)。今回の要望はこれを覆すので、決定として書き直す
- [core-concept](../../core-concept.md): 「小さな空間でも散歩した感じがする」が絶対に外せない体験の一つ。**広くすること自体は目的ではなく、散歩した感じを長く保つのが目的**
- [overview §1](../overview.md): スコープは広げない。景観の増量は後回し
- 提案時に参照した過去容量: 2026-09-24のAndroid 37.91 MB。最新再計測は下記の着手記録と [ビルドサイズ実測](../../plans/2026-09-24-build-size-audit.md) を参照。Terrain の拡張はハイトマップ・スプラット・木の配置で増える
- 負荷: Quest 単体・iOS の実機は未測定 ([VER-WLD-001](VER-WLD-001-quest-ios-devices.md))。体験会のスマホは「快適」の所感のみ

### 2026-09-27 着手承認後

ユーザーが実行を承認。記録は [コース拡張の計測と制作](../../plans/des-env-002/implementation.md)。現行シーンの最新容量はAndroid 42.75 / iOS 41.78 MiB（[容量の正本](../../plans/2026-09-24-build-size-audit.md)）。歩行設定は2m/sで、提案の1.81kmは一定速度なら約15分。20分の距離は犬連れの実歩行から詰める。

着手時は川の180m代表区間・小橋・軽量水面を本シーンのコピーに生成した。この段階では既存NavMesh/犬の経路とは未接続だった。その後の全周展開は末尾と [IMP-ENV-004](IMP-ENV-004-river-loop-course.md) を参照。本シーン/既存地形は保全している。ユーザー指定の確認端末はQuest 3単体とiPhone 15 Pro。16人・犬6匹の実機条件は [VER-WLD-001](VER-WLD-001-quest-ios-devices.md) に記録した。

## 検討した案 (構成採用前の履歴)

1. **周回**: 広場から別の道で門へ戻る (下り道)。往復と違う景色になり、犬の目的地は「広場」「入口」のままで済む
2. **長い散歩道**: 見晴らしの先に尾根道や谷道を足し、目的地を増やす (game-design §4 は目的地追加に対応できる構成)。20 分は歩く速さ 1.1〜2.4 m/s で 1.3〜2.9 km 相当。現行の 10〜25 倍で、Terrain の面積・木・NavMesh・通過点がそれに応じて増える
3. **川**: 沢を道沿いに置く (見た目 + 音、[DES-WLD-002](DES-WLD-002-sound.md))。水面シェーダはモバイルで軽いものに限る。犬の水遊びは範囲外 (犬の行動を増やさない)
4. **段階**: まず周回 + 短い川で「散歩した感じ」が伸びるかを PCVR で見てから、長いコースを判断する
