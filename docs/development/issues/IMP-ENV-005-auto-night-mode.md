# IMP-ENV-005 時間経過のナイトモードとオート／マニュアル切替

2026-09-29 ユーザー依頼。入室後の時間経過で徐々に暗くする。既存のナイトモードのスライダーと描画を活用し、設定画面のナイトモード欄でオート／マニュアルを選べるようにする。

## 要件

- **オート**: インスタンス内で共通の時間経過・暗さをグローバルに同期する。途中参加者も、その時点の共通の暗さに合流する。
- **マニュアル**: 既存スライダーで自分の見え方だけをローカルに調整する。他人の暗さや共通の時間経過を変更しない。
- モードの選択は個人単位。同じインスタンスにオートとマニュアルの人が混在できる。
- マニュアルからオートへ戻ると、現在の共通の時間経過へ復帰する。個人の入室やモード切替で共通の時計をリセットしない。
- 既存の空・乗算オーバーレイによる連続的な暗さ表現を再利用する。

## 実装前に決めること

- 「入ってから」の時間の起点。**最初の参加者の入室を共通の開始時点にする案**を候補とし、各自の入室時刻から別々に進める方式とは区別する。ユーザー指定の起点としてはまだ確定しない。
- 暗くなる所要時間、開始と到達時の暗さ、変化の仕方。夜で止めるか、昼夜を循環させるかも未決定。
- 初回のモード、モードの保存有無、再入室時の扱い。既存の個人の暗さ保存値をどう引き継ぐか。
- オート時のスライダーの表示・操作可否、モード切替時のフェードとマニュアル値の復元。
- 共通時計の管理主体と引継ぎ。管理者の退出・Owner交代・途中参加でも進行が巻き戻らないこと。
- 既存のライブ暗転入力との優先関係。通常のオート／マニュアルとライブ演出が競合しない契約にする。

## 既存実装と範囲

- `Assets/KominkaHillside/Scripts/KH_NightMode.cs` はローカル描画と暗さの PlayerData 保存を持つ。オートの値で個人の保存値を上書きしない設計を検討する。
- 設定面のスライダーは [IMP-UI-001](IMP-UI-001-menu-table-driven-and-settings.md) で実装済み。本Issueはその拡張。
- [初期のナイトモード記録](../../plans/2026-09-21-sky-and-night-mode.md) の OFF/ON・保存なしは初期仕様。現在のスライダー実装と区別する。
- 実装時に [仕様](../../game-design.md) と [UI仕様](../../world-ui-spec.md) の関連箇所を更新し、既存のローカル専用という記述との整合を取る。
- 今回はIssue登録のみ。昼夜に伴う犬の行動変更は含めない。

## 設計案 (2026-09-29、AI 下書き・未決定)

### 事実 (コードで確認)

- `KH_NightMode` は Sync None で、同期変数は 0 本。表示する暗さは `max(手動のフェード × onDarkness, liveDarkness)` で、空 (`_Exposure` / `_Tint`) と全画面の乗算オーバーレイを書くのはこの 1 か所だけ
- 設定のスライダー (`KD_MenuSettings._NightMode`) は `_SetDarkness(0..1)` を呼ぶ。値は PlayerData `KH_NightMode.dark` に保存し、`OnPlayerRestored` で戻す。復元前に操作していれば、その操作が優先される
- フェード (`fadeSeconds` 3 s) は OFF⇄ON の切替にしか掛からず、ON のまま値を変えると即座に変わる
- `KH_LiveNight` は同期変数を持たず、同期済みのライブの時計 (`KD_LiveSystem.startMs` をサーバー時刻と比べる) の純関数として `liveDarkness` を毎フレーム書く。途中参加者もその時点の暗さから始まる。ライブ終了後は 3 s で 0 へ戻る

### 推奨案 (R)

- **時間の起点**: インスタンスの最初の参加者が入った時刻 `epochMs` (サーバー ms) を 1 本だけ同期する。各自の入室時刻からは数えない
- **暗さの形** (仮値。実機で決める): 入ってから 10 分は昼 (0)。そこから 30 分かけて smoothstep で 0 → 0.8 へ進み、**夜で止める** (循環しない)。上限を 1 でなく 0.8 にするのは、道・犬・メニューを読める余地を残すため
- **同期の仕組み**: 新しい部品 `KH_AutoNight` (Manual、同期 int 1 本) を足す
  - 各クライアントが毎フレーム `f(サーバー時刻 − epochMs)` を計算し、`KH_NightMode.autoDarkness` に書く (`KH_LiveNight` と同じ形)
  - 暗さそのもの・進み具合・誰がオートかは同期しない。`vrc-networking` §6「出力が同期済み入力の純関数のときだけ各自で計算」に当たる
  - Owner は既定 (マスター) のまま、SetOwner は呼ばない。`epochMs` を書くのは「Owner で、値が 0 で、インスタンスに自分 1 人」のときの 1 回だけ。`Start` 内ではなく、自分の `OnPlayerJoined` の後に書く (§5「Start の RequestSerialization は届かない」)
  - Owner が交代しても値はそのまま残るので、時計は巻き戻らない。途中参加者は受信するまで 0 (昼) を表示し、受け取ったら 3 s で合流する
  - サーバー時刻の差は int の減算で取る (約 24.8 日の一周に耐える。`KD_TreatBox.EarlierMs` と同じ扱い)
- **表示**: `Darkness = max(mode == Auto ? autoDarkness : manual, liveDarkness)`。ライブとは今と同じく強い方を取る。ライブが終わると 0 ではなくオートの値へ戻る
  - オートがライブの上限より暗いと、ライブの暗転は見えなくなる。ライブ中だけオートを止める案は、夜にいた人をライブの開始で明るくしてしまうので採らない
- **初期値と保存**: モードは PlayerData に新キー `KH_NightMode.mode` で保存する
  - キーが無い人 (初回・既存利用者とも) はオートで始める
  - 既存の `KH_NightMode.dark` はマニュアル値としてそのまま使う。オートの値では上書きしない
- **切替**: 設定のナイトモード欄に [オート][マニュアル] を置く
  - オート中のスライダーは共通の値を表示するだけ (淡色)。触るとマニュアルへ切り替わり、その値になる
  - 切替時は表示値を 3 s かけて寄せる。今は値の変化が即時なので、表示値を平滑化する処理を足す
  - マニュアル→オートは、その時点の共通の暗さへ寄せる (時計はリセットしない)

### 代案 (S)

- **形**: 昼夜を循環させる。例は 60 分周期 (昼 25 分 → 夕 10 分 → 夜 15 分 → 明け 10 分)。長く滞在しても昼へ戻れるが、「入ってから暗くなる」の読みは弱くなる
- **初期値**: 既定をマニュアル (現状どおり) にし、オートは選んだ人だけ。既存の見え方を変えないが、共通の夜を体験する人が減る
- 同期の仕組み (`epochMs` 1 本の純関数) は R と同じ。S でも同期変数は増えない

### ユーザーに決めてもらう点

1. 夜で止める (R) か、循環させる (S) か
2. 所要時間の仮値 (昼 10 分 + 夕暮れ 30 分) と到達時の暗さ (0.8)
3. 初回のモード: オート (R) か、マニュアル (S) か
4. オート中にスライダーを触ったら、自動でマニュアルへ切り替えてよいか (R)。それとも、オート中はスライダーを操作不可にするか

関連: game-design §4「夜の散歩」は「ナイトモードはローカル・非同期なので犬の行動は変えない。同期される夜が入ったら再検討」としている。オートは同期される夜に当たるが、本 Issue は犬の変更を含めない (上の既存記述どおり)。

決定: 2026-10-02 (ユーザー決定) オートナイトモードは初期公開に入れる。「ユーザーに決めてもらう点」4 件は未回答。

決定: 2026-10-02 (ユーザー決定) 「ユーザーに決めてもらう点」4 件はすべて推奨案 (R): 夜で止める、所要時間は昼 10 分 + 夕暮れ 30 分・到達時の暗さ 0.8 (仮値)、初回のモードはオート、オート中にスライダーを触ったら自動でマニュアルへ切り替える。

## 実装 (2026-10-02)

- 推奨案 (R) のとおり。`KH_AutoNight` (新規、Manual 同期、同期変数は開始時刻 `_epochMs` の 1 本) が共通の時計を持ち、各クライアントがサーバー時刻との差から暗さを計算して 1 秒ごとに `KH_NightMode.autoDarkness` へ渡す。表示は max(オートなら共通の値 / マニュアルなら手動値, ライブの暗さ)
- 時計を書けるのは Owner だけで、値が 0 のときに 1 回。書ける条件 = インスタンスの最初の 1 人 / この時計の状態を受信済み / 通信が落ち着いた (`IsNetworkSettled`) のどれか。満たさなければ 5 秒ごとに待ち直し、120 秒届かないときだけ新しく始める (Codex の指摘: 未受信の新 Owner が時計を書き直して夜が昼へ巻き戻る経路を塞いだ)
- 保存: 新しい PlayerData `KH_NightMode.mode` (0 オート / 1 マニュアル、無ければオート)。既存の `KH_NightMode.dark` は手動値だけで、オートの値では上書きしない
- 設定画面: ナイトモードの行に [オート] [マニュアル] と注記 (13 言語、3 キー)。オート中にスライダーを触るとマニュアルへ切り替わる。切替・途中参加の到着は 3 秒のフェード
- メニュー: `Night/1 Setup Sky And Night` (2 回)、`Menu/15 Setup Night Mode`、`Menu/19b Assign Network IDs`。検査 `Night/2` 46/46、`Menu/15a` 41 PASS / 0 FAIL、`Menu/22` 9363 PASS
- ClientSim `Course/83c` (run 20261002-120527) N0〜N7 PASS = 初回はオート、時計どおりに暗くなり 0.8 で止まる、マニュアルは時計を無視、スライダーでマニュアルへ、マニュアル → オートはフェードで共通の値へ、途中参加の合流 (疑似)、未受信の新 Owner は書かず届いた時計を使う (疑似)、ライブは強いときだけ勝つ (疑似)
- Codex 独立レビュー: 高 1 (上の巻き戻り) と検出できないテスト 1 件を反映。モードと保存・ライブとの合成・性能・呼び出し権限・ビルダーと翻訳は指摘なし
- 未確認: 実通信の 2 人 (同じ暗さ、途中参加、Owner 交代・退出)、再入室での復元、暗さ 0.8 での道・犬・メニューの見やすさ、11 言語のボタン文字の収まり、Quest 単体・iOS
- 仕様上の制限: 起点は「最初の人が入って約 2 秒後に書いた時刻」。インスタンスが約 49.7 日続くと差の計算が折り返す
