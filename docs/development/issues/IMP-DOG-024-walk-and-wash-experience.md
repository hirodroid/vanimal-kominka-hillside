# IMP-DOG-024 散歩帰りの犬のお手入れと複数の洗い場

2026-09-30ユーザー要望。**犬と出かける → 一緒に遊ぶ → 汚れる → 帰ってくる → きれいにしてあげる → また一緒に過ごす**までを、裏山の一続きの体験として作る。Animal Washの先行実装は参考にし、洗う気持ちよさ・犬の反応・汚れの見え方を中心に、裏山用の体験と実装を一から設計する大型Issue。

起票時点の成果はIssue化と方針整理。2026-10-02時点の実装・検証状況は下記の子Issueを参照し、当時の未着手という記録と区別する。以下の「採用方針」と日付付きのユーザー決定は確定した方針。「設計案」「比較すること」は方式や調整値の確定を意味しない。仕様の境界は[game-design](../../game-design.md)、体験の判断基準は[core-concept](../../core-concept.md)、公開目標は[開発全体像](../overview.md)を正本とする。

## 背景と狙い

Animal Washで弱かった「なぜ洗うのか」「洗ったあと何をするのか」を、犬との散歩が自然につなぐ。裏山を体験したフレンドの「散歩帰りに足をふきふきできたらいい」という反応も、ユーザーから共有された。帰ってきた犬を世話する時間を、散歩の締めとして成立させる。

成功は点数や作業量ではなく、自分の手入れに応じて犬がきれいになり、犬の反応を見て「世話をしてあげた」と感じられること。将来の独立作品Animal Washに向けた実地検証にもなるが、そのための大型基盤は今回の成立条件にしない。

### 最優先の品質目標はASMR的な洗浄の気持ちよさ

**2026-10-02 追加要望:** こすると泡がバーッと広がり、シャワーではサーッと流れるテンポを強める。肩・関節に泡がしつこく残る症状を改善し、周囲が流れたら残りの泡も自然に流れてよい。細かい残りを狙い続ける手間より、快適にすすげることを優先する。症状・原因の仮説・改修後の確認条件は [IMP-DOG-025](IMP-DOG-025-wash-prototype-one-dog.md) の「最新の体験改善要望」に記録する。修正・検証は未実施。

**同日の追加ユーザー指定：今回最も重要なのは「むちゃくちゃ洗うのが気持ちいい」と感じること。洗浄の核に絞るぶん、その核はAnimal Washの先行実装以上を目指して磨く。** 機能を少なくすることと、洗う表現の品質を簡素に済ませることを混同しない。

中心となる感覚は、**泡をつけて犬がもこもこになる → 水を当てると接触が分かり、飛沫が跳ね返る → プシューと泡と汚れが一緒に流れ、きれいな毛が現れる**という連続した変化。泡を増やす過程そのものにも満足感を持たせ、最後に清潔状態へ切り替わるだけで終わらせない。ASMRは音だけを指さず、見た目・音・操作への反応が同じ場所・同じタイミングでつながる品質目標として扱う。

| 核となる瞬間 | 求める品質 | 試作で見ること |
|---|---|---|
| 泡でもこもこにする | つけた所に泡が育ち、厚み・柔らかさ・蓄積が分かる | 単に犬を白く塗るだけにならず、操作した場所から泡立つ気持ちよさがあるか。顔と犬らしさも読めるか |
| 水を当てる | 噴射と着水の違いが分かり、水が犬に当たった手応えがある | 接触位置に飛沫・跳ね返りが出るか。空中に噴射している時と、犬へ当てた時の見た目・音が対応するか |
| 泡と汚れを流す | 水を動かした跡から泡が崩れ、きれいな毛が帯状に現れる。汚れた犬では泡と汚れが一緒に流れる | ゆっくり横へ流した時に、泡ときれいな毛の境目が操作についてくるか。部位全体の瞬時切替だけにならず、清潔な犬への再洗浄でも泡を流す楽しさがあるか |
| 洗う音を聴く | 噴射音と犬への接触音を聞き分けられ、泡に当たる・泡が流れる・毛に水が当たる変化が操作と対応する | 開始・継続・停止が自然で、川音・BGM・隣の洗浄音と重なっても自分の操作の音と会話を聞き取れるか。長い再洗浄でもループや反応音の反復が気にならないか |

方式・粒子数・音素材・音量・反応時間は未決定。コントローラー振動は入力機器に応じた補助手段の候補とし、振動のない端末でも見た目と音で接触を理解できるようにする。犬のリアクションは、小さな反応だけでは分かりにくいため、**分かりやすいコミカルな反応も適宜入れる**（2026-09-30ユーザー決定）。動きと声の頻度・強さは、反応を楽しめて洗う対象・音も追えるように調整する。

**採用した評価順（2026-09-30レビュー後）:** 代表1匹・主洗い場を中心に磨き、同じ試作段階で動く足か尻尾・コミカルな反応・2人利用を組み合わせて確認する。方式を固定する前に白い毛・暗い毛・小型犬にも簡易表示し、対象端末で早期確認してから6匹・複数地点へ展開する。全地点に薄い仮実装を広げただけでは品質目標の達成にしない。先行Animal Washの比較対象の版・体験場面を試作前に選び、同程度の汚れで泡立て→水の接触→すすぎを短く繰り返して比較する。良くなった点と違和感をユーザー評価で記録し、命中と変化の対応・所要時間・端末負荷の結果と分ける。比較の体験確認は未実施であり、「先行作以上」は現時点の達成報告ではない。

## 採用方針と今回の範囲

- 既存の同じ6匹を使い、散歩による汚れとお手入れを初期公開の開発対象に加える。
- 基本体験は無料。課金設計を待たずに進める。
- **1匹を1〜2分で十分きれいにでき、その後も自由に洗い続けられる**体験を目標にする（2026-09-30、推奨案をユーザー採用）。時間は体験の調整目標であり、強制終了や時間経過だけで自動洗浄する条件にはしない。
- **きれいな犬にも何度でも泡をつけて洗える**（同日、推奨案をユーザー採用）。汚れるのを待たずに泡立ち・すすぎ・反応を楽しめるようにし、清潔になったことと遊びを終えることを分ける。
- **同じ犬を友達と2人で一緒に洗える**体験を初期範囲へ採用（同日のレビュー推奨案をユーザー採用）。1人でも一通り手入れでき、2人なら泡付けとすすぎなどを自然に分担できる。専用の役割選択や協力ボーナスは加えない。2人を超える同時操作数や道具数は設計・負荷確認で決める。
- **道具と手順は自由に選べる。** 足だけふいて終える、水から始める、すすぎ途中に泡を足すことを認め、全工程の順番を強制しない。泡立て→すすぎを最も豊かな洗い心地として作る。足ふきを別の進行ミニゲームにすることは前提にしない。
- 想定する一周は、汚れる → 手入れを始める → 泡をもこもこにつける → こする・洗う → 水で泡と汚れを一緒に流してきれいにする → タオルやブルブルなどで仕上げる → 犬が反応する。汚れが落ちる主な見せ場はすすぎとし、こする段階との内部処理の配分は設計で決める。反応は終了時だけでなく、手入れ中の手応えとしても検討する。
- 主洗い場は**古民家の門の外、現在犬たちが集合し、リード用の設備が置いてある辺りを整備する**（同日のユーザー補足）。川辺・広場（公園的な遊び場）・裏山にも複数ポイントを作る方向。同じ洗浄処理を使い、場所ごとに別システムを作らない。各設備の座標と道中ポイントの最終的な数・位置は導線・負荷・制作量を見て決める。
- 洗浄スコア・評価、図鑑、複雑な成長、大型ゲームシステム、大量のアンロック、洗浄関連の課金商品は今回の対象外。
- 公開後の特別なシャンプー・泡や水の演出・タオル・洗浄後の装飾や遊びは将来案。基本体験を壊さない追加として別途判断する。

## 採用した体験と残る調整

| 場面 | 目指す手応え | 比較・決定すること |
|---|---|---|
| 散歩して汚れる | 散歩や土・泥での遊びが新しい汚れの理由になる。洗った後、普通に過ごす間は清潔な余韻を楽しめる | 汚れる場所・行動・速さ・上限。洗い場から数歩歩いただけで汚れ直さない条件を調整する |
| 足をふく | 短い散歩でも気軽に足だけふいて終えられる | 全工程は必須にしない。ふく範囲・判定・見え方を調整する |
| 泡をつけてこする | 手や道具を動かした場所がもこもこになり、泡の見た目・音・犬の反応が返る | 道具、接触・移動の条件、部位単位と局所表現の粒度、反応の強さと頻度 |
| 水で流す | 水の接触と跳ね返りを感じ、泡と汚れが一緒に流れてきれいな毛が現れる | 汚れ・泡・濡れをどう区別するか。流れる途中の表現、噴射と接触の音、水だけで落ちる汚れの範囲 |
| 仕上げる | 普通に洗った見た目の満足感と清潔判定を合わせ、短い満足げな仕草などで「もう十分きれい」を知らせる。続けて洗うこともできる | タオルとブルブルの役割、濡れの解消、区切りを知らせる仕草と再発火の条件。小さな汚れ探しや長い演出で拘束しない |
| また過ごす | 撫でる・休む・散歩へ戻る行動が自然につながる | 終了・中断時の自由行動復帰、道具を戻す方法、次に汚れるまでの猶予 |

**採用方針:** 汚れを罰や洗浄義務にせず、洗わなくても散歩や遊びを続けられるようにする。こすり続けるだけの単調な待ち時間や、落ち残りを探す作業を中心にしない。1〜2分で十分きれいにできる採用目標に合わせ、具体的な手間・部位数・変化の速さを代表1匹で体験して調整する。再洗浄のために清潔な犬へ泥を付け直す必要はない。

**コミカルな反応の置き方:** 洗浄中は首をかしげる・足を上げるなど、その場で分かる反応を返す。水を止めた瞬間や仕上げには全身ブルブルなどを目立たせる。これらは採用した演出方針の例で、具体クリップ・きっかけ・頻度は試作で調整する。狙っていた部位を追いかけ直す作業にせず、すすぎ前に泡をすべて落として見せ場を奪う反応や、同じ反応の連発を避ける。

汚れが落ちる見た目と実際の判定を対応させる。「当たっているのに落ちない」「触れていない遠い場所だけが消える」を避ける。白・黒・茶の毛色と体格差を確認し、汚れや泡で犬の顔・表情・毛の特徴を隠しすぎない。

## 洗い場と散歩の導線

| 候補 | 役割 | 設計時に確かめること |
|---|---|---|
| 古民家の門の外にある犬の集合場所・リード設備付近 | 帰ってきて世話をする主洗い場。既存の屋外スペースを整備し、最初に一周を試作する場所 | 集合・リードの取り出し・散歩への出発を妨げない配置、犬と人が立てる足場、道具の置き場 |
| 川辺 | 道中の水遊びと手入れをつなぐ | 安全な岸、既存の入水・泳ぎ・回収との切替。川に入っただけで洗浄完了にするかは未決定 |
| 広場・公園的な遊び場 | 遊んだ後に気軽に手入れできる | おもちゃの回収範囲との干渉、道具の発見性と戻し先 |
| 裏山の要所 | 長い散歩の途中でも手入れを選べる | 利用する理由、傾斜・犬種別の届きやすさ、他の洗い場との間隔 |

場所を増やしても操作と状態の意味は同じにする。水の出方や小物などの差は設定・配置で表現する案を優先する。共通化で制作の重複は抑えられるが、道具・描画・同期・同時利用の負荷まで一定とは見なさない。

初見でも道具を取ってすぐ洗い始められる配置とし、リードから手を空ける動作も含めて確認する。集合スペースに隣接して洗浄道具をまとめ、犬の横へ回れる余白と見える戻し先を用意する。洗い場整備は本Issue、[スポーン・ポータル周りの手動調整](IMP-ENV-003-spawn-and-dropped-portals.md)は別件。手動調整済み配置との干渉を確認し、同Issueのholdを一括解除しない。

**洗い場はすべて門の外の話であり、古民家の中へ入る必要はない**（同日のユーザー補足）。古民家の建物は遠景専用のまま、山から見返せる構図も維持する。建物への接近・室内導線の新設をこのIssueの課題にしない。**初回の設計案は裏山ワールド内で一周を完結させる。** 別ワールドの古民家へ移動して汚れを持ち越す機能は前提にせず、[古民家との往復導線](DES-WLD-001-round-trip.md)とは分ける。

## 方式を決めるための比較と検証

- **汚れと洗浄判定:** 部位ごとの段階表現と、局所的なマスク表現などを比較する。見た目と接触の一致、体格・毛色差、動く部位への追従、制作工数、実機負荷で選ぶ。到達できない箇所を完了計算に含めず、全対象部位を手入れして終えられることを確認する。
- **犬の反応:** 手入れ中の反応と仕上げの反応を分け、小さな反応に加えて分かりやすいコミカルな反応を適宜入れる。具体的な動作・きっかけ・頻度は試作で決める。既存の撫で・歩行・水遊びのAnimator制御と両立させる。使えるクリップの棚卸しを行い、必要なら新規制作する。反応によって道具が当たらなくなる問題も調べる。
- **入力と姿勢:** PCVRだけでなくDesktop・Touchでも、自分が狙った場所から泡と汚れが変わる気持ちよさを確保する。座位・片手・ゆっくりした操作で楽しめる入力案を用意し、高速で正確な往復動作を成功条件にしない。小型犬の足や大型犬の背中に無理なく届く位置・姿勢を試す。
- **既存行動との切替:** リード、散歩、Fetch、集合、水遊び、呼び戻し、ワープとの優先順位と中断・復帰を決める。他人が連れている犬を一方的に洗い場へ拘束しない扱いを設計する。
- **共有状態と同時利用:** 同じ犬への2人協力洗浄を前提に、犬の汚れ・泡・濡れ・使用中の状態を誰が確定するか、何を共有するかを決める。同じ箇所への泡付けとすすぎが重なる場合の優先・見え方、別地点での別の犬の手入れ、道具の所有・復旧、途中参加、Owner交代、利用者退出を扱う。犬の既存Owner権威を崩さない。犬のOwnerでない人が操作した時も、接触の手応えと共有された結果が対応することを代表試作で確認する。
- **自由な操作と状態:** 汚れ・泡・濡れを分けて考え、各状態へ泡・水・タオルを使った結果を小さな表にする。清潔になると泡がつかない、泡をつけ直すと泥が戻るなどの矛盾を避け、清潔判定と手入れを終えて犬を解放する条件を分ける。データ形式は方式比較後に決める。
- **保存とリセット:** インスタンス内で状態を保つ範囲、洗い場移動、再入場、リセット時の扱いを決める。汚れの永続保存やワールド間共有を当然の要件にしない。

実装前に `vrc-character-rig`・`vrc-udonsharp`・`vrc-networking`、小物制作・シーン配置時に該当Skillを読む。ここでは技術方式を確定せず、比較結果を記録してから実装項目へ分割する。

## パフォーマンスと容量

既存モデルと共通の洗浄処理を使い、大容量の犬種別テクスチャを大量追加しない。泡・水・汚れのParticleやShaderは体験に必要な範囲に絞る。**泡のもこもこ・接触・跳ね返り・すすぎの変化は今回の中心価値**なので、軽量化ではまず方式・同時実行・距離による制御などを比較し、その手応えが残るかを確認する。方式ごとのPC・Quest単体・スマホでの可否と見え方を調べて選ぶ。

**追加負荷を小さくできるという見込みは未検証。** 容量だけでなく、犬6匹＋Terrain＋植生の本番環境で、未使用時／1か所使用／複数地点同時使用を比べる。計測前に同時使用数・許容する追加負荷・画質・参加者とアバター表示条件を定め、CPU/GPUフレーム時間・メモリ・描画負荷・ビルドサイズ差分を記録する。既存の16人検証目標とも合わせる。
