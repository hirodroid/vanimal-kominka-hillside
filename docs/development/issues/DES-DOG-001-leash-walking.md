# DES-DOG-001 リード散歩の操作・行動・同期を設計する

根拠は [後から受領した企画資料](../../reference/VAnimal_KominkaHillside_Walking_Addendum.md) と受領後のユーザー決定。現行仕様は [game-design.md](../../game-design.md) §4〜6、履歴は §8。基本散歩は実装済みでPCVRの体験評価を受領。現在はメニューとの連携、集合、拠点への道具回収を設計中。実装値は最終仕様・全端末検証済みを意味しない。

## 進め方

2026-09-23 分担更新: 既存の飾り・屋外休憩・追加トレーナー機能を裏山へ持ち込むかという採否相談とメニュー全体の構成は [DES-UI-003](DES-UI-003-menu-scope-and-polish.md) へ集約する。本Issueは採用後の犬の挙動・リードとの競合・権限、おしゃれの種類や保存等の詳細を担当する。以下の初期対象を決める項目はDES-UI-003の採否と連動させ、別々に決定しない。

1. 基本散歩の移植結果を土台に、古民家の集合・呼び出し・終了処理と権利確認を調べ、裏山で必要な差分を整理する。移植済み範囲はIMP-DOG-001の記録を参照する。
2. リードの先端を手に持って犬の首輪に取り付ける体験を前提に、成立判定・入力、左右の割当、解除・状態表示を VR・デスクトップ・スマホそれぞれで設計する。手が追跡されない環境の基準点も決める。
3. リード長・範囲内の動き、自由行動の境界・帰還、高速移動・段差・障害物への対応を決める。目的地と通過点による自由な散歩の合意はgame-design §4を正とし、初期目的地・追加接続・解除/再接続/接続者交代時の保持、誘い・犬同士の遊びの終了/中断・他行動との優先順位を具体化する。
4. 同じ犬の選択競合、接続中の Fetch 可否・解除要否、呼び出し・集合の優先順位を決める。
5. 接続状態の管理主体、既存移動処理との責任分担、接続者退出・Ownership 変更・途中参加の契約を決める。目的地指定は自分の接続犬だけに適用し、要求中の接続変更の再判定・犬ごとの目的地復元・じゃれ合いの相手/開始/終了の裁定も扱う。犬同士の相互作用を裁定する主体と移動Ownerの整合を設計し、各クライアントで独立抽選しない。接続者を犬の Owner とする方式を先に固定しない。
6. 首輪・リードの種類・選択・保存・公開範囲・解放条件、既存の飾り・屋外休憩・トレーナー機能の初期対象を決める。
7. PC・Quest 単体・iOS の 6 匹散歩・複数人利用の性能予算と検証手順を決める。

## 2026-09-20 追加相談と実装調査

2026-09-20追加合意は [game-design §4「集合と拠点のリード」](../../game-design.md) を正とする。集合は接続犬を自他とも除外し、終了後の参加犬の自由行動の中心を集合場所へ更新する。各目的地のローカル取り出し口と解除後の道具回収を設計対象に追加する。

実装調査: `KH_LeashClip` は既にローカルPickup。`KH_LeashCollar.PostLateUpdate` → `KH_LeashManager._OfferTip` → `KH_LeashClip._OfferAt` が解除地点を道具の戻し先にしているため、地面に道具が残る。拠点回収への変更箇所はこの経路。犬の解除後の自由行動の中心は `KH_LeashManager.releasedHomes` が同期管理しており、集合終了側と更新責任を揃える必要がある。コードは未変更。

最寄りの利用可能な拠点への回収は追加了承済み。距離計算・拠点不在などの実装詳細は下表に分ける。

## 決定した論点と残る実装詳細

Q1〜Q5へのユーザー回答はgame-design §4へ反映済み。Q1は古民家同様の1分制限を採用し、無期限の手動終了案は不採用。Q2は集合中の接続/Fetch割込を禁止。Q3は追加犬への行き先継承、Q4は近距離のメニュー接続・距離不問の自己解除、Q5は歩行集合・到達不能時の障害物すり抜けを採用した。少数参加は空席を残し、斜面でも集合する。

古民家の調査根拠: `Assets/KominkaDogRun/Scripts/KD_GroupActivities.cs` の `Handle` は開催受理時に `startedMs` を設定し、`Mode` は経過60秒未満で有効。途中終了は開催者または `live.CanManageNow` の対象者が要求でき、開催者退出でも終了する。`Offset(shape, dogIndex)` は6匹の固定枠で、`ValidPlacement` は地面法線 `.9`・基準高との差 `.25m` を制限している。時間/空席は継承し、斜面配置の高さと判定は変更する。古民家と同じ隊形でも斜面対応まで移植済みとは扱わない。

### 開発側で具体化すること

| 項目 | 次の作業・観測条件 |
|---|---|
| トレーナー権利 | 同一Product/Listingを使う方針・調査結果はworld-ui-spec §6。両ワールドの購入入口・権利取得と読込失敗/期限の扱いを配線し、購入済みの双方向認識を実機確認する |
| 隊形と斜面 | 固定枠・空席保持は確定。参加枠の地表高さへ配置し、0匹なら開始不可。地面なし/場外の拒否、歩行中の地形追従、斜面の立ち姿を確認 |
| 到達不能時の救済 | 障害物すり抜けは確定。停滞を検出する時間・移動速度・経路・地表復帰を試作し、開始から60秒以内に移動と整列がどう見えるか確認。時間切れ/取消/退出では移動を止め、到着前の犬の自由行動の中心を到達済み地点の安全な地表へ置く実装案を具体化する |
| 行き先の選択保持 | 追加犬への継承は確定。同じ滞在中は全解除後も本人の選択を保持、再入室/未選択時は広場とする実装案。接続者交代時は新しい接続者の選択を使う。受理時の対象・接続変更・古い要求の扱いを定義する |
| 集合と共有状態 | 別集合禁止・集合中の接続禁止・古民家同様の終了は決定済み。受付時の接続状態再判定、同時要求の裁定順、終了の反映、Owner交代時の復元、到着済み/移動中の犬の取消処理、自由行動の中心の書込者を具体化。旧releasedHomesによる巻き戻りを防ぐ |
| 最寄り拠点 | 歩いて使える拠点を候補に、斜面/折り返しで直線距離が不自然にならない選定を具体化。同距離は固定順、候補なしは道具回収と接続解除を分ける案で検討。拠点追加と道の途中からの回収を検証 |
| ローカル道具 | 1人が同時に持つ道具数、再Interact、接続成功・未接続Drop・タイムアウト時の戻し先を定義。各拠点の取り出し口が他人の利用で消えないこと、既に握った道具が別の犬の解除で移動しないことを確認 |

| 検証の出口 | game-design §6の11・12を具体化。未接続犬の集合→終了→自由行動→接続→散歩→解除→最寄り拠点回収を、2人と途中参加で確認。実装Issueは契約確定後に採番 |

2026-09-20 実装 (Editor 検査済み): 上表のうち、行き先の選択保持 (本人のローカル選択を接続要求に添える)、集合と共有状態 (Manager と同じ GameObject で単一 Owner、参加マスク固定、終了時に `_OnGatherEnded`)、最寄り拠点 (NavMesh 経路長・空きスロット)、ローカル道具 (6 本・拠点スロット)、隊形と斜面 (法線 0.5・高低差無制限)、到達不能時の直進を実装。停滞検知・端末別入力・購入権の双方向確認は Play 後。「解除地点の最寄り拠点へ回収」は道具が接続時に戻る実装との差を [記録](../../plans/2026-09-20-menu-gather-stations.md) に明記し、ユーザー確認待ち。

2026-09-24 呼ぶ (屋外休憩) の斜面判定 ([IMP-DOG-016](review/IMP-DOG-016-call-pose-port-and-slope.md)): 呼ぶの配置は**地面法線 ≥ 0.9 (約 25.8°、仮値)** を採用し、集合 (0.5) より厳しくした。伏せる・寝る姿勢は体を地面に付けるので、集合の立ち姿より平らさが要るため。拠点のまわりと散歩道の実測点はすべて 0.9 以上。Q2 (集合中の割込禁止) に合わせて、集合中の犬も呼ぶの対象から外し、呼ぶとリードが同時に同じ犬に乗ったらリードが勝つ。

おしゃれ・屋外休憩・犬同士の遊び・性能予算は本Issueに残る別の設計対象。今回のメニュー/集合/回収の合意だけで完了にしない。
