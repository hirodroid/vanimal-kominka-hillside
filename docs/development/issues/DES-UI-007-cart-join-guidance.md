# DES-UI-007 カートの看板で「合流」を分かりやすく伝える

## ユーザー報告と依頼 (2026-10-14)

フレンド何人かと訪れた際、カートの看板では合流が分かりにくいようで、みんなそれぞれのカートに乗ってしまった。**どうしたら分かりやすくなるか、相談するところから始めたい。**

目指すのは、一緒に散歩したい人が、看板・メニューを見て合流の存在と操作を理解し、同じグループで走れること。各自が自分のカートに乗ること自体は、一人乗りカートの既存仕様に沿っている。今回の課題は「それぞれ乗る」ことと「同じグループで一緒に走る」ことの関係が伝わっていない点として調査する。

同日の追加回答で、**みんな「ここから出発」を押した**ことを確認した。表示されていた合流先・各人のグループ状態は未確認。全員が出発を乗車の入口として選んだことを、今回の改善の出発点とする。

## 相談・検討する内容

- 現在の看板と乗り場メニューを実物で確認し、最初に見える内容、出発と合流の文言・配置・目立ち方、合流先一覧への気づきやすさを整理する。
- 「自分で出発する」と「先に乗った人と一緒に走る」の違い、および合流しても一人ずつ自分のカートに乗ることを、どう伝えるか検討する。
- 最初の一人が出発し、後続がその人のグループへ合流する流れを、短い説明・図・操作の並びで伝える案を比較する。
- 参加したい相手を名前などから識別できるか、合流先がない・受付停止などの場合にも次の行動が分かるかを検討する。
- すでに各自で出発した後でも、一緒に走り直すための現行手順が伝わるか確認する。操作や仕様の変更が必要な場合は、案内だけの変更と分けて相談する。
- 文言の改善、看板の構成変更、メニュー内の出発／合流の見せ方など、複数案と推奨理由を示してユーザーと相談する。具体的な文言・配置・操作方式は、この起票では確定しない。

### 6ロールの独立レビュー

実装・セルフレビュー: 親Codex。独立レビュー: 作成に参加していない6名のCodexエージェント（gpt-6-astra）にロールを分けて依頼。各担当は読取と指摘のみ、追加レビューは起動していない。共通スキルのClaude Code経由は制限環境で応答せず、通常権限での再実行も「HTMLの外部Claudeサービスへの送信に明示承認がない」と自動承認レビューに拒否されたため、内部の別担当に切り替えた。Claudeのレビュー完了とは扱わない。

対象: HTMLと本Issue、Dは現行Runtimeと照合、Vは初版のデスクトップ・狭幅の描画画像も参照。実機利用者のテストではない。

| ロール / 指摘 | 対応 |
|---|---|
| U・X: 一覧0件では全員が最初の一人になろうとする可能性 | 出発する人を一人決める案内、後続は名前が出るまで待つ案内を上部・空状態へ追加 |
| U・X: 一覧に友人全員が出るように読める | 各グループの先頭の人だけが表示されると明記。先頭交代で名前が変わることも設計メモへ |
| U: 別々に出発した後の「一人」「その人」が曖昧 | 一緒に走る相手を決め、その人は乗ったまま、ほかの人は自分が降りたカートで選ぶと具体化 |
| M・X: 受付終了の結果と受付中の行が矛盾 | 対象行を受付停止へ更新し再操作を無効化。受付中の件数も更新 |
| M: 全8台使用中で結果セレクターが成功のまま | 「空いているカートなし」へ揃え、この状態では結果選択を無効化 |
| D: CartClosedをすべて受付停止と断定している | 既知の受付停止と理由を断定できない利用不可を別の模擬結果へ。世代変更・残ったカートを他人が使った場合の案内は実装時に判定へ接続 |
| D: CartOkと実成功の境界を明確にする | CartOkは確認中、同期割当と保留要求の一致で成功、割当と着座完了を区別と設計メモへ追記 |

| P・X: 初見テストの開始条件が曖昧 | 合流先0件・全員未乗車・同時開始・出発者を検証者が指名しない、を後続確認へ追加 |

各ロールとも提案と既存仕様の区別、Unity未反映、実機未検証という扱いには問題なし。Vは暗い面・明るい文字・操作面の強弱を評価。U/Xの指摘は利用者テスト結果ではなく専門ロールによる仮説である。

## 2026-10-14 HTML確認後の追加要望

ユーザーから、①空車がないことを押す前に知りたい（更新は30秒〜1分程度でよい）、②「川辺」等は目的地と明記、③犬のお散歩の目的地と同じ行き先を使う説明、④乗車中の撮影カメラへの案内、を受領。HTMLに次を反映した。Unity未反映は継続。
