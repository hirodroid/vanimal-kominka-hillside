# BUG-UI-002 カート移動中の通知・確認ダイアログを追従させる

## ユーザー報告 (2026-10-14)

カート移動中、合流の通知や、撮影カメラで選ばれた**撮影される相手側に出る許可確認画面**が追従しない。表示がすぐ後ろへ流れていき、ボタンを押せない。撮影の報告対象は、同日のユーザー補足「撮影相手に出る方の確認画面だよ」で確定。

思い当たるのはこの 2 件だが、ほかにもないか点検し、**カート移動中に出る個人用の通知・確認表示が、移動に追従して読める・操作できるようにしたい。**

## 起票時のコード確認

実行・シーン配線の検証は未実施。以下は 2026-10-14 のソース上の確認であり、実機の再現確認とは区別する。

| 表示・処理 | コード上の状態 | 点検対象 |
|---|---|---|
| カートの追従処理 `KH_CartDock` | `LateUpdate` で手元メニューと撮影モニターをドックへ移動する。通知板への参照・追従処理はない | 独立した通知・確認板が対象から漏れていないか |
| `KH_TravelNotice` | 表示時に目の前へ配置し、水平移動が `replaceMeters` (コード既定 3 m) を超えたら再配置する。連続した追従ではない | 合流申請、呼び出し、撮影許可の受信通知。撮影許可後の 4 秒の案内も同じ配置処理を使う |
| 撮影対象の人一覧・確認 `personListRoot` / `personConfirmRoot` | `KH_VideoCameraEditor.Permit.cs` の `BuildPersonUi` ではモニター内に生成する | 今回の報告対象ではないが、横断点検として保存シーンの親子関係・参照・表示中の追従を確認する |
| 手元メニューの共通購入確認 `confirmRoot` | `KD_TreatSetupEditor.Pouch.cs` ではメニュー板内に生成する | 購入確認など、メニューから開く子画面も含めて操作できるか。未報告の不具合とは断定しない |
| 写真ビューア `KD_PhotoViewer` | `PostLateUpdate` で頭に追従する既存処理がある | 既存の追従を維持し、二重に位置を制御しない。乗車中の動作は別途確認する |

参照ソースはいずれも `Assets/KominkaHillside/` 内。通知は `Scripts/KH_TravelNotice.cs`、カート追従は `Scripts/Cart/KH_CartDock.cs`、撮影対象 UI は `Scripts/KH_VideoCamera.People.cs` と `Scripts/Editor/KH_VideoCameraEditor.Permit.cs`。移植メニューと写真ビューアは `Imported/KominkaDogRun/` 内。

## 作業範囲

- 乗車中に開ける・届く個人用の通知、確認、選択、結果表示を棚卸しし、表示元・位置を動かす処理・親子関係・操作の有無を一覧にする。上の候補だけで点検完了としない。
- 報告の 2 件と同系統の表示について、走行中に読み、許可・拒否・取消・閉じるなどの必要な操作を終えられる位置を保つ。
- 乗車前から開いている表示、乗車後に新しく開く表示、再表示、直線・旋回・坂道・停止・再発進、降車や乗り換えの切替を扱う。

- 追従は本人の表示位置の扱いとして修正する。申請・許可の対象、期限、取消、入力の取り違え防止など既存の意味を維持する。

## 原因 (2026-10-14、ソースの静的確認)

- 表示経路: 受付箱 `KH_TravelMailbox` が合流・呼び出し・撮影の申し込みを受けると `notice._Show(this)` (`KH_TravelMailbox.cs` 338 / 363)、撮影の [いいよ] の後の 4 秒は `notice._ShowFilmGranted` (`KH_TravelMailbox.Film.cs` 326)、手元メニューの「申し込み 1 件」は `travelNotice._Reshow()` (`KD_TreatPouch.Travel.cs` 188)。どれも乗車中かどうかを見ない。通知板はシーン直下に 1 枚 (`KH_TravelNotice`、子 `Board` = WorldSpace Canvas 760×380 px @0.001 = 0.76×0.38 m、root の原点・中心ピボット、layer Default。`Course/85`)。撮影される相手側の許可確認はこの板の 3 つめのボタンの組 (Button6 / Button7)。
- `KH_TravelNotice.Place()` は表示時に頭の前 1.1 m・視線の 15° 下に置くだけで、`Update()` は水平移動が `replaceMeters` (3 m) を超えたときだけ置き直す。カートは 1.3 m/s なので約 2.3 秒ごとに跳び、その大半を頭の後ろで過ごす (押す前に流れる)。
- カートの追従 `KH_CartDock` (LateUpdate、`DefaultExecutionOrder(100)`、乗車中だけ enabled) は手元メニューと撮影モニターだけを運び、通知板への参照が無かった。

## 修正 (2026-10-14)

- `KH_CartDock`: `public KH_TravelNotice notice; public Transform dockNotice;` を追加。乗車中の LateUpdate で、通知板の `board` が active なら `notice.transform` を `dockNotice` の姿勢へ置く (Board は root の原点なので板の中心がドックに来る。+Z = 座っている人から板へ、表 -Z が乗員を向く。手元メニュー・モニターと同じ約束)。閉じていれば触らない。`_SetRiding(on)` で `notice._SetDocked(on, index)` を呼ぶ (`dockNotice` が無いカートでは呼ばない)。
- `KH_TravelNotice`: ドックしているカートの番号 `_dockCart` (-1 = なし) を持つ。`_SetDocked(true, c)` で c に、`_SetDocked(false, c)` は c がドック中のときだけ -1 に戻す (乗り換えで `ApplyState` が「新しいカートの on → 古いカートの off」の順に呼んでも外れない)。ドック中は `Update` の 3 m 規則と `_Show` / `_ShowFilmGranted` / `_Reshow` の `Place()` を止め、板を出すだけにする (`PlaceOrOpen`)。出す・隠す・中身の更新・押下は従来どおり。書き手は常に 1 つ。
- 常時処理は増やしていない: `KH_CartDock` は従来どおり乗車中だけ enabled (追加は `activeSelf` 1 回と、開いているときの `SetPositionAndRotation` 1 回)、`KH_TravelNotice.Update` は表示中だけ動く形のまま (追加は int の比較 1 回)。
- `Cart/1` (`KH_CartSetupEditor.Controls.cs` `BuildCartUi`): 各カートの `Docks` の下に `Dock_Notice` を作り `FaceEye` で目へ向け、`notice` (シーンの KH_TravelNotice を探す。1 枚でなければ null と WARN) と `dockNotice` を SerializedObject → `CopyProxyToUdon` で配線。本体 (`KH_CartSetupEditor.cs`) は変えていない。
- `Cart/2` (`KH_CartSetupEditor.VerifyM11.cs` `CartUiCheck`): 全 8 台で `notice` / `dockNotice` の配線 (プロキシと backing)、`Dock_Notice` の位置 (±0.02 m) と向き (+Z が目から板へ)、目からの距離 0.8〜1.2 m、通知板 (シーンの Board の実寸) とモニター / 操作帯 / Tab / 最小化タブ / 手元メニューの角度の隙間 ≥ 5° (既存の `AngularMarginDeg`)。1 台あたり 12 項目、計 +96。

### 配置値 (Dock_Notice、カートのローカル座標)

採用は右前 **(0.45, 1.00, 0.70)**。操作帯 (左前 (-0.40, 1.00, 0.50)) の鏡像側。目 `SeatedEyeLocal` (0, 1.25, -0.26) から 1.09 m、通知板は方位 4.6..45.6°・仰角 -23.2..-3.2°。`Project` / `AngularGap` と同じ計算 (外周を 8 分割で標本化) で比べた値:

| 相手 | 相手の角度範囲 (方位 / 仰角) | 隙間 |
|---|---|---|
| 撮影モニター (本体 + パターン板) | -42.8..7.2 / 3.9..34.0 | 7.1° (仰角で離れる) |
| 操作帯 | -37.7..-17.8 / -29.7..-2.7 | 22.4° |
| Tab (展開中) | -22.4..-19.2 / -6.0..-2.9 | 23.8° |
| 最小化タブ | -43.0..-36.6 / -42.1..-37.4 | 41.3° |
| 手元メニュー | -104.5..-50.0 / -28.2..4.2 | 54.6° |

- 統括の例 (0.45, 1.05, 0.70) はモニターとの隙間が 4.6° で既存の基準 5° に届かないので 5 cm 下げた。モニターとの 5° の制約があるので上へは動かせない (0.95 まで下げるとモニターは 9.6° になるが、前方の犬の線へさらにかぶるので 1.00 にした)。
- 犬: BUG-DOG-014 の修正以降、乗車中の犬は保つ線 (原点から前 1.7 m、揺らぎで +1.7〜+2.1 m、横 -0.45 / +0.45 / 0) に立つ。右の犬の頭 (0.45, 0.6, 1.7) は目から方位 12.9°・仰角 -17.9° で通知板の範囲 (方位 4.6..45.6°・仰角 -23.2..-3.2°) の中にある。**犬が線 1.7 m に立つ今の配置では、通知の表示中 (最長 20 秒 + 撮影許可後の 4 秒) だけ右の犬が板に隠れ得る。** 通知は短時間で、読んで押せることを優先して採用した (Codex 独立レビューの指摘、統括判断 2026-10-14)。Play で気になれば位置を再検討する。中央・左の犬は方位で外れる。
- カート本体の当たり (BoxCollider、y 0..0.6、Ignore Raycast) より板の下端 (約 0.82 m) が上なので、ポインタは遮られない。
- カート上メニュー `Panel` (0.29, 1.33, -0.02、外向き) は Parked (乗員なし) のときだけ出るので、乗車中の通知板と同時には出ない (比較の対象外)。
- 座面の調整 (高さ ±30 cm・前後) で目が動くと隙間は変わる (既存の板と同じ制約)。

## 2026-10-14 記録

- 実装 (Opus B、統括の採用方針): `KH_CartDock.cs`、`KH_TravelNotice.cs`、`Editor/Cart/KH_CartSetupEditor.Controls.cs` (Dock_Notice の生成と配線)、`Editor/Cart/KH_CartSetupEditor.VerifyM11.cs` (Cart/2 の検査)。原因・修正・配置値・棚卸しは上の節。

- 降車後の戻り (静的な読み): ドック中は `_placedFrom` を更新しないので、降車後の最初の Update で「最後に Place() した地点」から水平 3 m 以上離れていれば目の前へ置き直す。ふつうの乗車は 3 m を超えるので降車直後に戻る。例外は「乗る前に出ていた通知を、乗った地点から 3 m 以内で降りた」場合で、板はドックの姿勢 (降りたカートの右前) に残り、3 m 歩くまで置き直さない。乗車中に初めて出た通知は、前回の Place の地点 (初回なら原点) との比較になる。これらはユーザーの Play で確かめる項目に入れる (不具合とは見なさない)。
- 検証の分担: ClientSim は VRCStation に座ると移動入力で自動降車するため、乗車中の動作は ClientSim では確かめられない。走行中に読める・押せる、旋回・坂・停止・再発進、乗る前から出ていた通知が乗車でドックへ移る、乗車中に新しく出る・再表示 (`_Reshow`)・撮影許可後 4 秒の案内、乗り換え、降車後に目の前へ戻る (上の例外を含む)、既存メニュー・モニター・操作帯の操作を妨げない、板の左下 (カートのローカルで約 (0.09, 0.82, 0.82)) が車体の模型の前部と重ならない、通知の表示中に右の犬が板に隠れるのが気にならないか (気になれば位置を再検討)、は**ユーザーの Play (実機) に残す**。2 人での申請側・受信側 (許可・拒否・取消・期限切れ) も同じ。
- 未修正で統括へ報告: `KD_HintDirector` の紹介通知 (12 秒、頭の前に 1 回置くだけ) と `KD_SleepPlacement` の呼び出し中の HUD (最大 9 秒止まる)。どちらも移植スクリプトで本票の担当範囲外。
