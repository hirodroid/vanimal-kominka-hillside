## 拒否 (RC-14) が今守っているもの

拒否は 2 段: Manager の `ReqAttach` が `_InWater` (同期の `waterPose` ≠ 0 か、同期位置の水深) で断る (`KH_LeashManager.cs:221`、`KH_LeashManager.Water.cs:20-24`。手元メニューも `WalkGateWater` で同じく断る、`KD_TreatPouch.Walk.cs:137`)。それでも通った接続は、犬の Owner が最初に見たフレームで濡れていれば `_waterLeashVeto` を立ててリード処理を飛ばし (`KD_DogWanderController.cs:1336`)、水遊びの出水を続け、`ReqWaterRelease` で解除を頼む (`HillsideWater.cs:439-468`)。由来は破壊監査 2026-09-28 FUNC-04 BUG-02 / RC-14 (`docs/_sessions/destructive-audit-2026-09-28/triage.md`:2155・:7264、git 管理外)。

**拒否だけを外すと戻る不具合** (コードの読み。Codex 相談で確認し、自分の記述の誤りを 2 つ直した: 水遊びの終わり方の順序、Return の速さと TeleportTo):

1. **小型犬が河床を歩いて沈む。** リード処理が先に走り、`HillsideLeash.cs:386` の `WaterClearFloat()` が毎フレーム泳ぎを落とす。水面に Collider が無いので接地のレイは河床に当たり、口の高さ 0.13〜0.36 m の犬が最深 0.40 m の川底を歩く。泳ぎの姿勢 (2) にも入らない。
2. **深さの規則が効かない。** リード散歩は NavMesh (`LeashGo`) で、その一歩は `_navStep` で川の判定 (沈み防止 0.03 m・非泳ぎの上限) を飛ばす (`HillsideWater.cs:177`)。今これが安全なのは河床が NavMesh から外れているから (`KH_RiverData.BandMargin = 1f // = NavMesh riverbed exclusion`)。水中から NavMesh の角へ向かう直進は、深さを見ずに川を横切る。
3. **出水の監視と復旧が走らない。** 水遊びの状態は次の判断で `preempted` として終わり (`HillsideWater.cs:358`。Codex の訂正: `WaterEnd("leashed")` の :486 には届かない)、10 秒・停滞 → 別出口 → 復帰点の 3 段 (監査 GUARD-03) が無くなる。
4. **追いつき・瞬間移動が水を考えない。** 手が 1.25 × リード長を超えると Return (1.6 × 超で 7.2 m/s、それ以下は 4.5 m/s)、10 m 超で `TeleportTo` (水中からは岸が 2 m 以内のときだけ成功)。
5. **止まったときの姿勢。** `LeashPose` は水の中でも伏せ・嗅ぐを選べる (全端末)。
6. **水中で外したとき、自由行動の中心が川の中になる。** 通常の `Release` は今の位置を `releasedHomes` に書く (`KH_LeashManager.cs:272`)。`ReqWaterRelease` だけは元の値を戻していた。

## 方式

| 案 | 中身 | 判断 |
|---|---|---|
| A | 浅瀬だけ別の NavMesh エリア (またはリード用の agent) にして歩かせる | **採らない。** 上の 2 の前提 (河床は NavMesh に無い) が崩れ、リード以外の NavMesh 移動 (`GatherStep`・水の Fetch の陸の脚・洗い場の呼び出し) も深さを見ずに水へ入る。全 `CalculatePath` (`NavMesh.AllAreas`) にエリアの指定が要り、Course/8・10・20・30 の焼き直しと検査 (Not Walkable の volume 241 個・agent 一致・「Riverbed walkable」)、岸のスライス (Course/90・91) の焼き直しも要る。1 つのエリアでは犬ごとの口の高さ・泳ぎの切替を表せず、結局実行時の水の判定が要る |
| **B (推奨)** | NavMesh はそのまま。リード中の犬が濡れている、または手へ向かう一歩が川の帯へ入るとき、Owner のローカル状態で **既存の川の Fetch の脚** (`_WaterRiverStep` と同じ: 川の規則の `_BlockedByRiver`、`WaterSwimLookAhead`、`WaterApplySwimHeight`、`WaterPoseRefresh`) で手へ向かう | 川全体の河床格子 (z 0〜720、半幅 + 2 m で帯を覆う) と岸のスライス・復旧は IMP-DOG-021 で作って検査済み。新しい同期変数は要らない (位置・`waterPose`・`walkers` で足りる。非 Owner は今と同じく受信位置と `waterPose` で泳ぎを表示) |

**B の形** (Codex 相談 2026-10-11 の指摘を反映。細部は実装 Issue で決める):

- 状態 (Owner のローカル): 陸 (今の `LeashGo`) → 入水 → 川で追従 / 限界で待つ → 上がる → 陸。入口は NavMesh の縁から帯へ直接入るか、近くの ok な岸のスライス (`_NearestSlice`) を通るか。**どちらにするかは実装前に Edit で調べる** (NavMesh の縁と帯の縁の距離の分布。Play 不要)。
- 深さ: 川の Fetch と同じ規則 (沈み防止 0.03 m、泳がない犬は 0.85 M、泳ぐ犬種は先読みで泳ぐ、橋の区域の帯には入らない)。リードに 0.85 M を採るのは新しい設計の選択として明記する (水遊び場の自由行動の 0.45 M は変えない)。
- 目標: `_WalkingTarget` は手 + 犬ごとのずらし。届かない目標 (深すぎ・橋の区域) は手前の届く点へ縮め、そこで止まって保持者を向く。待っている間は停滞と数えない。
- 追いつき: 水中では速さを泳ぎ / 歩きの上限より上げない。10 m を超えたら水中から瞬間移動せず、保持者側の岸へ上がり始める。上がれないときだけ既存の 3 段 (別出口 → 復帰点)。上陸後は今の追いつき。
- 引き継ぎ: 泳いでいる犬に接続したら、泳ぎの高さを保ったまま水遊びを明示的に終える (河床へ一度落とさない)。Owner 交代は位置・水深・`waterPose` から組み直す。
- `WaterClearFloat` はリード処理では乾いて浮いていないときだけ。切符は **位置を変えたときだけ** 消し、適用後に `WaterPoseRefresh` (今は位置を変えない適用でも消している、`HillsideTravel.cs:78-97`)。
- 水中の止まり方: 伏せ・嗅ぐ・座るを出さない (全端末、`waterPose` ≠ 0 で判断)。
- 間引き: 濡れている・入水に向かう間は毎フレーム判断 (`LeashLegsOk` に入水への接近を足す)。6 匹が水中なら 6 匹とも毎フレーム (自由な水遊びと同じ費用)。
- 押し合い: 同じ保持者の犬どうしは押し合わない (`KD_DogPack.cs:271`)。別の保持者・自由な犬との押し合いが川の規則を読むよう、浮いている側・歩いている側の両方を直す (`_WaterPushBlocked`)。
- 退役: Manager の `_InWater` の拒否、メニューの `WalkGateWater` と文言 `course.water.busy` (13 言語)、`_waterLeashVeto` / `WaterLeashTick` の拒否の半分、`ReqWaterRelease` (送る側と受ける側を一緒に)。残す: 移動後の姿勢の更新、取り残しの出水 (水中で外された犬・保持者の退室・Fetch の終了後)、Fetch 非 Idle とディスクの接続拒否 (水と関係なく今のまま)。
- 洗い場への呼び出し: 今は水遊びの出水を待つ。リードの川の状態でも同じく「先に上がる」を受け持つ。
- 紐: 手と首輪のたるみの曲線だけで、地面・水面との当たりは無い (`KH_LeashCollar.cs:581-590`)。変えない (見え方は PCVR)。
- 汚れ: `KH_DogWash` は `WaterPose` だけを見る (`KH_DogWash.cs:2942`)。リードの有無に依らず、川ですすがれ濡れる・下限 0.15 で清潔にはならない。変えない。
- 散歩の写真: 「水の中は撮らない」のまま (game-design §4 の写真の行)。
- 実装時に書き直すコメント・記録: `HillsideWater.cs` の先頭と RC-14 の節、`KH_LeashManager.Water.cs`、`HillsideLeash.cs:384`、IMP-DOG-034 W1 (「Leashed walks run on the NavMesh」)、IMP-DOG-036 の RC-14 の行。

最小の検証 (実装後): 泳ぐ小型犬 1 匹 (岸 → 入水 → 浮いて止まる → 同じ岸へ上がる)、非泳ぎの大型犬 1 匹 (限界で待つ → 保持者が離れる → 上がって追う)、泳いでいる犬への接続 (水遊び場の中 / 外)、橋の区域と使えない岸、泳いでいる犬の切符 (位置を変える / 変えない)。6 匹の混在と保持者 ≠ Owner・途中参加・退室は PCVR の 2 人以上。

## ユーザーに決めてもらうこと (推奨つき)

1. **浅瀬だけか、泳ぎもか** — 推奨: **泳ぎも。** 泳ぐ犬種 (ポメ・コーギー・ダックス、柴は試作) は深い所で泳ぎ、大型犬 (サモエド・ラブ) は歩ける深さまで。理由: 拒否をやめる以上、泳いでいる犬に付けることが起きるので、浅瀬だけにしても浮きの処理は省けない。脚は川の Fetch と同じものを使う。
2. **どこまで深く入るか** — 推奨: **川の Fetch と同じ** (泳がない犬は口の高さの 0.85 倍まで、どの犬も口が水面から 3 cm を切る所へは歩いて入らない)。橋の下とその前後 (橋の区域) は入らない。水遊び場の 0.45 倍 (浅瀬だけ) にする案もある。
3. **紐が水の上を通るとき** — 推奨: **今のまま** (たるみの曲線。水面に垂れて少し沈んで見えることがある)。気になれば、紐を水面より下へ垂らさない処理を自分の画面だけで足せる。
4. **川から出るとき** — 推奨: 保持者の後を追い、**近い上がれる岸から上がる**。保持者が 10 m より離れたら自分で保持者側の岸へ上がって追いかける (水中で瞬間移動しない)。泳いだ後は上がった所で 1 回身震い (1.2 秒、保持者が歩き去るときは省く)。
5. **何匹も連れて入るとき** — 推奨: **今の上限のまま (片手 3・両手 6 匹) 全部入れる。** 犬ごとの深さで止まる (泳ぐ犬だけ先へ進み、大型犬は手前で待つ)。
6. **濡れ・汚れ** — 推奨: **今のまま。** 川で足の汚れが少し落ちて毛が濡れる。川だけでは清潔にならない (IMP-DOG-029)。
7. **水の中で合流・呼ぶ・地点ワープをしたとき** — 推奨: **切符で一緒に運ぶ。** 着地点は陸、着いたら泳ぎは解け、乾いた扱い ([IMP-WLD-002](IMP-WLD-002-call-player.md) の「運ぶか・外すか」はこれで不要になる)。
8. **水の中でリードを外したとき** (Codex 相談で見つけた追加) — 推奨: **外された犬は自分で近い岸へ上がる** (今の取り残しの規則)。自由行動の中心は外す前の陸の位置のまま (川の中にしない)。
