# DES-WLD-001 古民家と裏山の往復導線を決める

古民家の拡張先として出かけて戻れる体験を設計する。[game-design](../../game-design.md) §4の未解決事項を扱う。今回は計画のみで、古民家側の改変・公開は実施しない。

## 決めること

2026-09-23 決定: **今回は古民家とのポイント・所持品の引き継ぎを導入しない。** 裏山のおじいさんとの初回会話で支度用ポイントを付与し、裏山で追加の飾り等を解放する ([DES-UI-003](DES-UI-003-menu-scope-and-polish.md)、仕様はgame-design §4)。下記の装着状態等の検討も所持品共有を前提にしない。CE購入権の確認は従来どおりDES-LIV-001等と区別する。

- 古民家での出発場所、裏山の到着場所、帰還手段、必要な短い案内。
- 元インスタンスへの帰還が可能か、できない場合にどう案内するか。
- 犬の名前・飾り・リード状態のうち何を引き継ぎたいか。実現性を調べ、今回採用する範囲と保留する範囲を分ける。
- 別ワールドでも同じ犬たちと過ごすと感じられ、状態リセットが誤解されない表現。

## 完了条件

- [x] 出発→散歩→帰還の手順と移動先を仕様へ記録した (本 Issue の決定 2026-10-03。古民家の門の設置型ポータルで入り、裏山の門の案内ボードから出るポータルで戻る。実装は IMP-WLD-006)
- [x] 元インスタンスへの帰還と状態保存の実現性を根拠付きで整理した (元インスタンスへの帰還は作らない。状態は引き継がない。ユーザー決定 2026-10-03)
- [x] 未対応・リセットされる状態を利用者へ伝える方法を決めた (IMP-WLD-006 の案内ボードに、古民家の内容と「引き継がれるものは無い」旨を書く。文言は実装時)
- [x] 採用案に実装Issueと実機の往復確認手順がある ([IMP-WLD-006](IMP-WLD-006-farmhouse-portal-board.md) の完了条件)

大規模なワールド間状態共有を公開の必須条件へ追加しない。古民家だけで遊びが完結する関係を維持する。

2026-09-20追補: Candy Step/ハロウィンの既存購入者が裏山でも再生できる要件は [DES-LIV-001](DES-LIV-001-hillside-live.md) へ分離。購入権利の確認と、犬の名前・飾り・接続状態の保存/移動は別の仕組みとして調査する。

決定: 2026-10-02 (ユーザー決定) 古民家との往復導線は初期公開に入れる。出発・到着場所と帰還手段、古民家側の改変の要否は未決定。

決定: 2026-10-03 (ユーザー決定) 「往復導線ってなに？古民家ドックランは触らない。VRCの設置型ポータルで移動するだけなので特に何もすることは無い。→ いまポータルおいてあるけど、門のところに。そこを古民家ドックランの説明案内ボードにして、インタラクトしたら隣にポータルが出るように修正が必要。」

上の「決めること」への回答として読む (読みは AI): 古民家側 (別リポジトリ) は改変しない / 移動は VRChat の設置型ポータル / 犬の名前・飾り・リード状態など状態は引き継がない / 帰還のための仕組みは作らない (各ワールドのポータルがあるだけ)。実装は [IMP-WLD-006](IMP-WLD-006-farmhouse-portal-board.md) (門のポータルを古民家ドッグランの案内ボードにし、Interact で隣へポータルを出す)。

## 完了記録

2026-10-03: 設計 Issue としての完了。確認方法はユーザーの回答の照合 (質問 3 点がそれぞれ上のとおり答えられ、残る設計判断が無い)。実機の往復の確認は IMP-WLD-006 が持つ。想定と実際のずれ: 「出発場所・帰還手段・状態引き継ぎ」を設計する前提だったが、古民家を触らず設置型ポータルだけという最小の形で、新しい設計物はボード 1 枚の実装に縮んだ。
